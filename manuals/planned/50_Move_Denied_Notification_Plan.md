# 計画50: キャラクター移動拒否の控えめな通知

**状態**: 未実装・小規模タスク  
**作成日**: 2026-10-17  
**背景**: `566dc64` で通常ルームのキャラクター移動・未配置化に所有者チェックが追加された。拒否時にサーバーは `move_denied` を送るが、クライアントに受信処理がなく、操作したプレイヤーには何も起きないように見える。

## 目的

操作が拒否されたことと理由を利用者に伝えつつ、誤操作やドラッグ中にポップアップで操作を中断させない。

## 方針

- `move_denied` をクライアントで受信し、画面内に短時間表示する控えめな通知（トースト等）で「このキャラクターを操作する権限がありません」と伝える。
- `alert` 等のモーダルなポップアップは使わない。
- ドラッグ操作などで拒否イベントが短時間に繰り返されても通知が連続・多重表示されないよう、同種通知を抑制または既存通知を更新する。
- 既存の共通通知UIがあれば再利用し、新しい通知基盤は作らない。
- サーバーの権限判定や `move_denied` のペイロードはこのタスクでは変更しない。

## 実装タスク

1. `static/js/visual/visual_socket.js` 等、Socket イベントを一元管理する箇所で `move_denied` の受信を登録する。
2. 既存の通知UIを調査して再利用し、短い文言と表示時間で拒否を知らせる。
3. 連続拒否時の抑制を実装し、盤面ドラッグと配置・未配置化ボタンの両方で通知が過剰にならないようにする。
4. 関連するフロントエンドテストがあれば追加・更新し、手動確認項目も確認する。
5. JS ソース変更後に `npm run build` を実行し、`static/dist/` の成果物を更新する。
6. 実装完了後、この計画を削除し、確定した通知仕様を `manuals/implemented/E01_Visual_Battle_Architecture.md` または適切な E 系統仕様書へ統合する。

## 受け入れ条件

- 権限のない移動が拒否されたとき、操作した本人に拒否理由が画面上で分かる。
- モーダルなポップアップで画面操作を止めない。
- ドラッグで拒否イベントが続いても通知が連続表示されない。
- サーバー側で拒否された移動は、キャラクター状態に反映されない。
- フロントエンドビルド成果物とソースが一致している。
