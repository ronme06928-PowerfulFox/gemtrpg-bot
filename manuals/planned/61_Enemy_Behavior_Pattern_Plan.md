# 計画61：敵キャラと行動パターンの管理

作成日: 2026-11-04
状態: 論点確定・未着手。着手は計画60の Phase 1（スキーマ）の後、計画46の主な作業が落ち着いてから（§7 論点6）。[マスターデータベース・プロジェクト](../projects/master_database/README.md)の段階2。コードは未着手。

## 1. 目的

敵キャラ（ステータス・所持スキル・パッシブ）と、その行動パターンを、アプリの中でまとめて作り・保存し・使い回せるようにする。

1体の敵に、シナリオや場所によって違う行動パターンを複数持たせ、どの戦闘でどのパターンを使うかを選べるようにする。敵のステータスやスキルを直したら、その敵の全部のパターンと、使っている全部の編成に効くようにする。

## 2. 今の作り（2026-11-04 調査）

- **敵キャラ**：戦闘専用プリセットのキャラクター（`resource_type` がキャラクターの `preset_resources` の行）。中身はキャラクターの JSON で、スキルはチャットパレットの `【ID 名前】`、特殊パッシブは `SPassive` の ID 配列で持つ。所有者・ACL・`revision`・コレクションと区分・参照の整合の検査がある（D01 Part 4・6）。
- **行動パターン**：キャラクターの JSON の `flags.behavior_profile` に、1キャラにつき1つ埋め込む（D01 Part 1 §6）。ループ・ステップ・遷移の条件を持つ。編集は `static/js/modals/behavior_flow_editor_modal.js`。
- **編成ごとの差し替え**：敵編成の各メンバーは `behavior_profile_override` を持てる。中身は行動パターンの丸ごとの写しで、配置のときにキャラの `flags.behavior_profile` を上書きする（`manager/preset_deployment.py`、`manager/room_preset_apply.py`、`manager/battle_only_runtime.py`）。編成の画面（`battle_only_enemy_formation_modal.js`）で JSON または行動チャートのエディターで編集する。
- **困りごと**：
  - 同じ行動パターンを複数の編成で使うと、写しが編成ごとに増え、直すときは全部を直す必要がある。
  - パターンに名前が無く、「坑道用」「ボス戦用」のように選んだり探したりできない。
  - キャラ本体のパターンと、編成ごとの写しの、どちらが使われるかが画面から分かりにくい。
  - 敵が使うスキル・パッシブの ID は文字列で書くだけで、マスターデータとのつながり（存在するか、廃止されていないか、どの敵が使っているか）を引けない。

## 3. 構想

### 3.1 行動パターンを独立したデータにする

行動パターンを、キャラクターから切り離した独立したデータ（新しい `resource_type`）にする。

- 名前・説明・どの敵用か（キャラクターの ID）・中身（今の `behavior_profile` と同じ形）を持つ。
- パターンは1体の敵に属する。その敵を消すと、パターンも一緒に消える（§7 論点1）。
- 別の敵へ複製できる。複製するとき、ステップのスキルが複製先の敵に無ければ、その場で一覧にして直させる。複製したパターンは別物で、片方を直してももう片方は変わらない。
- 1体の敵が、パターンをいくつでも持てる。パターンが1つ以上あれば、既定は必ず1つ。最初に作ったパターンが自動で既定になり、既定を消すときは別のパターンを既定にしてから消す。パターンが0個の敵は、今と同じ自動の選び方（AI 提案・使えるスキルからのランダム）で動く（§7 論点2）。
- 所有者・ACL・版は、ほかのプリセットと同じ仕組みに乗せる。

### 3.2 編成の枠でパターンを選ぶ

敵編成の各メンバーは、行動パターンの写しではなく、**パターンの ID** を持つ。指定が無ければ、その敵の既定のパターンを使う。

- シナリオや場所の違いは、今ある編成・ステージ・コレクションで表す。新しい「シナリオ」の入れ物は作らない。
- 写しの `behavior_profile_override` と、キャラ本体の `flags.behavior_profile` はやめる（後方互換は持たない）。
- 編成の中だけでパターンを変える写しは持たない。少し変えたいときは、編成の画面の「このパターンを複製して編集」で、同じ敵の別のパターンとして保存する（§7 論点3）。

### 3.3 敵のスキル・パッシブをマスターデータの参照にする

敵が使うスキル・パッシブを、マスターデータの ID の参照として扱う。

- 保存の前に、存在しない ID・廃止された ID を検査する（計画60 論点4-補の「廃止」）。
- 「このスキルを使っている敵」「この敵が使っているスキル」を引けるようにする（プロジェクトの共通の土台）。
- 行動パターンのステップが指すスキルも、その敵が持っているスキルかを検査する。

### 3.4 敵キャラを項目に分けて持つ

敵キャラを、ココフォリア形式の JSON 丸ごとではなく、項目に分けて持つ（§7 論点5）。

- 項目：ステータス（HP・MP など）、パラメータ（筋力・敏捷など）、スキルの一覧（ID とキャラごとの名前）、パッシブの一覧（ID）、スキル以外のパレットの行。
- チャットパレット（`commands`）は保存しない。配置のときに、マスターの `チャットパレット` 列から作る（今ある `manager/granted_skills/service.py` の `_build_skill_command_line` と同じ作り方）。マスターでスキルを直すと、全部の敵に効く。
- ココフォリアへの書き出しは作らない。
- 入口は敵の画面の「JSON から取り込む」1つ（§7 論点4）。ココフォリア形式の JSON（CharaCreator の出力、今のプリセットの書き出し）を貼ると、`commands` の各行からスキル ID とキャラごとの名前を読み取り、スキルではない行は「スキル以外の行」に回す。`flags.behavior_profile` があれば既定のパターンとして取り込む。新規作成と移行の両方に使う。

### 3.5 画面

- 敵キャラの画面に、ステータス・スキル・パッシブと、その敵の行動パターンの一覧を並べる。パターンの追加・複製・既定の切り替えをここで行う。
- 編成の画面では、メンバーごとにパターンを一覧から選ぶ。中身の編集は行動チャートのエディターを開く。

## 4. 対象範囲

対象とするもの：

- 行動パターンの独立したデータと、その保存・ACL・版
- 敵編成のメンバーが持つパターンの参照と、配置のときの解決
- 敵のスキル・パッシブ・行動パターンのステップの参照の検査
- 敵キャラの画面と編成の画面の、パターンの選択・管理

対象としないもの：

- 行動チャートの中身の仕組み（ループ・遷移の条件）の拡張
- 味方キャラ・持ちキャラ（F01 Part 9）
- 敵専用のデータを隠すネタバレ対策（プロジェクトの段階3）

## 6. 関係

- 計画60：ルールの部品は `catalog_entries` などの別の表に、同じ形（種類＋ID＋中身＋版）で持つ（計画60 論点10）。この計画の行動パターンは `preset_resources` に乗せ、参照の検査は共通の関数を使う。参照の検査は実行時の辞書（`all_skill_data` など）に対して行うため、計画60の DB 化を待たない。廃止の印は、計画60の DB 化の後に効くようになる（§7 論点6）。
- 計画38：シナリオNo.2 の敵5体・編成3つはローカル DB に作成済みで、行動チャートは未設定（計画38 §8）。計画38は今の仕組みで先に進め、この計画ができたら取り込み口で移す（§7 論点6）。
- 計画35：ホロウダンジョンは、敵・パターンを大量に扱うため、この計画の結果に乗せる。
- 仕様：プリセットは D01 Part 4・5・6、行動チャートは D01 Part 1 §6、画面は E02 Part 9・10。

## 8. 受け入れ条件（暫定）

- [ ] 1体の敵に名前付きの行動パターンを複数持たせ、1つを既定にできる。
- [ ] 敵編成のメンバーごとにパターンを選べ、指定が無ければ既定のパターンで動く。
- [ ] パターンを直すと、そのパターンを使う全部の編成に効く。
- [ ] 敵キャラはステータス・パラメータ・スキル・パッシブを項目で持ち、マスターでスキルを直すと配置した敵のチャットパレットに効く。
- [ ] 存在しないスキル・パッシブの ID と、敵が持っていないスキルを指すステップは、保存の前に検査ではじかれる。
- [ ] CharaCreator の出力を「JSON から取り込む」で入れられ、計画38の敵5体をこの口で移せる。
