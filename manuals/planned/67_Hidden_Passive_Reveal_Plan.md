# 計画67：伏せたパッシブを戦闘の途中で得る（形態変化）

作成日: 2026-11-17
状態: たたき台（議論前）。§6 の論点を一問一答で決めてから、段階と PR に分ける。マスターデータベース・プロジェクトとは別の、戦闘の仕組みの計画（2026-11-17 ユーザー）。ホロウダンジョン（計画35）に手を付ける前に行う（2026-11-23 ユーザー）。

## 1. 目的

ボスなどの敵が、戦闘の途中で新しい特殊パッシブを得る（第2形態になる）遊びを作る。敵には中身を伏せた「？？？」のパッシブ（伏せ札）を持たせておき、決まった時にそれを本物のパッシブへ差し替える。遊ぶ人には「この敵にはまだ何か隠している物がある」ことだけが見え、差し替わった瞬間に中身が分かる（2026-11-17 ユーザーの構想）。

## 2. 今の作り（2026-11-17 調査）

- **キャラのパッシブ**：キャラの `SPassive`（特殊パッシブの ID の並び）で決まる。戦闘の途中で `SPassive` を変える仕組みは無い。戦闘中にパッシブを持つキャラが増えるのは、召喚（`SUMMON_CHARACTER`）で新しいキャラが登場する時だけ。
- **パッシブの効果の組み立て**：`manager/utils.py` の `apply_passive_effect_buffs` が `SPassive` から、パッシブ由来の常時バフ（`special_buffs` の `source: "passive"`）を組み直す。何度呼んでも前のパッシブ分を消して作り直す。能力値の補正は `get_passive_stat_mod` が使うたびに `SPassive` を読む。呼ばれている所は、キャラの追加（`events/socket_char.py`）・待機列の登場（`manager/preset_deployment.py`）・召喚（`manager/summons/service.py`）。
- **似た効果**：`GRANT_SKILL`（B02 §2）は、効果で対象にスキルを付け与える（`manager/battle/effect_handlers/action_effects.py`）。パッシブを付け与える効果は無い。
- **行動チャート**：敵の行動チャート（D01 Part 1 §6）は「次にどのスキルを使うか」を決め、HP割合などの条件でループを移れる。パッシブを直接変える機能は無い。

## 3. 構想（たたき台）

1. **伏せ札のパッシブ**：効果を持たない特殊パッシブを「伏せ札」として、マスターデータに用意する（伏せ札だと分かる持ち方は論点で決める。計画66 の印の仕組みができていれば、それに足してもよい）。敵に何枚持たせてもよい。遊ぶ人のキャラ詳細と図鑑には「？？？」と出る。
2. **差し替える効果**：新しい効果タイプ（仮に `REVEAL_PASSIVE`）。対象の伏せ札を1枚外し、指定した特殊パッシブを付け、`apply_passive_effect_buffs` で効果を組み直す。**ログに「〇〇は △△ を得た」のような文は出さない**（2026-11-17 ユーザー）。
3. **スキルで変える**：「HP が半分を切ったら形態変化のスキルを使う」ように行動チャートを組み、そのスキルの効果で差し替える。形態変化はスキルの予告として遊ぶ人に見える。PvP では GM がそのスキルを使えば同じことが起きる。
4. **スキルに頼らずに変える**（2026-11-17 ユーザー：演出として用意したい）：スキルの使用を挟まずに、パッシブを変える・得る仕組みも作る。候補（論点8 で決める）：
    - 行動チャートのループに入った時の動作として差し替える（「HP が半分を切ったら第2形態のループへ移り、移った時に伏せ札を差し替える」）。
    - 伏せ札の側に条件を書き、条件を満たしたら自分で差し替わる（「HP が○%以下になったら △△ になる」「○ラウンド目に △△ になる」）。
    - GM がキャラ詳細から手で差し替える。
5. **公開と見せ方**：差し替わった瞬間に、新しいパッシブをキャラ詳細で見えるようにする。気づかせ方はログの文ではなく演出で行う（論点7）。計画66 の図鑑ができていれば、そこでも「登場の時」と同じく解禁する。

## 4. 対象範囲

対象とするもの：伏せ札の印、差し替える効果、キャラ詳細と図鑑での見え方、テストと仕様（B02・C01・D01）。

対象としないもの：パッシブ以外（能力値・画像・名前）の形態変化、パッシブを戦闘中に消すだけの効果。

## 5. 段階（たたき台）

1. 伏せ札の印と差し替える効果（戦闘の処理・スキーマ・管理画面のフォーム）。
2. キャラ詳細での「？？？」と公開（図鑑での扱いは、計画66 の図鑑ができてから合わせる）。
3. 見本の敵（形態変化のボス）を1体作り、演習場（E02）やシミュレータ（F03）で試す。

## 6. 論点（未決定）

1. **効果の形**：「伏せ札を1枚外して付ける」だけにするか、外す伏せ札を指定できる（伏せ札ごとに中身の候補を決めておく）ようにするか。伏せ札が残っていないときにそのまま付けるか、何もしないか。
2. **伏せ札の数の見せ方**：「？？？」を枚数どおり並べるか（枚数自体がヒントになる）、「何か隠している」を1つだけ出すか。
3. **元に戻すか**：形態変化を取り消す（得たパッシブを伏せ札に戻す）効果やラウンドでの期限を作るか。戦闘が終わったとき・待機列で戻したときの扱い。
4. **召喚のキャラ**：召喚で出たキャラにも伏せ札を持たせられるか。
5. **誰が使えるか**：敵だけの効果にするか、味方のスキルにも使えるか（味方の覚醒のような遊び）。
6. **得たパッシブの登場時の効果**：差し替えた瞬間に、そのパッシブの「登場時」や「ラウンド開始時」の効果を起こすか。
7. **演出**：**ログの文は出さない（決定 2026-11-17）**。ユーザーの案（2026-11-17）：パッシブが変わった敵の駒の近くに、更新の印（アイコンや「New!!」など）を付ける。いつ消すか（キャラ詳細を開いた時、次のラウンドなど）も決める。差し替えた時の気づかせ方を、駒や解決パネル・キャラ詳細の演出（「？？？」の札が割れて中身が現れる、など）で決める。スキルで変えた時とスキルに頼らずに変えた時で、同じ演出にするか。
8. **スキルに頼らない変え方**：§3.4 の候補（行動チャートのループに入った時の動作、伏せ札の側の条件、GM の手動）のどれを作るか。いつ判定するか（ラウンドの頭、解決の後、HP が変わった時など）。
