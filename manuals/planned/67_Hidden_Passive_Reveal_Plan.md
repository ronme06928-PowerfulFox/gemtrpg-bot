# 計画67：伏せたパッシブを戦闘の途中で得る（形態変化）

作成日: 2026-11-17
状態: 実装完了（2026-11-23）。PR67-1〜3 をローカルで確認。マスターデータベース・プロジェクトとは別の、戦闘の仕組みの計画。ホロウダンジョン（計画35）に手を付ける前に行う（2026-11-23 ユーザー）。

## 1. 目的

ボスなどの敵が、戦闘の途中で新しい特殊パッシブを得る（第2形態になる）遊びを作る。敵には中身を伏せたパッシブを持たせておき、決まった時にそれを明かして効かせる。遊ぶ人には「この敵にはまだ何か隠している物がある」ことだけが見え、明かした瞬間に中身が分かる（2026-11-17 ユーザーの構想）。

## 2. 今の作り（2026-11-17 調査、2026-11-23 補足）

- **キャラのパッシブ**：キャラの `SPassive`（特殊パッシブの ID の並び）で決まる。戦闘の途中で `SPassive` を変える仕組みは無い。ユニットでは `passives` の欄で持ち、盤面に出すときに `SPassive` へ写す（`manager/units/characters.py`）。召喚は召喚テンプレートの `SPassive` を写す（`manager/summons/service.py`）。
- **パッシブの効果の組み立て**：`manager/utils.py` の `apply_passive_effect_buffs` が `SPassive` から、パッシブ由来の常時バフ（`special_buffs` の `source: "passive"`）を組み直す。何度呼んでも前のパッシブ分を消して作り直す。能力値の補正は `get_passive_stat_mod` が使うたびに `SPassive` を読む。呼ばれている所は、キャラの追加（`events/socket_char.py`）・待機列の登場（`manager/preset_deployment.py`）・召喚（`manager/summons/service.py`）。
- **似た効果**：`GRANT_SKILL`（B02 §2）は、効果で対象にスキルを付け与える（`manager/battle/effect_handlers/action_effects.py`）。パッシブを付け与える効果は無い。
- **行動チャート**：敵の行動チャート（D01 Part 1 §6）は「次にどのスキルを使うか」を決める。ループの移り変わり（`transitions`）は HP 割合などの条件で、ラウンドの頭（敵の宣言を作る時）に判定する。パッシブを直接変える機能は無い。
- **図鑑**（計画66、完了）：出会ったユニットの中身を図鑑で解禁する。敵専用の印（`marks` の `enemy`）を持つ物は、出会うまで見せない。

## 3. 作るもの（2026-11-23 決定）

### 3.1 伏せたパッシブの持ち方

- ユニット（ユニット管理）と召喚テンプレートに、`hidden_passives` の欄を足す。中身は明かす物の並びで、1件は `{passive_id, reveal_when}`。
  - `passive_id`：明かしたときに効く本物の特殊パッシブの ID。中身は最初から決まっている。効果の無いダミーのマスターは作らない。
  - `reveal_when`（任意）：伏せた側に書く、自分で明かす条件。今は「HP 割合が ○% 以下」と「○ラウンド目以降」の2つ。両方書いたら両方を満たした時。
- 盤面に出したキャラは `hidden_passives` を写して持つ。明かすまで、その特殊パッシブは効かない（`SPassive` に入っていない）。
- 持ちキャラ（遊ぶ人のキャラ）には持たせない（味方の覚醒は必要になったら足す）。

### 3.2 明かす処理（1か所にまとめる）

明かす処理は1つの関数にまとめ、次の3つの入口から呼ぶ。

1. **スキルの効果**：新しい効果タイプ `REVEAL_PASSIVE`（`passive_id` を指定）。対象の `hidden_passives` にその ID があれば明かす。無ければ何もしない。
2. **行動チャートのループに入った時**：ループに「入った時に明かすパッシブ」の並びを書ける。HP 割合などで第2形態のループへ移った時に明かす。
3. **伏せた側の条件**：`reveal_when` を、ラウンドの頭（R開始。ループの移り変わりと同じ時）に判定する。明かしたパッシブは、そのラウンドの宣言から効く。

明かす処理がすること：

- `hidden_passives` から外し、`SPassive` の末尾に足し、`apply_passive_effect_buffs` で常時の効果を組み直す。
- 「戦闘開始時」などの、明かした瞬間だけの効果は起こさない。「ラウンド開始時」などは、次の機会から普通に働く。
- ログに「〇〇は △△ を得た」のような文は出さない（2026-11-17 決定）。
- 戻さない。取り消す効果・期限は作らない。戦闘終結の後も明かしたまま残る。待機列から出し直した敵は、ユニットから新しく写すので伏せた状態で出る。

### 3.3 見え方

- 遊ぶ人のキャラ詳細には、伏せた数だけ「？？？」を並べる（数もヒントになる）。GM には中身が見える。
- 伏せた中身（パッシブの ID・名前・条件）は、GM 以外の端末へ送らない。画面で隠すだけにしない。
- 図鑑は、明かす前の伏せたパッシブを解禁しない。明かした時に、出会いと同じく解禁する。
- 演出：明かした敵の駒に小さな「New!!」の印を、そのラウンドの終わりまで全員に出す。キャラ詳細では縦の光が左から右へ走り、通ったところから「？？？」の札の中身が現れる。スキルで明かした時もそれ以外も同じ演出。

## 4. 対象範囲

対象とするもの：伏せたパッシブの欄（ユニット・召喚テンプレート）、明かす処理と3つの入口、キャラ詳細と図鑑での見え方、演出、管理画面の入力、テストと仕様（B02・C01・D01・E02）。

対象としないもの：パッシブ以外（能力値・画像・名前）の形態変化、パッシブを戦闘中に消すだけの効果、持ちキャラの伏せたパッシブ、GM がキャラ詳細から手で明かす操作（2026-11-23 作らないと決めた）。

## 5. 守る決まり

- AGENTS.md の順（資料 → テスト → 最小実装 → 片付け）。後方互換やデータ移行は作らない。
- 伏せた中身はサーバーの外へ漏らさない（§3.3）。状態の配信・図鑑・演習場の API・ログのどれでも確かめる。
- 明かす処理は1か所。3つの入口はそれを呼ぶだけにする。
- 手元の DB は開かない。確認は `python app.py --db _local/agent_db/gemtrpg.db`。

## 6. 論点（すべて決定、2026-11-23）

1. **持ち方**：ユニットに伏せた欄を足し、本物の ID を最初から入れておく（§3.1）。ダミーのマスターは作らない。
2. **数の見せ方**：伏せた数だけ「？？？」を並べる。
3. **元に戻すか**：戻さない。戦闘終結の後も明かしたまま。
4. **召喚のキャラ**：召喚テンプレートにも伏せた欄を持たせる。
5. **誰が使えるか**：ユニットと召喚テンプレートだけ。持ちキャラには持たせない。
6. **明かした瞬間の効果**：起こさない。常時の効果を組み直すだけ。
7. **演出**：駒に「New!!」（そのラウンドの終わりまで）を出し、キャラ詳細では左から右に走る光で「？？？」を明かす。入口によらず同じ。
8. **スキルに頼らない明かし方**：行動チャートのループに入った時と、伏せた側の条件（ラウンドの頭に判定）。GM の手動は作らない。
