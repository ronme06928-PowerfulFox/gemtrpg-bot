# 計画66：マスターデータベースを探す・見せる（段階3）

作成日: 2026-11-17
状態: 論点16個を決め、PR66-1〜PR66-3 は完了（2026-11-17）、PR66-4 は完了（2026-11-18）。図鑑の見た目は試作で固めた（2026-11-18、論点14・15）。残りは §5 の段階で進め、次は PR66-5。[マスターデータベース・プロジェクト](../projects/master_database/README.md)の段階3（今後の順番3）。

## 1. 目的

段階1・2で、ルールの部品（スキル・バフ・用語など7種類）とユニット資源（敵・行動パターン・編成・ステージ）を作って入れる仕組みはできた。この計画では、それを**探す・つながりをたどる・遊ぶ人に見せる**側を作り、データベースとして使える形にする。

- 制作者：管理画面で「このバフはどのスキル・敵で使われているか」をたどれる。
- 遊ぶ人：用語・スキル・アイテム・バフ・エネミーを読める図鑑（2026-11-14 ユーザーの構想）。
- どちらでも、敵専用のデータなどのネタバレを、見せてよい範囲に絞る（段階1で保留した対策）。

## 2. PR66-1 実装前の作り（2026-11-17 調査）

- **管理画面（マスターデータ）**：`static/js/master_data/workspace.js`。種類ごとのタブ（件数つき）、ID・名前・説明の文字検索、状態（公開・廃止、制作者には下書き・承認待ち・却下）、分類の絞り込み、一覧と詳細の2つの面。スキルは専用画面で、左に10カテゴリ（`E` は敵スキル）。**種類をまたいだ検索は無い**（種類をまたぐ一覧は管理者の「承認待ち」だけ）。
- **逆引き**：`manager/catalog/references.py` の `find_references`（`GET /api/catalog/<kind>/<id>/references`）が「この項目を参照している所」を返す。用語は関連用語と文章の `[[W-xx]]`、バフは `buff_id`・`buff_name`、ほかは ID の一致。スキル・パッシブ・輝化・アイテムはユニット（`skills`・`passives`・`radiance`・`items`）からの参照も含む（非公開のユニットは制作者だけ）。画面は詳細の「使われている所（N件）」の折りたたみだけで、**行は文字だけで押しても移れない**。
- **遊ぶ人の引き方**：用語は文章の中のリンク（ホバーで要約・押すと窓、`static/js/common/glossary_ui.js`）からだけ。スキルは自分のキャラのスキル一覧か用語のリンクから詳細の窓（`openSkillDetailModal`、本の見た目）。バフ・アイテムには一覧が無い。一覧で探すには、メインメニューの「マスターデータ」（管理画面、ログインした全員が読める）を開くしかない。
- **公開範囲**：`/api/get_{skill,skill_metadata,item,radiance,passive,summon,buff,glossary}_data` の8つは認証なしで全件を配る（敵スキルも含む。戦闘の画面がこれを読む）。管理 API（`/api/catalog/*`）はログインが要る。
- **敵専用の目印**：スキルの ID の頭 `E`（138件中36件）だけ。パッシブ・バフ・アイテム・輝化には敵専用・ホロウ専用・公開範囲の項目は無い。ユニットには公開範囲（`public`・`staff`。`staff` は制作者・管理者・そのルームの GM だけ）と、`gm_only`・`scenario` などの印がある（D01 Part 4）。ホロウ専用の印（`domain`）は計画35の PR35-1・PR35-10 で付ける予定で、まだ無い。
- **件数**：スキル138・用語83・バフ53・輝化9・パッシブ8・アイテム3・召喚テンプレート3（`data/cache/`）。全部合わせても数百件で、端末に全部を読んでも軽い（最大のスキルで約137KB）。
- **画面の置き場**：メインメニュー（`static/js/app_screens.js`）の `MENU_CARDS`（セッション・ダンジョン・マイキャラクター・使い方）と `DATA_CARDS`（ユニット管理・マスターデータ）。新しい画面は `SCREENS`・`WORKSPACES` とカードを足す。

## 3. 柱（たたき台）

### 3.1 種類をまたいだ検索

図鑑（PR66-4）では、1つの入力欄で種類をまたいで探せるようにする。対象は論点3、管理画面の検索範囲は論点11に従う。

### 3.2 つながりをたどる

マスターデータ管理画面の詳細で「参照している物」（このスキルが付けるバフ・使う用語など）と「使われている所」（逆引き）を、押すとその項目へ移れるリンクにする。戻るで元の項目へ戻れる。図鑑のリンクの範囲は論点7に従う。

### 3.3 遊ぶ人の図鑑

読むための画面。用語・スキル・アイテム・バフ・エネミーを、ゲームでの見え方（本の見た目のスキル詳細など）で見せる。編集の操作は出さない。ルームの中から開けるかは論点。

### 3.4 ネタバレ対策

見せてよい範囲を決める。対象の候補は、敵スキル（`E`）、敵専用のパッシブ・バフ、敵ユニット、ホロウ専用の項目。隠し方は「図鑑に載せないだけ」から「配る API から外す」まで段がある。API から外すには、戦闘で敵のスキルを送る経路の改修が要る（段階1 論点3 の保留理由）。

### 3.5 戦闘マスターへの入口

スキルの詳細に「このスキルを試す」を置き、計画63（戦闘マスター）を開く。計画63 ができてから足す。

## 4. 対象範囲

対象とするもの：ルールの部品7種類とユニット資源の検索・閲覧・つながり、遊ぶ人の図鑑、その公開範囲。

対象としないもの：データの作り方・承認の流れ（段階1）、ユニットの編集（段階2）、かち合わせ・勝率（計画63）、一括編集。

## 6. 論点

1. **画面の分け方**：**決定（2026-11-17）図鑑は別の画面、制作者のつながりのリンクは今の管理画面に足す**（管理画面の横断検索は論点11 で見送り）。図鑑は読むための画面（本の見た目）として新しく作る。使う人ごとに画面の役目を分ける。
2. **図鑑の入口**：**決定（2026-11-17）メインメニューのカードと、ルームの中の両方**。遊んでいる最中にもルームの中から窓で開き、その場で引ける。今のスキル詳細の窓・用語の窓との関係は、図鑑の作りを決めるときに合わせる。
3. **図鑑に載せる種類と並べ方**：**種類は決定（2026-11-17）用語・スキル・バフ・アイテム・エネミー・輝化スキル・特殊パッシブの7つ。召喚テンプレートは載せない**。並べ方（スキルのカテゴリなど）は図鑑の作りを決めるときに試作で見る。
4. **ネタバレの範囲**：**決定（2026-11-17）敵専用の物（敵スキル `E`・敵ユニット・敵専用のパッシブやバフ）は、遊ぶ人がその敵に出会うまで図鑑で「？？？」にし、出会ったら見える**。GM・制作者には全部見せる。図鑑らしい楽しさ（集める）を出す。出会いの記録が要る。
5. **ネタバレの隠し方**：**決定（2026-11-17）図鑑の表示で隠すだけ**。配る API は今のまま（調べようとすれば見られるが、仲間内の遊びには十分で、戦闘の改修が要らない）。**出会いの決まり**：敵ユニットとその特殊パッシブは盤面に登場した時（パッシブはキャラが持っている物で、戦闘の途中で段階的に切り替えたり開いたりする仕組みは無いため。召喚で出たキャラも登場として扱う）、敵スキルはその敵がラウンドの宣言で使用を予告した時（論点10 と同じ時）、敵専用のバフは戦闘で付いた時に解禁する。その場にいた参加者全員が対象。2026-11-17 に「スキル・パッシブは使われた時」から改めた。
6. **敵専用の目印**：**決定（2026-11-17）パッシブ・バフ・アイテムに「敵専用」の印の項目を足し、制作者が管理画面で付ける**（スキルは今の ID の頭 `E` のまま）。**ホロウ専用の印も同じ仕組みで先に作る**（印を「敵専用」「ホロウ専用」と増やせる形にし、計画35 はそれを使う）。図鑑でホロウ専用を隠すかは計画35 で決める。
7. **逆引きの見せ方**：**決定（2026-11-17、第3回の結果を第4回に反映）図鑑には出さない**。逆引きは制作者の管理画面の「使われている所」のリンクだけにする。用語やバフでは数十件になり、遊ぶ人の読む頁には要らない。本文中の用語（`[[W-xx]]`）のリンクは残す。
8. **検索の置き場**：**決定（2026-11-17）端末で絞る**。画面を開いた時に公開データを読み、打つたびに端末で絞る。件数が大きく増えたら見直す。
9. **見た目**：**方向は決定（2026-11-17）紙と金とは違う、ファンタジー感のある模様や色合いにする**（ユーザー：ずっと同じ紙と金では代わり映えがしない）。案は試作で見比べて決める。候補：革装丁と蝋封の古書、星図（夜空の青と星座の線）、宝石の標本箱（ビロードの地と台座）、錬金術の手稿（インクの図と円陣）。読む所の文字のコントラスト（UI計画 §2.6）は守る。

10. **ルームの中のキャラ詳細の敵スキル**（2026-11-17 ユーザーの構想）：**決定（2026-11-17）敵側で登場したキャラは、所持スキルを全部「非公開」（`hidden_skills`）にして登場する。その敵がラウンドの宣言でスキルの使用を予告したら、そのスキルを自動で公開にし、遊ぶ人のキャラ詳細で読めるようにする。図鑑の解禁も同じ時にそろえる**。GM は今どおりキャラ詳細の「公開」の印で手で公開・非公開にできる。
    - 今の作り：キャラ詳細のスキル一覧は、`hidden_skills` に入ったスキルを GM 以外に出さない（`static/js/modals.js`）。GM は「公開」の印で1つずつ切り替える。初めは全部公開。
    - 予告の時：敵の宣言（PvE は自動、PvP は GM）が確定して、遊ぶ人に見える形になった時。宣言を取り消しても、一度公開したスキルは戻さない。
11. **管理画面の横断検索とリンクの戻り方**（PR66-1）：**決定（2026-11-17）管理画面には種類をまたいだ検索を作らない**。効き目が大きいのはつながりのリンクで、件数は数百件なので種類ごとのタブでも探せる。種類をまたいだ検索は図鑑（PR66-4）で作り、管理画面で要るようになったら流用する。**戻り方は詳細の上の戻るボタン**（たどった順に戻る。ブラウザの戻るは今のまま）。**ユニットもリンクに含め、押すとユニット管理の画面へ移る**（戻るボタンでマスターデータへ戻れる）。
12. **印の作り**（PR66-2）：**決定（2026-11-17）印を付けられるのは特殊パッシブ・バフ・アイテムの3つ**（スキル・用語・輝化は、要るようになったら同じ仕組みで足す）。持ち方は印の並び `marks`（`enemy`・`hollow`。増やせる）。**管理画面は札＋絞り込み**。**検査**：敵専用の物（印 `enemy` の物と `E` のスキル）を、敵以外の物（`E` でないスキル、印 `enemy` の無いパッシブ・バフ・アイテム）が参照していたら「注意」（保存はできる）。ホロウ専用は検査しない（スキルにホロウ専用の印が無く、ホロウのスキルが注意だらけになるため）。**今のデータ**：自動では付けない。`E` のスキルと敵ユニットからだけ使われている物を候補として報告し、push の後にユーザーが本番の管理画面で付ける。
13. **予告での公開と出会いの記録の細部**（PR66-3）：**決定（2026-11-17）**
    - **非公開で登場させる範囲**：敵側（`type` が `enemy`）のキャラすべて。ユニットの配置・手での追加・敵側の召喚のどれでも、所持スキルを全部 `hidden_skills` に入れて登場させる。味方は今どおり（ユニットのスキルの「非公開」の印に従う）。
    - **記録する物**：敵の関係を全部記録する（後から印を付けても、過去の出会いで解禁されるように）。登場の時はユニットの ID（配置の時にキャラへ `source_unit_id` として持たせる。手で追加・召喚の敵はユニットが無いので記録しない）と、そのキャラの特殊パッシブ全部。予告の時はそのスキルの ID（`E` に限らない）。バフは戦闘で付いた物全部（どちらの側に付いたかを問わない。敵が遊ぶ人へ付ける物が主なため）。図鑑はこの記録と印から「？？？」を決める。
    - **参加者**：その時ルームにつないでいるログイン中のユーザー全員（GM を含む）。席を外していた人は解禁されない。
    - **手での公開**：GM がキャラ詳細の「公開」の印で敵のスキルを公開した時も、予告と同じく記録する（図鑑も解禁）。
    - **表**：ユーザーごとの出会いの表（ユーザー・種類・ID・最初に出会った日時・ルーム）。同じ物は最初の1回だけ残す。読む API は図鑑（PR66-4）で作る。
14. **図鑑の見た目の試作**（§5 の 4）：**決定（2026-11-17）**
    - **案**：革装丁と蝋封の古書・星図・宝石の標本箱の3つ（錬金術の手稿は外す）。
    - **組み方**：「左に一覧・右に詳細」と「カードの並び＋窓」の両方を作り、案と組み方を切り替えて見比べる。
    - **？？？**：出会っていない敵専用の物は、一覧に ID と「？？？」の枠だけ出し、詳細は開けない。種類ごとに「解禁 12/36」のように数を出す。
    - **スキルの詳細**：中身（威力・コスト・効果の文章）は今のスキル詳細の窓の部品を使い回し、地と飾りだけ案の色に合わせる。
    - **第1回の結果（2026-11-17 ユーザー決定）**：意匠は**宝石の標本箱**、組み方は**カード＋窓を本の形に発展させる**。
      - 分類ごとに1冊の本にして棚に並べ、開くと1項目ずつの頁をめくって読む。
      - 宝石は透明感と輝きのある表現にする。
      - 配色は深緑だけにせず、本ごとに宝石の色を変える。読む面の文字は十分なコントラストを取る。
      - 古書・星図と「一覧＋詳細」は外す。第2回の試作で詰める。
    - **第2回の結果（2026-11-17 ユーザー決定）**：16冊の棚・目次・1項目1見開き・頁送りの形は保つ。第3回の試作で次を詰める。
      - 左の頁に、宝石・ID・名前のほか、札・フレーバー・初めて出会った日を移し、右の頁を本文だけにする。
      - 頁めくりを、紙が回って見える形にする。
      - 棚の本を、カードではなく背表紙の並ぶ本に見せる。宝石の色を本ごとに重ねない。
      - 頁番号は目次と合わせ、「？？？」を飛ばした時は番号も飛ぶ（`2/37 → 4/37`）。
    - **第3回の結果（2026-11-17 ユーザー決定）**：背表紙の棚・頁めくり・1項目1見開きは保つ。第4回の試作で次を詰める。
      - 棚は使う場面で4段に分ける：**戦う**（アクティブのスキル9冊：Ps〜C、宝石の加護を含む）・**身に付く力**（輝化スキル・特殊パッシブ）・**出会う**（敵スキル・エネミー）・**調べる**（用語・バフ・アイテム）。
      - 目次は空きを残さず、大きめのカードで頁を敷き詰める。入り切らない本は目次を複数の見開きにする。

    - **第4回の結果（2026-11-18 ユーザー決定）**：第5回の試作で次を詰める。
      - 棚は**仕切りの違う標本箱**にする。本の数に合わせた幅の区画に分け、空きを出さない。4つの区画の名前は**技能**（アクティブのスキル9冊）・**天賦**（輝化スキル・特殊パッシブ）・**脅威**（敵スキル・エネミー）・**知識**（用語・バフ・アイテム）にする。

      - 頁めくりでは、めくる紙の上下が本の枠で切れて見えている。めくる間は枠で切らず、紙全体が見えるようにする。
    - **第5回の結果（2026-11-18 ユーザー決定）**：本らしさのため、背表紙の幅と高さを全冊でそろえ、細くする。区画は本の数に合わせた幅で、上の段に技能・天賦・脅威、下の段に知識とホロウの引き出しを並べる。

      - **世界の理**：用語・バフ。

    - **ホロウ専用**：印 `hollow` の物は、計画35 でホロウの扉を開くまで遊ぶ人の図鑑に載せない（本にも数にも出さない）。ホロウの扉は錠のまま「0/？」。制作者には本の中に印付きで見せる。
    - **敵ユニットの範囲**：敵として出せるユニット（`allow_enemy` が真）をエネミーの本に載せる。今のユニットはほぼ敵だけ。味方専用（`allow_enemy` が偽）のユニットは今は載せず、味方 NPC が出てきたら別の本を作るかをその時に決める。
    - **公開範囲 staff の敵ユニット**：出会うまでは遊ぶ人に存在も伏せる（数にも入れない）。出会ったら、その人の図鑑に載せる（図鑑用の API が出会った分だけ返す）。public の敵ユニットは、出会うまで「？？？」。
