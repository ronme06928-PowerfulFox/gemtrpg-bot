# 計画55：演出に合わせた効果音

作成日: 2026-10-29
状態: たたき台（議論前）。着手は計画52のPR5の後。§9の論点を一問一答で決めてから、指示文を作る。

## 1. 目的

計画52で入れた演出（威力の確定、攻撃の動き、着弾、効果名、戦闘不能、宝石の加護、戦闘の終結など）に、ちょうど合う短い効果音を足す。音を演出と同じ瞬間に鳴らし、遊んでいるときの没入感を上げる。

## 2. 対象範囲

対象：

- PC Web版の戦闘画面と、セッション中のログ表示で鳴る効果音。
- 効果音の素材（探す、または作る）と、その置き場所・ライセンスの記録。
- 演出と音を同じ時刻に合わせる仕組み（§4）。

対象外：

- BGM（計画28のP3の大型テーマに残っている。必要になったら別計画にする）。
- モバイル版（`static/mobile/`。開発停止中）。
- 説明動画（計画54）への音の取り込み。この計画では、動画も同じ時刻の表を読めるようにするところまでを扱う。
- サーバーの判定や記録の変更。音はすべて画面側で、今ある知らせと記録から鳴らす。

## 3. 今の効果音（2026-10-29 調査）

- 鳴る音は、ダイスを振ったときの1つだけ（`static/audio/dice-roll.mp3`、約14KB）。ログの種類は `SoundFx.isDiceLog` で見分ける。
- 仕組みは `static/js/sound_fx.js`（`window.SoundFx`）。HTMLの `Audio` を音ごとに使い回し、鳴らせないときはブラウザの中で合成した短い音（`AudioContext`）に切り替える。
- スマートフォンのブラウザで音を出すための最初の解除（画面に触れたときに音の再生を許可させる処理）はすでにある。
- 設定は `localStorage` の `sound_fx_enabled`（入り切り）と `sound_fx_volume`（音量。既定 0.55）。アクションドックの♪ボタンで入り切りを切り替える（`action_dock.js`、探索の画面は `exploration_dock.js`）。
- 計画52の決まりに「効果音を鳴らしている箇所には、演出も同じ箇所から出す」がある（計画52 §5）。

## 4. 作り方（案）

### 4.1 鳴らす時刻は演出の定義に値として持たせる

- 各演出の定義（`Fx.define`）に、何秒目にどの音を鳴らすかの表を値として足す。例：`sounds: [{ t: 0.8, name: 'impact-heavy' }]`。
- 音を鳴らすのは再生側（`fx_player.js` から `SoundFx`）だけにする。演出の定義（`fx_core.js`・`fx_effects.js`）は、今の決まり（時刻から描く、アプリや `setTimeout` に頼らない。計画52 §4.2・§4.4）のまま、音の表を値として持つだけにする。
- 再生側は、演出を始めるときに、まだ過ぎていない時刻の音だけを予約する。途中から描いたとき（`elapsedSeconds`）は、過ぎた音を鳴らさない。`Fx.finishAll` で片付けたときは、予約した音も取り消す。
- 段階（小・中・大）で音を変えたいときは、`render` と同じく `params` を見て音の名前や音量を選べるようにする（具体的な形は §9 の論点）。
- 動画は同じ表を読んで音を置ける。

### 4.2 音の名前と素材の対応は1か所

- 音の名前（`impact-heavy` など）と素材のファイルの対応は、`SoundFx` の側に1か所だけ置く。演出の定義には素材のファイル名を書かない。
- 素材を差し替えても、演出の定義は直さない。

## 5. 要る音の候補

| 場面 | 計画52の演出 | 音の候補 |
|---|---|---|
| ダイス（チャット） | `chat-dice` | 今の `dice-roll`（そのまま） |
| 威力の確定 | `power-roll` | ダイスが止まる・数字が決まる短い音 |
| マッチのぶつかり合い | `clash-flash` | 金属が打ち合う音 |
| 斬撃 | `attack-slash` | 風を切る音 → 着弾で斬る音 |
| 打撃 | `attack-strike` | 振り下ろす音 → 着弾で重い衝撃音 |
| 貫通 | `attack-pierce` | 鋭い突きの音 → 刺さる音 |
| 属性なしの一撃 | `attack-flash` | 軽い打撃音 |
| ダメージの数字 | `resolve-damage` | 鳴らさないか、ごく小さい音（攻撃の音と重なるため。§9） |
| 効果名のポップアップ | PR4の効果名 | 決め音（効果ごとに変えるかは §9） |
| 混乱 | PR4の「混乱」 | 揺らぐような音 |
| 戦闘不能 | PR4の結晶が砕ける演出 | ガラス・結晶が割れる音 |
| 宝石の加護 | PR5のカットイン | 宝石がきらめく和音 |
| 勝利・敗北 | PR5の終結の飾り | 短いファンファーレ・沈む音 |
| ラウンド開始 | `round-banner` | 短い合図の音（鳴らすかは §9） |

- 攻撃の小・中・大は、別の素材を用意せず、音量と高さで変えるのが第一案。

## 6. 素材の手に入れ方（どれにするかは §9）

| 方法 | 例 | よい点 | 気をつける点 |
|---|---|---|---|
| 無料の効果音サイト | 効果音ラボ、OtoLogic など | 音の質が高い。日本語で探しやすい | 利用規約の確認が要る。素材をリポジトリに置いて配ってよいか、クレジットの表記が要るか、加工してよいか |
| CC0（権利を放棄した素材） | Kenney、Freesound の CC0 のもの | 配り方・表記の心配がない | 探す手間がかかる。質にばらつきがある |
| 自分で作る（ファイルにする） | 音を合成する道具（jsfxr など） | 権利の心配がない。演出の長さにぴったり合わせられる | 作る手間がかかる。ゲームらしい電子音に寄りやすい |
| 自分で作る（ブラウザの中で合成） | `AudioContext` で鳴らす | ファイルが要らない。今の予備の音と同じ仕組み | 質を上げにくい |

- どの方法でも、素材ごとに出どころ・ライセンス・作者・加工の有無を記録する（置き場所は §9）。
- ネットから素材を落とすときは、そのたびに、何を・どこから・どれくらいの大きさで落とすかをユーザーに確かめてから落とす。

## 7. 守る決まり（案）

- ♪が切りなら鳴らさない。音量は今の `sound_fx_volume` に従う。
- 再接続や状態の同期では鳴らさない。その場で起きたことにだけ鳴らす（計画52 §5と同じ）。
- 同時に鳴らす数に上限を設ける。広域攻撃などで一斉に起きるときは、同じ音をまとめる。
- 演出の段階（軽め・通常・派手）とは別に扱う。動きを減らしたい人でも、音は聞きたい場合があるため（§9で決める）。
- タブが裏にある間は鳴らさない。
- 進行の時間は延ばさない。音の終わりを待たない。
- 素材は短く小さくする（1つ1〜2秒、10〜30KB程度）。置き場所は `static/audio/`（Render は Node を持たないので、素材もリポジトリに置く。Cloudinary にするかは §9）。

## 8. テスト

- 演出の定義の音の表：値の形（時刻・名前）が正しいこと。長さを超える時刻がないこと。
- 再生側：始めたときに過ぎていない音だけを予約すること。途中から描いたときは過ぎた音を鳴らさないこと。`Fx.finishAll` で予約が消えること。♪が切りなら予約しないこと。
- 名前と素材の対応：演出の定義にある音の名前が、すべて対応表にあること。
- 今のテスト（`tests/test_motion_fx_*_frontend.py` の Node `vm` と偽の DOM）と同じ書き方にする。

## 9. 論点（議論前）

1. **素材の手に入れ方**（§6）：サイトの素材・CC0・自作のどれを主にするか。混ぜるか。
2. **リポジトリの公開範囲とライセンス**：リポジトリは公開か非公開か。公開なら、配ってよい素材に限られる。ライセンスの記録をどこに置くか（`static/audio/README.txt` を書き直す、など）。
3. **鳴らす場面の範囲**：§5の表のうち、どれを最初に入れるか。ダメージの数字やラウンド開始は鳴らすか。
4. **段階（小・中・大）と音の変え方**：音量と高さだけで変えるか、別の素材を用意するか。
5. **演出の段階との関係**：軽めのときも音を鳴らすか。音だけの設定（音量の段階など）を足すか。
6. **効果名の決め音**：全部同じ音にするか、効果ごとに変えるか。
7. **置き場所**：`static/audio/` か Cloudinary か。
8. **PRの分け方**：仕組み（§4）と最初の数個の音を1つ目、残りの音を2つ目、など。
