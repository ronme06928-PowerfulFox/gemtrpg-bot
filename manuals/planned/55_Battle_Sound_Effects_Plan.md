# 計画55：演出に合わせた効果音

作成日: 2026-10-29
状態: 1つ目（音を予約する仕組みと宝石の加護の全体版のS3）を実装。論点4・6はその場面を作るときに決める。

## 1. 目的

計画52で入れた演出（威力の確定、攻撃の動き、着弾、効果名、戦闘不能、宝石の加護、戦闘の終結など）に、ちょうど合う短い効果音を足す。音を演出と同じ瞬間に鳴らし、遊んでいるときの没入感を上げる。

## 2. 対象範囲

対象：

- PC Web版の戦闘画面と、セッション中のログ表示で鳴る効果音。
- 効果音の素材（探す、または作る）と、その置き場所・ライセンスの記録。
- 演出と音を同じ時刻に合わせる仕組み（§4）。

対象外：

- BGM（計画28のP3の大型テーマに残っている。必要になったら別計画にする）。
- モバイル版（`static/mobile/`。開発停止中）。
- 説明動画（計画54）への音の取り込み。この計画では、動画も同じ時刻の表を読めるようにするところまでを扱う。
- サーバーの判定や記録の変更。音はすべて画面側で、今ある知らせと記録から鳴らす。

## 3. 今の効果音（2026-10-29 調査）

- 鳴る音は、ダイスを振ったときの1つだけ（`static/audio/dice-roll.mp3`、約14KB）。ログの種類は `SoundFx.isDiceLog` で見分ける。
- 仕組みは `static/js/sound_fx.js`（`window.SoundFx`）。HTMLの `Audio` を音ごとに使い回し、鳴らせないときはブラウザの中で合成した短い音（`AudioContext`）に切り替える。
- スマートフォンのブラウザで音を出すための最初の解除（画面に触れたときに音の再生を許可させる処理）はすでにある。
- 設定は `localStorage` の `sound_fx_enabled`（入り切り）と `sound_fx_volume`（音量。既定 0.55）。アクションドックの♪ボタンで入り切りを切り替える（`action_dock.js`、探索の画面は `exploration_dock.js`）。
- 計画52の決まりに「効果音を鳴らしている箇所には、演出も同じ箇所から出す」がある（E01「演出の土台の決まり」）。

## 4. 作り方（案）

### 4.1 鳴らす時刻は演出の定義に値として持たせる

- 各演出の定義（`Fx.define`）に、何秒目にどの音を鳴らすかの表を値として足す。例：`sounds: [{ t: 0.8, name: 'impact-heavy' }]`。
- 音を鳴らすのは再生側（`fx_player.js` から `SoundFx`）だけにする。演出の定義（`fx_core.js`・`fx_effects.js`）は、今の決まり（時刻から描く、アプリや `setTimeout` に頼らない。計画52 §4.2・§4.4）のまま、音の表を値として持つだけにする。
- 再生側は、演出を始めるときに、まだ過ぎていない時刻の音だけを予約する。途中から描いたとき（`elapsedSeconds`）は、過ぎた音を鳴らさない。`Fx.finishAll` で片付けたときは、予約した音も取り消す。
- 段階（小・中・大）で音を変えたいときは、`render` と同じく `params` を見て音の名前や音量を選べるようにする（具体的な形は §9 の論点）。
- 動画は同じ表を読んで音を置ける。そのため、音の表は関数を含まない値（時刻・音の名前・音量）だけにし、音の名前と素材のファイルの対応（§4.2）も動画の側から読める値として置く。素材は手元のファイルから読めるようにする（計画52 §4.4と同じ。説明動画は作業フォルダの外やネットの素材を埋め込めない）。

### 4.2 音の名前と素材の対応は1か所

- 音の名前（`impact-heavy` など）と素材のファイルの対応は、`SoundFx` の側に1か所だけ置く。演出の定義には素材のファイル名を書かない。
- 素材を差し替えても、演出の定義は直さない。

### 4.3 宝石の加護の試聴（2026-11-22）

本番に入れる前に、宝石の加護（`gem-blessing`）の音を3案作り、演出の一覧（計画56）で同じ映像に重ねて聴き比べる。

- 音はファイルにせず、ブラウザーの中で合成する（`AudioContext`）。音の高さ・鳴り始め・減衰などを値の表で持ち、「余韻を半分に」のように値を直して作り直せるようにする。そのため §9 の論点1・2・7（素材・ライセンス・置き場所）はこの段階では決めない。
- 置くのは一覧の側（`scripts/fx_gallery/`）だけで、アプリ本体と本番のバンドルは変えない。
- 加護の全体版（1.6秒）の流れ：宝石が育つ 0.06〜0.36秒、表面の光 0.25〜0.5秒、ひび 0.46〜0.59秒、砕けて閃光 0.6秒、光の粒が胸へ 0.6〜1.2秒、文字 0.72秒から、消える 1.32秒から。解決中の小さい版は同じ流れを1.2秒に縮める。
- 3案：A「一粒」（砕ける瞬間に澄んだ一音）、B「共鳴＋一音」（宝石が育つ間の低い共鳴に、砕ける瞬間の高い一音が重なる）、C「収束」（表面の光とひびの間の細かな結晶音が、砕ける瞬間に一つの和音へまとまる）。値は試聴の依頼文に書く。
- 選ぶ基準：(1) GM が話していても言葉が聞こえる、(2) 戦闘不能の破砕（後で作る）と聞き違えない、(3) 一晩に何度聞いても疲れない。単体で一番きれいな音かどうかでは選ばない。卓に近い音量で、続けて何度も鳴らして判断する。
- 採った案の値は、§4.1 の音の表と §4.2 の名前の対応に移す。本番への組み込みは §9 の論点を決めてから。

試聴用の値は `scripts/fx_gallery/sounds.mjs` に置く。余韻を半分にする場合は対象の音の `decay` を半分にし、`npm run gallery` で一覧を作り直す。

**1回目の結果（2026-11-22 ユーザー）**：3案とも採らない。正弦波を重ねた合成は「安っぽい電子音」で「耳障り」だった。

**2回目：録音の素材を使う**

- ガラス・鈴・結晶・鉱石などを録音した CC0（権利を放棄した）素材を探し、加工して聴き比べる。§6 の「CC0」にあたる。配り方・表記の心配がないため、リポジトリの公開範囲（§9 論点2）に左右されない。
- 落とす前に、候補ごとに出どころ・作者・ライセンス・長さ・大きさを並べ、ユーザーが選んだ物だけを落とす（§6 の決まり）。
- 加工は ffmpeg（手元の 9.0.1）で、切り出し・頭の無音の削除・フェード・音量をそろえる・必要なら高さを変える・重ねる。1つ1〜2秒、30KB 前後。
- 一覧の聴き比べの仕組み（切り替え・音量・5回続けて・過ぎた音を鳴らさない）は1回目の物を使い、合成の代わりに素材のファイルを鳴らす。値の表は「何秒目に・どのファイルを・どの音量と高さで」の形にする（§4.1 と同じく値だけ）。
- 採った素材は、出どころ・ライセンス・加工の内容を記録する（置き場所は §9 論点2・7 で、本番に入れるときに決める）。

**2回目の候補の結果（2026-11-22 ユーザー）**：Freesound の CC0 の6件（一粒・共鳴・収束を2件ずつ）を配布ページで聴き、C1「36 Bar Chimes Sweep Ascend Long Ring Out 01」（loganzsound、[配布ページ](https://freesound.org/people/loganzsound/sounds/874687/)）に絞る。目指すのは「神聖なさらさら感」。C1 だけを加工の案にして、一覧で映像に重ねて聴き比べる。

**3回目：C1 を手本に合成を作り込む（2026-11-22 決定）**

録音をそのまま使う代わりに、C1 を解析して手本にし、値で直せる合成を作り直す。1回目が安っぽかった理由（倍音が整数倍・打つ瞬間の雑音がない・時刻と高さが揃いすぎ・残響と広がりがない）を直す。

- 作る場所は `scripts/sound_lab/`。Python（numpy・scipy。今の環境にある）で値の表から音のファイルを作り、ffmpeg で OGG にする。アプリでは作らず、作った音のファイルを鳴らす（§4.2 の名前と素材の対応にそのまま乗る）。
- 音の作り：チャイムの棒1本ごとに、自由な棒の倍音（基音のおよそ 1・2.76・5.40・8.93 倍）を、高い倍音ほど早く減衰させて重ねる。打つ瞬間に短い雑音を足す。棒ごとの時刻・高さ・音量・左右の位置に、種を決めた乱数で小さなばらつきを付ける（同じ値なら同じ音）。最後に作った残響（減衰する雑音の響き）をかける。
- 手本：原本の取得にはアカウントが要るため、配布ページでログインなしに再生できる試聴用の MP3 を使う（ユーザー承認、Git の外に置く）。C1 から、棒が鳴る時刻・各棒の高さ・減衰の速さ・明るさ（音の重心）を取り出し、値の表の初期値にする。合成と C1 の同じ数値を並べて比べる。
- 一覧（計画56）の加護のカードで、C1 の加工版（手本）と合成の案を切り替えて聴く。
- 言葉と値の対応（「さらさら」「神聖」「耳障り」などをどの値で直すか）を `scripts/sound_lab/` に書き、エージェントが言葉の注文から値を直して作り直せるようにする。

C1 の公開試聴版を解析し、一覧で C1・S1・S2・S3 と無音を比較できるようにした。作り直し方と値の対応は [sound_lab の README](../../scripts/sound_lab/README.md) を参照する。

**3回目の結果（2026-11-22 ユーザー）**：S3「さらさら・神聖」を加護の音の候補に採る。値は `scripts/sound_lab/presets.json` の S3 で、同じ値から同じ音を作り直せる。細かな調整は言葉の注文から値を直して行い、本番への組み込みは §9 の論点を決めてから。

## 6. 素材の手に入れ方（どれにするかは §9）

| 方法 | 例 | よい点 | 気をつける点 |
|---|---|---|---|
| 無料の効果音サイト | 効果音ラボ、OtoLogic など | 音の質が高い。日本語で探しやすい | 利用規約の確認が要る。素材をリポジトリに置いて配ってよいか、クレジットの表記が要るか、加工してよいか |
| CC0（権利を放棄した素材） | Kenney、Freesound の CC0 のもの | 配り方・表記の心配がない | 探す手間がかかる。質にばらつきがある |
| 自分で作る（ファイルにする） | 音を合成する道具（jsfxr など） | 権利の心配がない。演出の長さにぴったり合わせられる | 作る手間がかかる。ゲームらしい電子音に寄りやすい |
| 自分で作る（ブラウザの中で合成） | `AudioContext` で鳴らす | ファイルが要らない。今の予備の音と同じ仕組み | 質を上げにくい |

- どの方法でも、素材ごとに出どころ・ライセンス・作者・加工の有無を記録する（置き場所は §9）。
- ネットから素材を落とすときは、そのたびに、何を・どこから・どれくらいの大きさで落とすかをユーザーに確かめてから落とす。

## 7. 守る決まり（案）

- ♪が切りなら鳴らさない。音量は今の `sound_fx_volume` に従う。
- 再接続や状態の同期では鳴らさない。その場で起きたことにだけ鳴らす（演出と同じ。E01「演出の土台の決まり」）。
- 同時に鳴らす数に上限を設ける。広域攻撃などで一斉に起きるときは、同じ音をまとめる。
- 演出の段階（軽め・通常・派手）とは別に扱う。動きを減らしたい人でも、音は聞きたい場合があるため（§9で決める）。
- タブが裏にある間は鳴らさない。
- 進行の時間は延ばさない。音の終わりを待たない。
- 素材は1つ1〜2秒を目安にし、加護はSafari対応のMP3で30〜60KB程度にする。リポジトリの `static/audio/` に置く。

## 8. テスト

- 演出の定義の音の表：値の形（時刻・名前）が正しいこと。長さを超える時刻がないこと。
- 再生側：始めたときに過ぎていない音だけを予約すること。途中から描いたときは過ぎた音を鳴らさないこと。`Fx.finishAll` で予約が消えること。♪が切りなら予約しないこと。
- 名前と素材の対応：演出の定義にある音の名前が、すべて対応表にあること。
- 今のテスト（`tests/test_motion_fx_*_frontend.py` の Node `vm` と偽の DOM）と同じ書き方にする。

## 9. 論点

1. **素材の手に入れ方**（§6）：**決定（2026-11-22）** 加護は自作の合成（`scripts/sound_lab/` の S3）。録音の素材は手本にだけ使い、配らない。ほかの場面は作るときに決める。
2. **リポジトリの公開範囲とライセンス**：**決定（2026-11-22）** 自作の合成なので配り方の心配はない。音ごとの作り方（どの値から作ったか）を `static/audio/README.txt` に書き直して記録する。
3. **鳴らす場面の範囲**：**決定（2026-11-22）** 最初は宝石の加護の全体版（戦闘の始めの1.6秒の演出）だけ。解決中の小さい版は鳴らさない。ほかの場面は同じ作り方で後から足す。
4. **段階（小・中・大）と音の変え方**：音量と高さだけで変えるか、別の素材を用意するか。
5. **演出の段階との関係**：**決定（2026-11-22）** 軽めでも鳴らす。音を止めたい人は今の♪で切る。音だけの設定は足さない。
6. **効果名の決め音**：全部同じ音にするか、効果ごとに変えるか。
7. **置き場所**：**決定（2026-11-22）** `static/audio/`（今のダイスの音と同じ）。
8. **PRの分け方**：**決定（2026-11-22）** 1つ目は仕組み（§4.1・§4.2）と加護の音。ほかの場面は場面ごとに足す。
