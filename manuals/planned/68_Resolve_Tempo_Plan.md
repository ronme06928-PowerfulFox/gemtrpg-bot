# 計画68 解決演出のテンポ

**作成日**: 2026-11-26
**状態**: 計画。論点は決定済み。ホロウ（計画35）を先に進めるため、着手は後に回す（2026-11-26）。着手するときは、速さの倍率を見比べのページで決めてから依頼文を書く。
**きっかけ**: ホロウ（計画35）の手元の試遊で、解決の演出の通常の速さがわずかに間延びして感じた。不発がダイスの音つきでゆっくり流れ、テンポを落としていた。

## 1. 目的

解決の演出のテンポを上げる。ホロウの部屋も通常ルームも同じ仕組みで扱う。

1. 演出の速さを「通常・やや速め・高速」の3段にし、ルームで1つに決める。
3. ドックに散っている表示の設定（演出の強さ・SE・矢印表示）を1つのアイコンの「設定」の窓にまとめ、速さもそこに置く。
2. 不発は解決の舞台に出さず、チャットのログだけに出す。

## 2. 今の作り

- 段階の長さは `static/js/battle/components/resolve_stage_timing.js` の1つの表（`RESOLVE_TEMPO`）から作る。舞台・同期の時計・見比べのページが同じ表を使う（E02「解決パネル」、B03 付録A-2）。
  - マッチ：名前0.5秒＋威力1.2秒＋攻撃0.7秒＋勝敗2.2秒＋待ち0.6秒で、1件5.2秒。戦闘不能があると勝敗を1.5秒延ばす。
  - 不発：名前0.5秒＋威力1.2秒＋結果0.9秒＋待ち0.5秒で、1件3.1秒。威力の段階があるので、ダイスの音も鳴る。
- 威力のロールと攻撃の演出は、段階の長さに合わせて再生の速さを変えている（`fxPlaybackRate`）。
- 次の件へ進む合図は、進行役の画面から出す（自動進行または手動の「次へ」）。全員が合図を受けた時刻から、その件の演出を始める。チャットの保留ログも合図のときに出す（B03 付録A-2）。
- サーバーの `manager/battle/resolve_presentation.py` は、舞台に出さない行（引き寄せ・回避の差し込み・スキルのない不発 `no_intent`）を件数と進行の位置から外している。

## 3. 決めたこと

| 論点 | 決定 | 根拠 |
|---|---|---|
| 速さを持つ単位 | **ルームで1つ**。人ごとには持たない | 次の件へ進む時点は進行役の画面が決める。人ごとに変えても、遅くした人の演出が途中で切られるだけで、進み方は変わらない |
| 変えられる人 | **進行できる人**（通常ルームは GM、ホロウの部屋はホストとオーナー。`can_progress_battle`） | テンポを決めるのは進める人 |
| 段の数と既定 | **通常・やや速め・高速の3段。既定は「やや速め」** | 今の通常はわずかに間延びする。新しいルームも今あるルームも、設定が無ければやや速めで流す |
| 設定の置き場 | **ドックの1つのアイコンから開く「設定」の窓**に、演出の強さ・SE（音量を含む）・矢印表示をまとめる。速さはその窓の中で、進行できる人にだけ出す | ドックのアイコンが多く、役目の違う物が同じ見た目で混ざっている（UI 基盤計画 §7.4 UI-2f）。表示の設定は1か所にあれば探しやすい |
| 不発 | **舞台に出さず、ログだけ**。ダイスの音も鳴らさない | 不発は読む中身が少なく、ゆっくり流す意味がない。高速で流すと一瞬出て読めないまま消えるので採らない |

## 4. 仕様（案）

### 4.1 速さ

- ルームの状態に `resolve_speed`（`normal`・`brisk`・`fast`）を持つ。無いときは `brisk`。
- 段階の長さ（名前・威力・攻撃・勝敗・戦闘不能の延長・待ち）に、段ごとの倍率を一律に掛ける。倍率は §5 の見比べで決める。たたき台は、通常1.0（今の長さ）、やや速め0.8、高速0.6。
- 宝石の加護の前置き（1件1.6秒）にも同じ倍率を掛けるかは、見比べで決める。
- 設定の場所は、ドックの「設定」の窓（§4.2）。速さの欄は進行できる人にだけ出す。変えたら全員へ同期し、次の件から効く（流している件の途中では変えない）。
- 途中参加・再接続の合流（`step_started_at`）も、同じ倍率の長さで計算する。

### 4.2 設定の窓

- ドックの「演出の強さ」「SE切替」「矢印表示切替」の3つのアイコンを、1つの「設定」のアイコンにまとめる。押すと窓が開く。
- 窓の中身：演出の強さ（今の3段）、SE（入・切と音量）、矢印表示（入・切）。ここまでは人ごとの設定で、今の保存のしかたを変えない。
- 進行できる人（通常ルームは GM、ホロウの部屋はホストとオーナー）には、「ルームの設定」の区切りの下に解決演出の速さを出す。ほかの人には出さない。
- 窓は共通の窓（大理石の白、E02 Part 16・17）で作る。

### 4.3 不発

- 不発（trace の `kind: 'fizzle'`）は、すべて `resolve_presentation.py` の舞台に出さない行に含める。件数 `#n/N` と進行の位置からも外す。
- 不発の理由は、今どおりチャットのログに1行ずつ出す。出す時点は、その不発の直前に舞台に出した件の「次へ」の合図か、次に舞台に出す件の合図のどちらかにそろえる（保留ログのキーの扱いを実装で確かめる）。
- 不発でも、その場で効くこと（コストの消費・状態の変化）は今どおり数値とログに反映する。
- そのラウンドがすべて不発なら、舞台は「戦闘開始」の後すぐにラウンドの終わりへ進む。

## 5. 進め方

1. **見比べ**：解決パネルの見比べ用ページ（`npm run resolve-preview`）に、3段の倍率を並べて流せるようにする。マッチ・戦闘不能・広域・加護の前置きで見て、倍率を決める。
2. **PR68-1**：不発を舞台から外す（サーバーの件数とクライアントの舞台。保留ログの出し方）。
3. **PR68-2**：設定の窓と速さ（ドックの3つのアイコンを1つの窓にまとめる、ルームの状態・同期・権限・倍率を掛けた時計）。
4. 実装したら、この計画書を消し、内容を B03（付録A-2）と E02（解決パネル）へ移す。

## 6. 確かめること

- 不発を外しても、件数 `#n/N`・途中参加・再接続・自動進行・手動の「次へ」・引継ぎが今どおり動く。
- すべて不発のラウンド、最後の件が不発のラウンドで止まらない。
- 速さを変えると全員の画面が同じ長さで流れ、進行できない人は変えられない（サーバーでも拒否する）。
- 3段のどれでも、演出の終わりと次の件の始まりが重ならない。
