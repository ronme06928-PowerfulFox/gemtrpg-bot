## 1. 目的

計画52で入れた演出（威力の確定、攻撃の動き、効果名、戦闘不能など）を、戦闘を起こさなくても1か所でまとめて見られるようにする。

- 見た目を決める・直すときに、すぐ見比べられる。
- PRごとの確認で、実際の戦闘を組まずに「どう表示されるか」を確かめられる。
- 演出の一覧（アーカイブ）として、何があるかを後から見返せる。

## 2. 対象範囲

対象：

- 計画52の演出の定義（`static/js/fx/fx_effects.js` の `Fx.define`）すべてを並べた一覧のページ。
- 本物の解決パネルを、見本の記録で頭から最後まで流す通しの見本（§4.2。入れるかは §9）。
- 一覧や通しの見本から、決まった時刻のコマを撮って動く画像・動画にする書き出し（§4.3。入れるかは §9）。

対象外：

- アプリの本番の画面の変更。一覧は本番と同じ定義を読むだけで、本番の動きは変えない。
- 説明動画（計画54）の制作。書き出しの仕組みは、動画からも使えるようにするところまでを扱う。
- 効果音（計画55）。計画55が入ったら、一覧で音も確かめられるようにする（§7）。
- モバイル版（`static/mobile/`。開発停止中）。

## 3. 今の状態（2026-10-29 調査）

- 演出の定義は14種類：`float-text`・`round-banner`・`power-roll`・`clash-flash`・`clash-shade`・`attack-flash`・`attack-slash`・`attack-strike`・`attack-pierce`・`impact-flash`・`resolve-damage`・`effect-band`・`ko-shatter`・`chat-dice`。このうち属性別の攻撃3つ（斬撃・打撃・貫通）は、1つのループでまとめて定義している（計画52 §6.3）。PR5で宝石の加護と戦闘の終結が増える。
- どの定義も `render(t)` だけで描き、同じ t なら同じ見た目になる（計画52 §4.2・§4.4）。録画しなくても、好きな時刻で止めて描ける。
- 再生側の `fx_player.js` は、アプリの中で時計・同時に出す数の上限・段階（軽め・通常・派手）を受け持つ。
- 解決パネル（`ResolveFlowPanel.js`）は `setTimeout` と `Date.now` で段階を進めるので、そのままではコマ単位で止められない。
- 見た目の確かめ方は、今はテスト（Node の `vm` と偽の DOM で数値を読む）だけ。実際のブラウザでの見た目は、PRごとに確かめきれていない（計画52 PR3・PR4の報告）。
- 説明動画の作業では、ブラウザで時刻を指定してPNGを撮り、ffmpeg でつなぐ手順がすでにある（`typst_manual/動画/README.md`）。

## 4. 作り方（案）

### 4.1 一覧のページ（本体）

- 演出ごとにカードを並べた、1枚で完結するHTMLにする。
- 本番と同じ `fx_core.js`・`fx_effects.js`・`motion_fx.css` を読む（または組み立て時に中へ取り込む）。一覧のための別の描き方は作らない。
- 各カードに置くもの：
  - 再生・繰り返し・一時停止。
  - 時刻のつまみ（例：攻撃の着弾の0.8秒で止める）。
  - 段階（軽め・通常・派手）の切り替え。
  - 見本の切り替え（味方・敵、小・中・大、属性、自分への効果など）。
  - コマの帯：0.2秒ごとの見た目を横に並べた静止画。動かさなくても流れが一目で分かる。
- 背景は解決パネルに似せた仮の台（立ち絵の枠、名前、参加者の丸アイコン）にする（2026-10-29 決定）。
  - 立ち絵は `static/images/characters/` の4枚の本物を使う。
  - 状態のアイコン（出血・破裂・亀裂・荊棘・戦慄・蓄力・凝魔）も本物を使う。
  - 背景の洞窟の絵（約5.7MB）は使わず、色の近いグラデーションで代える。
  - 画像はどれもHTMLの中に取り込む。単体のHTMLでは `/static/images/…` のパスが届かないため。HTMLは1MB前後に収める。
- 見本の値は、データとして1か所にまとめる（例：`fx_gallery_samples.js`）。演出を足したら、ここに見本を足す。
- 時刻を進めるのは一覧のページ側の時計にして、各カードの `render(t)` を直接呼ぶ。再生側（`fx_player.js`）を通さないので、同時に出す数の上限などの影響を受けない。

### 4.1a 結果の段階の場面カード（2026-10-29 決定）

- 演出単体のカードに加えて、並べたときの見え方を確かめる場面カードを数枚置く。例：
  - 打ち合いで戦慄殺到から混乱、戦闘不能。
  - 一方攻撃で破裂爆発と追加ダメージ。
  - 広域-合算で3人が被弾し、うち1人が戦闘不能。
  - 自滅。
- 並び順と時刻は、本番と同じ純粋な関数（`resolve_flow_result_fx.js` の `planResolveOutcome` など）で決める。一覧のための並べ方は作らない。
- 描くのは一覧の時計で、各演出の `render(t - at)` を直接呼ぶ。本物の解決パネルと時計の差し替えは使わない。止める、コマ送りする、段階の延長と待ちから求める4.6 / 6.1秒の枠に収まるかを見る、ができる。
- 置き場所（名前・背景・丸アイコンの上）は、一覧の仮の台で本番と同じクラス名を使って決める。本物のパネルの配置とは少し違うことがある。
- **2026-10-29 改め：場面カードは本物の解決パネルで描く**（ユーザーの依頼「実際の解決フェーズの画面に合わせてほしい」）。
  - カードの中身は、本番の `ResolveFlowPanel` の描画（`_renderStep`）にそのまま作らせる。名前・スキル・威力・ダメージの内訳・ボタン・進行の帯まで、本番と同じ見た目になる。
  - CSS は、本番の `visual_battle.css` から解決パネルの規則（`#resolve-flow-panel` を含む規則と、それを含む `@media`）だけを抜き出し、`#resolve-flow-panel` を `[data-gallery-resolve-panel]` に付け替えて取り込む。本番のCSSは書き換えない。
  - 時計：パネルが使う `Date.now` を、描く間だけ一覧の時刻に差し替え、勝敗の段階まで表示が出そろった状態で止める。パネルが読む店の状態（`store`）も、描く間だけ見本の状態に差し替えて戻す。
  - 演出は、本物のパネルの要素の位置に重ねる（`playResolveStageFx` が本物の要素を測る）。
  - カードの幅は、本番の `min(92vw, 1180px)` の代わりに、一覧の枠の幅に合わせる。本番の Socket・タイマー・効果音は動かさない（`initialize` を呼ばない）。
  - 単体の演出のカードは、今どおり仮の台で描く。

### 4.2 通しの見本（解決の流れ。後回し）

- 「打ち合いで戦慄殺到から戦闘不能」「広域-合算で3人が被弾」などの場面を、本物の解決パネルで流す。
- 中身は解決の記録（trace）の見本。テストですでに使っている記録を元にする。
- 時刻を指定して止めるために、見本のページでだけ時計を差し替える（`Date.now`・`setTimeout`・`performance.now`・`requestAnimationFrame`）。アプリの本体は変えない。

### 4.3 書き出し（後回し。2026-10-29 決定）

- 最初のPRには入れない。一覧のHTML（再生・コマ送り・コマの帯）と Artifact で、確かめる目的には足りるため。
- 足すのは、Discord などに動く画像として貼りたい、版ごとにファイルで残したい、説明動画（計画54）の部品にしたい、のどれかが出てきたとき。別のPRにする。
- 足すときの第一候補は WebP。そのときにブラウザの自動操作が作業者の環境で動くかを先に確かめる（2026-10-28 に Claude の環境では Playwright を起動できなかった）。
- 以下は、足すときの案。


- ブラウザの自動操作（Playwright など）で、一覧や通しの見本を決まった時刻ごとに撮り、ffmpeg でつなぐ。
- 形式の候補：
  - WebP（GIFのように動く画像）。
  - MP4。
  - GIF：光や半透明がにじみやすいので、色の数を調整して出す。
- 確認用の出力は Git の外に置き、最新の1組だけを残す（AGENTS.md「確認用の出力の片付け」）。置き場所は §9。
- 繰り返し使う撮影の手順は使い捨てにせず、`scripts/` に置く。

## 5. 置き場所の候補（2026-10-29 決定：ローカルのファイル＋必要なときだけ Artifact）

- 正本は、組み立て用のスクリプト（`scripts/`）と見本の値。スクリプトが本番の `fx_core.js`・`fx_effects.js`・`motion_fx.css` と見本の値を中に取り込み、単体で開けるHTMLを1枚作る。
- 出力はGitの外（例：`/_local/fx_gallery/fx_gallery.html`。実装のときに `.gitignore` へ足す）。ローカルでそのまま開いて見る。
- 見せたいとき・スマートフォンで見たいときだけ、Claude が同じHTMLを Artifact（claude.ai の非公開ページ）として公開する。Codex は公開しない。PRの確認のときに、最新の一覧のURLを一緒に渡す。
- 外から読み込むのは Google Fonts（Cinzel、Zen Antique）だけにする。ほかはすべてHTMLの中に取り込む。
- アプリ本体（Flask のルート、`static/dist/`）には何も足さない。
- 版は最新だけを残す（2026-10-29 決定）。ローカルの出力は毎回上書きし、Artifact も同じURLへ公開し直す。昔の版は、そのコミットからスクリプトで作り直すか、Artifact の履歴で見る。

検討した候補：

| 置き場所 | よい点 | 気をつける点 |
|---|---|---|
| Artifact（claude.ai の非公開ページ） | スマートフォンからも見られる。URLを渡せば人に見せられる。アプリを起動しなくてよい | 演出の定義が変わるたびに、組み立て直して公開し直す。外から読み込めるのは決まったCDNとGoogle Fontsだけなので、JS・CSSは中に取り込む |
| ローカルのファイル（Git の外） | 手軽。公開の手間がない | そのPCでしか見られない |
| アプリの開発用の画面（例：`/dev/fx`） | いつも最新の定義で見られる | 本番に出さない仕組みが要る。アプリにコードが増える |
