# 計画62：メインメニュー（ログイン後の最初の画面）

作成日: 2026-11-16
状態: 論点1〜9を決定（2026-11-16）。§7 の PR に分けた。次は PR62-1 の依頼文。見た目と画面の分け方は[アプリ全体のUI計画](../projects/app_foundation/ui/ui_foundation_plan.md)の決定に従う。

## 1. 目的

ログインした直後の画面を、ルーム一覧から「メインメニュー」に変える。遊ぶ・作る・調べる入口を1か所に並べ、ルーム一覧はその中の「セッション」として開く。

- 今のロビーは、ルーム一覧に管理画面やマイキャラクターのボタンが寄り集まっていて、何ができるアプリかが見えにくい。
- ユニット管理とマスターデータは、メインメニューから開く専用の画面にすると決めている（UI計画 §6-1、2026-11-15）。
- 見た目は「紙と金・控えめ」（UI計画 §4）。宝石の色は分類別（UI計画 §6-3：セッション＝サファイア、ダンジョン＝ルビー、マイキャラクター＝トパーズ、使い方＝水晶、ユニット管理＝エメラルド、マスターデータ＝アメジスト）。

## 2. 今の作り（2026-11-16 調査）

- 画面は `static/index.html` の4つの `div` を `static/js/main.js` が表示・非表示で切り替える：ログイン（`entry-portal`）、ルーム一覧（`room-portal`）、ユーザー管理（`user-management-portal`）、ルーム（`main-app-container`）。URL は変わらず、ブラウザーの「戻る」では戻れない。
- ルーム一覧（`renderRoomPortal`）に並ぶもの：
  - 上の帯：ようこそ表示、ユーザー設定、ユーザー管理（アプリ管理者だけ）、ログアウト。
  - ルームの検索・更新・新規作成・戦闘専用ルーム作成と、ルームの一覧。
  - 「マスターデータ」「ユニット管理」のボタン（重ね窓 `cat-workspace` で開く）。
  - 右下に浮いた「マイキャラクター」ボタン（重ね窓）。
- ルームのヘッダーの🏠は「ルーム一覧に戻る」で、入室の役割を解いてルーム一覧へ戻す（`showRoomPortal`）。
- マスターデータとユニット管理は、渡された枠の中に描く作り（`mountCatalogWorkspace` など）なので、重ね窓をやめても中身は使い回せる。
- 使い方ページは `static/help/master_data.html` の1件で、管理画面から開く。ほかに、基本ルールブックとセッション操作ガイドの PDF を `/manuals/rulebook.pdf`・`/manuals/guide.pdf` で配っている（`typst_manual/<冊子>/main.pdf` をそのまま返す。ログイン不要。Discord で案内。F01）。アプリの画面からのリンクは無い。
- ホロウダンジョン（計画35）は「ロビー左下の常設ボタン」を入口にする設計で、保留中（コードは無い）。
- 試作：`node scripts/ui_layout_proto/build.mjs` → `/_local/ui_layout_proto/index.html`。上段にセッション・ダンジョン、中段にマイキャラクター・使い方、下段にデータ管理（ユニット管理・マスターデータ）、右上にアカウント。右下で制作者・GM・一般を切り替えられる。

## 3. 構想

### 3.1 画面の流れ

```
ログイン → メインメニュー ─┬─ セッション（ルーム一覧）→ ルーム
                            ├─ ダンジョン（計画35、保留中は「準備中」）
                            ├─ マイキャラクター
                            ├─ 使い方
                            ├─ ユニット管理
                            ├─ マスターデータ
                            └─ アカウント（右上の名前：ユーザー設定・ユーザー管理・ログアウト）
```

- どの画面からもメインメニューへ戻れる。ルームから出たときは、ルーム一覧へ戻る（§6 論点2）。
- 試作の並び（遊ぶ入口を上、自分の物と読み物を中、データ管理を下、アカウントを右上）を元にする。

### 3.2 メニューの項目

| 項目 | 開くもの | 見える人 |
|---|---|---|
| セッション | 今のルーム一覧（検索・作成・戦闘専用ルーム作成） | 全員 |
| ダンジョン | 計画35 の入口（保留中は「準備中」で押せない） | 全員 |
| マイキャラクター | 今の持ちキャラの画面（F01 Part 9）を全幅の画面にする | 全員 |
| 使い方 | 読み物の一覧（基本ルールブック・セッション操作ガイドの PDF、マスターデータの使い方） | 全員 |
| ユニット管理 | 今のユニット管理（公開資源は全員が閲覧、編集は制作者） | 全員 |
| マスターデータ | 今のマスターデータ（閲覧は全員、編集・承認は権限による） | 全員 |
| アカウント（右上の名前） | ユーザー設定（重ね窓）・ユーザー管理（アプリ管理者だけ、全幅の画面）・ログアウト | 全員 |

## 4. 対象範囲

- メインメニューの画面と、画面の切り替え役（`main.js`）。
- ログイン直後・ルームから出たとき・各画面から戻るときの行き先。
- 使い方の一覧の画面と、右上のアカウントの入口。
- マスターデータ・ユニット管理・マイキャラクター・ユーザー管理を、メニューの下の全幅の画面へ移す（§6 論点3・4・7）。
- ルームに入るまでの画面を紙と金にそろえる（§6 論点8）。

対象外：プレイヤー向けの図鑑（マスターデータベース・プロジェクトの段階3で別に作る）、ルームの URL 化（招待リンク・切断後の復帰。全体が落ち着いてからコードを見て検討する、2026-11-08 ユーザー決定）、ルームと戦闘の画面の夜色化、ダンジョンの中身（計画35）、モバイル版（開発停止中）。

## 6. 論点（決めること）

Claude のおすすめを添える。一問一答で決める。

1. **メニューとルーム一覧の関係**：メニューの「セッション」でルーム一覧を開く（ルーム一覧はメニューの下の画面になる）。
   - **決定（2026-11-16）**：この形（案A）。ルーム一覧の中身（検索・作成・一覧）は今のまま使い、管理画面とマイキャラクターのボタンはルーム一覧から外してメニューへ移す。メニューとルーム一覧を1画面にまとめる案、ルーム一覧を最初の画面に残す案は採らない。
2. **戻る先**：ログイン直後はメインメニュー。ルームの🏠（今は「ルーム一覧に戻る」）の行き先は、ルーム一覧かメインメニューか。
   - **決定（2026-11-16）**：ログイン直後はメインメニュー。ルームの🏠からはルーム一覧へ戻す（説明は「ルーム一覧に戻る」のまま）。ルーム一覧・管理画面などメニューの下の画面には、左上にメインメニューへ戻る操作を置く。再読み込み・再ログインの行き先は論点4で決める。
3. **管理画面の開き方**：マスターデータとユニット管理を、今の重ね窓のままメニューから開くか、メニューの下の全幅の画面にするか。
   - **決定（2026-11-16）**：メニューの下の全幅の画面にする。中身は枠に描く作りを使い回し、重ね窓・背景のクリック・閉じるボタン・フォーカスを戻す処理を外す。メニューへ戻るときは今の未保存の確認を通す。ルームの中から開く入口は作らない（今も入口はルーム一覧だけ。配置は待機列、行動チャートは右クリックで直す）。
4. **URL と「戻る」**：画面ごとに URL の `#`（例：`#menu`、`#sessions`、`#units`）を持ち、ブラウザーの「戻る」で戻れるようにするか。
   - **決定（2026-11-16）**：メニューの下の画面だけ `#` を持つ（`#menu`・`#sessions`・`#characters`・`#help`・`#units`・`#master`・`#users` など）。「戻る」で前の画面へ戻り、未保存の入力があれば今の確認を通す。再読み込みはログインを確かめてから `#` の画面を開く（未保存の入力は消える）。`#` が無いときとログインの直後はメニュー。ルームの中は `#` を付けず、再読み込みでルーム一覧へ戻る今の動きのまま。管理画面の中の資源（例：`#units/U-003`）までは持たない。
5. **ダンジョン**：計画35 が保留中のあいだ、メニューに出すか。
   - **決定（2026-11-16）**：「準備中」として薄く出す（押せない札。色だけでなく「準備中」の文字を添える。試作の並びのまま、上段にセッションと並べる）。計画35 を再開したら押せる入口にする。計画35 の入口の記述（ロビー左下のボタン）は、メニューのダンジョンに直す。
6. **使い方**：何を並べるか（今は管理画面の使い方ページ1件）。
   - **決定（2026-11-16）**：読み物の一覧を出す画面にする。並べるのは、基本ルールブック（`/manuals/rulebook.pdf`）、セッション操作ガイド（`/manuals/guide.pdf`）、マスターデータの使い方（`static/help/master_data.html`）。PDF は今の配布の URL をそのまま開く（新しい仕組みは作らない）。読み物が増えたら一覧に足すだけで済む形にする。
7. **アカウント**：ユーザー設定・ユーザー管理・ログアウトを、右上の1つの入口にまとめるか。
   - **決定（2026-11-16）**：メニューの右上に名前の入口を1つ置き、押すと小さな一覧（ユーザー設定・ユーザー管理〈アプリ管理者だけ〉・ログアウト）を出す。ユーザー設定は今の重ね窓のまま。ユーザー管理は今の `user-management-portal` を置き換え、メニューの下の全幅の画面（`#users`）にする。ログアウトは今の確認を通す。ルームの中の⚙️は今のまま。
8. **見た目の範囲**：メニューだけ紙と金にするか、ルーム一覧・マイキャラクター・ユーザー管理まで当てるか。
   - **決定（2026-11-16）**：メニューの下の画面すべて（メインメニュー・ルーム一覧・マイキャラクター・ユーザー管理）と、ユーザー設定の窓、ログインの画面に当てる。ルームの中は対象外（夜色と金を予定）。共通のトークン `--ui-*` を当てる UI-1 と同じやり方。UI計画 §7 の段階7「ロビー」をこの計画で行う。
9. **権限で変わるもの**：一般の人にもユニット管理・マスターデータを見せるか。
   - **決定（2026-11-16）**：今の権限のまま、メニューの札は全員に同じ並びで出す。中で見える範囲と編集・承認のボタンは今どおり権限で出し分ける（E02）。ユーザー管理だけ、右上の一覧の中にアプリ管理者へ出す。一般の人に「図鑑」の名前で見せる形は採らず、図鑑はマスターデータベース・プロジェクトの段階3で別に作る。

## 7. 段階と PR

各 PR は AGENTS.md の順（資料 → テスト → 最小実装 → 不要コードと資料の確認）。JS・CSS を変えたら `npm run build`。メニューで使う部品は、先にひな形 `ui_template.html` に足す。

1. **PR62-1 画面の切り替えとメインメニュー**
   - `main.js` に画面の切り替え役を1つ置き、メニューの下の画面に `#` を持たせる（論点4）。「戻る」と再読み込みに対応する。
   - ログイン直後の行き先をメインメニューにする。メニューは紙と金で、上段にセッション・ダンジョン（準備中）、中段にマイキャラクター・使い方、下段にユニット管理・マスターデータ、右上に名前の入口（論点5・7）。
   - ルーム一覧をメニューの下の画面にし、管理画面とマイキャラクターのボタンを外す。左上にメインメニューへ戻る操作を置く。ルームの🏠はルーム一覧へ（論点1・2）。
   - 使い方の一覧の画面を作る（論点6）。
   - 管理画面・マイキャラクター・ユーザー管理は、この PR ではメニューから今の開き方（重ね窓・今の画面）で開く。
2. **PR62-2 管理画面を全幅の画面へ**：マスターデータ・ユニット管理・マイキャラクター・ユーザー管理を、メニューの下の全幅の画面にする（論点3・7）。重ね窓の入れ物を外し、メニューへ戻るときに今の未保存の確認を通す。使い方ページの写真を撮り直す。
3. **PR62-3 ルームに入るまでの画面の見た目**：ルーム一覧・マイキャラクター・ユーザー管理・ユーザー設定の窓・ログインの画面を紙と金にそろえる（論点8）。白い面を残さず、文字4.5:1・操作の枠3:1。
4. **PR62-4 資料の統合**：仕様を A〜F 系統（E02 など）へ移し、計画書を消す。計画35 の入口の記述（ロビー左下のボタン）をメニューのダンジョンに直す。UI計画の段階7（ロビー）を完了にする。
