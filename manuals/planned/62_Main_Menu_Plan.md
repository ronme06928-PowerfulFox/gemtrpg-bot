# 計画62：メインメニュー（ログイン後の最初の画面）

作成日: 2026-11-16
状態: たたき台（議論前）。§6 の論点を一問一答で決めてから、PR に分ける（§7 は仮の分け方）。見た目と画面の分け方は[アプリ全体のUI計画](../projects/app_foundation/ui/ui_foundation_plan.md)の決定に従う。

## 1. 目的

ログインした直後の画面を、ルーム一覧から「メインメニュー」に変える。遊ぶ・作る・調べる入口を1か所に並べ、ルーム一覧はその中の「セッション」として開く。

- 今のロビーは、ルーム一覧に管理画面やマイキャラクターのボタンが寄り集まっていて、何ができるアプリかが見えにくい。
- ユニット管理とマスターデータは、メインメニューから開く専用の画面にすると決めている（UI計画 §6-1、2026-11-15）。
- 見た目は「紙と金・控えめ」（UI計画 §4）。宝石の色は分類別（UI計画 §6-3：セッション＝サファイア、ダンジョン＝ルビー、マイキャラクター＝トパーズ、使い方＝水晶、ユニット管理＝エメラルド、マスターデータ＝アメジスト）。

## 2. 今の作り（2026-11-16 調査）

- 画面は `static/index.html` の4つの `div` を `static/js/main.js` が表示・非表示で切り替える：ログイン（`entry-portal`）、ルーム一覧（`room-portal`）、ユーザー管理（`user-management-portal`）、ルーム（`main-app-container`）。URL は変わらず、ブラウザーの「戻る」では戻れない。
- ルーム一覧（`renderRoomPortal`）に並ぶもの：
  - 上の帯：ようこそ表示、ユーザー設定、ユーザー管理（アプリ管理者だけ）、ログアウト。
  - ルームの検索・更新・新規作成・戦闘専用ルーム作成と、ルームの一覧。
  - 「マスターデータ」「ユニット管理」のボタン（重ね窓 `cat-workspace` で開く）。
  - 右下に浮いた「マイキャラクター」ボタン（重ね窓）。
- ルームのヘッダーの🏠は「ルーム一覧に戻る」で、入室の役割を解いてルーム一覧へ戻す（`showRoomPortal`）。
- マスターデータとユニット管理は、渡された枠の中に描く作り（`mountCatalogWorkspace` など）なので、重ね窓をやめても中身は使い回せる。
- 使い方ページは `static/help/master_data.html` の1件だけで、管理画面から開く。
- ホロウダンジョン（計画35）は「ロビー左下の常設ボタン」を入口にする設計で、保留中（コードは無い）。
- 試作：`node scripts/ui_layout_proto/build.mjs` → `/_local/ui_layout_proto/index.html`。上段にセッション・ダンジョン、中段にマイキャラクター・使い方、下段にデータ管理（ユニット管理・マスターデータ）、右上にアカウント。右下で制作者・GM・一般を切り替えられる。

## 3. 構想（たたき台）

### 3.1 画面の流れ

```
ログイン → メインメニュー ─┬─ セッション（ルーム一覧）→ ルーム
                            ├─ ダンジョン（計画35、保留中）
                            ├─ マイキャラクター
                            ├─ 使い方
                            ├─ ユニット管理
                            ├─ マスターデータ
                            └─ アカウント（ユーザー設定・ユーザー管理・ログアウト）
```

- どの画面からもメインメニューへ戻れる。ルームから出たときは、ルーム一覧へ戻る（§6 論点2）。
- 試作の並び（遊ぶ入口を上、自分の物と読み物を中、データ管理を下、アカウントを右上）を元にする。

### 3.2 メニューの項目

| 項目 | 開くもの | 見える人 |
|---|---|---|
| セッション | 今のルーム一覧（検索・作成・戦闘専用ルーム作成） | 全員 |
| ダンジョン | 計画35 の入口 | §6 論点5 |
| マイキャラクター | 今の持ちキャラの画面（F01 Part 9） | 全員 |
| 使い方 | 使い方ページの一覧 | 全員 |
| ユニット管理 | 今のユニット管理（公開資源は全員が閲覧、編集は制作者） | §6 論点9 |
| マスターデータ | 今のマスターデータ（閲覧は全員、編集・承認は権限による） | §6 論点9 |
| アカウント | ユーザー設定・ユーザー管理（アプリ管理者だけ）・ログアウト | 全員 |

## 4. 対象範囲

- メインメニューの画面と、画面の切り替え役（`main.js`）。
- ログイン直後・ルームから出たとき・各画面から戻るときの行き先。
- ルーム一覧・マイキャラクター・ユーザー管理・アカウントの画面を、メニューの下の画面として紙と金にそろえる。
- マスターデータとユニット管理を、重ね窓から専用の画面へ移す（§6 論点3）。

対象外：ルームの URL 化（招待リンク・切断後の復帰。全体が落ち着いてからコードを見て検討する、2026-11-08 ユーザー決定）、ルームと戦闘の画面の夜色化、ダンジョンの中身（計画35）、モバイル版（開発停止中）。

## 5. 関係

- UI計画：§4（見た目の元）、§6-1（専用の画面）、§6-3（宝石の色）、§7.2（試作）。メインメニューで使う部品は、先にひな形 `ui_template.html` に足してから画面に当てる。
- 計画35（ホロウダンジョン）：入口を「ロビー左下のボタン」から「メインメニューのダンジョン」に書き直す。

- F01 Part 9（マイキャラクター）。

## 6. 論点（決めること）

Claude のおすすめを添える。一問一答で決める。

1. **メニューとルーム一覧の関係**：メニューの「セッション」でルーム一覧を開く（ルーム一覧はメニューの下の画面になる）。
   - おすすめ：この形。ルーム一覧の中身（検索・作成・一覧）は今のまま使い、管理画面とマイキャラクターのボタンはルーム一覧から外す。
2. **戻る先**：ログイン直後はメインメニュー。ルームの🏠（今は「ルーム一覧に戻る」）の行き先は、ルーム一覧かメインメニューか。
   - おすすめ：ルームからはルーム一覧へ戻す（別のルームへ移る流れを短くする）。ルーム一覧の上にメニューへ戻る操作を置く。
3. **管理画面の開き方**：マスターデータとユニット管理を、今の重ね窓のままメニューから開くか、メニューの下の全幅の画面にするか。
   - おすすめ：全幅の画面。UI計画 §6-1 で「専用の画面」と決めている。中身は枠に描く作りなので使い回せ、重ね窓の閉じる・背景のクリックの処理が要らなくなる。
4. **URL と「戻る」**：画面ごとに URL の `#`（例：`#menu`、`#sessions`、`#units`）を持ち、ブラウザーの「戻る」で戻れるようにするか。
   - おすすめ：メニュー・ルーム一覧・各管理画面は `#` を持つ。未保存の入力がある画面から「戻る」で離れるときは、今の未保存の確認を通す。ルームは対象外（ルームの URL 化は後で）。再読み込みしたときは、ログインを確かめてから `#` の画面を開く。
5. **ダンジョン**：計画35 が保留中のあいだ、メニューに出すか。
   - おすすめ：出さない。押しても何もできない入口は置かない。計画35 を再開するときに足す。
6. **使い方**：何を並べるか（今は管理画面の使い方ページ1件）。
   - おすすめ：使い方ページの一覧を出す画面にする（今は1件。操作ガイドなどを足せる形）。
7. **アカウント**：ユーザー設定・ユーザー管理・ログアウトを、右上の1つの入口にまとめるか。
   - おすすめ：まとめる。ユーザー管理（今の `user-management-portal`）もメニューの下の画面にする。
8. **見た目の範囲**：メニューだけ紙と金にするか、ルーム一覧・マイキャラクター・ユーザー管理まで当てるか。
   - おすすめ：メニューの下の画面は全部当てる（ルームの中は対象外）。UI計画 §7 の段階7「ロビー」をこの計画で行う。
9. **権限で変わるもの**：一般の人にもユニット管理・マスターデータを見せるか。
   - おすすめ：見せる。公開資源の閲覧は全員ができる（E02）。編集・承認のボタンは今どおり権限で出し分ける。試作の右下で制作者・GM・一般を見比べられる。

## 7. 段階と PR（仮）

論点が決まったら書き直す。

1. **PR62-1 画面の切り替えとメインメニュー**：`main.js` に画面の切り替え役を1つ置き、ログイン後の行き先をメインメニューにする。メニューの項目は今の画面を開く（管理画面は一旦今の重ね窓のまま）。
2. **PR62-2 管理画面を専用の画面へ**：マスターデータ・ユニット管理・ユーザー管理を、メニューの下の全幅の画面にする。使い方ページの写真を撮り直す。
3. **PR62-3 ルーム一覧と周りの画面の見た目**：ルーム一覧・マイキャラクター・アカウントを紙と金にそろえる。
4. **PR62-4 資料の統合**：仕様を A〜F 系統（E02 など）へ移し、計画書を消す。計画35 の入口の記述を直す。
