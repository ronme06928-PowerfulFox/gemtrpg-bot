# 計画64：画像の保存と配信

作成日: 2026-11-14
状態: たたき台（議論前）。§6 の論点を一問一答で決めてから、段階と PR に分ける。

## 1. 目的

キャラクター・背景などの画像を、利用者が URL を意識せずに使え、表示が速く、保存と転送の量が膨らまない形にする。Cloudinary の無料枠が溢れそうになったときに、保存先を移せる作りにしておく。

## 2. 今の作り（2026-11-14 調査）

- **アップロード**：`app.py` の `upload_image` が、受け取った画像を Cloudinary の `gemtrpg/characters`・`gemtrpg/backgrounds` に送る。受け取りの検査は `manager/image_upload_validation.py`（10MB まで、PNG・JPEG・GIF・WebP）。送るときの加工は画質の自動（`quality: auto`）だけで、幅の上限は無い（「width制限を撤廃」のコメント）。
- **登録**：`image_registry` の表（`models.py` の `ImageRegistry`）に、名前・URL・`public_id`・種類・公開範囲・アップロードした人を持つ。削除は表と Cloudinary の両方から消す（`delete_image_api`）。
- **選択**：`static/js/image_picker.js` の `openImagePicker`（ギャラリー・新規アップロード・デフォルト素材）。デフォルト素材は `static/images/` から配る（`get_local_images`）。
- **表示**：配るのは預けた画像そのもので、配るときの加工は無い。ギャラリーも元の画像を `background-image` で並べるので、開くと全部を元の大きさで読む。
- **切り抜き**：切り抜いた画像は `canvas.toDataURL('image/png')` の data URL になり、キャラクターの JSON（`image`、元は `imageOriginal`）にそのまま入る。ルームの状態と通信が重くなる。

## 3. 使う量の見積もり（2026-11-14）

Cloudinary の無料プランは月25クレジット。1クレジットは保存1GB・転送1GB・変換1000回のどれか（[公式](https://cloudinary.com/documentation/billing_and_plans)）。

- 5人で1回遊ぶと、キャラの画像8枚と背景2枚を各人が1回ずつ読み（約22MB）、GM がギャラリーを開くと150枚 × 0.4MB で約60MB。合わせて約0.1クレジット。月8回で転送1クレジット弱、保存は300枚 × 0.5MB で0.15クレジットほど。
- 大きく増えるのは、大きな画像をそのまま預けたとき、ギャラリーの画像が増えたとき、ブラウザーのキャッシュが効かないとき。
- 見積もりは仮の数。Cloudinary の管理画面の使用量と比べて直す。

## 4. 構想（たたき台）

### 4.1 端末で整えてから預ける（根本の方針の案）

アップロードの前に、ブラウザーで画像を縮め（キャラは長い辺1024px、背景は1920px など）、WebP にしてから送る。同時に一覧用の小さな版（サムネイル）も作って預ける。

- 配るときの加工に頼らなくなるので、保存先が Cloudinary でも R2 でも自前のディスクでも同じに動く。
- ファイル名を中身のハッシュにすれば、同じ画像は1つにまとまり、ブラウザーと CDN に長く覚えさせられる。
- 切り抜きも、data URL ではなく、切り抜いた画像を同じ流れで預ける。

### 4.2 すぐ効く直し

- ギャラリーをサムネイルで見せる（Cloudinary なら URL に `w_200` などを足すだけでもよい）。
- アップロードで長い辺に上限を付ける。
- 切り抜いた画像を data URL で持たない。

### 4.3 見張りと片付け

- Cloudinary の使用量を API で取り、アプリ管理者の画面に出す。
- どのキャラ・プリセット・ルーム・背景からも使われていない画像を一覧にし、消せるようにする。

### 4.4 保存先を差し替えられるようにする

保存・削除・URL 作りを1つの部品に集め、保存先を設定で選べるようにする。候補：

| 保存先 | 無料枠 | 加工 | 向き不向き |
|---|---|---|---|
| Cloudinary（今） | 月25クレジット（保存・転送・変換で分け合う） | 配るときに自由に加工 | 今のまま使える。溢れると有料（Plus は月 $89〜99 と資料で食い違う） |
| Cloudflare R2 | 保存10GB、書き込み100万回、読み出し1000万回／月、転送は無料（[公式](https://developers.cloudflare.com/r2/platform/pricing/)） | 無し。Cloudflare の画像変換は無料プランで月5000種類まで（[公式](https://developers.cloudflare.com/images/pricing/)） | 転送が増えても無料。公開には Cloudflare に置いた自分のドメインが要る（`r2.dev` は回数の制限があり本番向けでない） |
| 自前のディスク（VPS・ミニPC） | 機械の容量しだい | 無し（4.1 で不要にする） | 前に Cloudflare の CDN を置けば速い。バックアップは自分で取る |

## 5. 対象範囲

対象とするもの：画像のアップロード・登録・選択・表示・削除、使用量の見張り、保存先の差し替え。

対象としないもの：アプリ本体の置き場（Render からの引っ越し）。考えるときは別に立てる。

## 6. 論点（未決定）

1. **端末で整える（4.1）か**：する場合の上限の大きさと形式（WebP か AVIF か）、サムネイルの大きさ。
2. **今ある画像**：今の Cloudinary の画像を縮め直すか、そのまま残すか（後方互換は持たない方針だが、画像は利用者の物）。
3. **保存先**：Cloudinary のまま見張るか、R2 へ移すか、移す時期の目安（使用量が何割を超えたら、など）。
4. **切り抜き**：切り抜いた画像を預ける形にするか、元の画像＋切り抜きの範囲を持つ形にするか。
5. **片付け**：使われていない画像を自動で消すか、一覧にしてアプリ管理者が消すか。
