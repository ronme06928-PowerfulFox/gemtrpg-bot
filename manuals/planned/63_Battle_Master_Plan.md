# 計画63：戦闘マスター（戦闘に関わる機能をまとめた画面）

作成日: 2026-11-12
状態: たたき台（議論前）。着手は計画60の残り（PR60-21 威力の見込みなど）の後。§6 の論点を一問一答で決めてから、段階と PR に分ける。[マスターデータベース・プロジェクト](../projects/master_database/README.md)に関わる。

## 1. 目的

戦闘に関わる「試す・調べる・使う」機能を、マスターデータの管理画面とは別の画面にまとめる（仮の名前「戦闘マスター」）。

- **マスターデータ（計画60）**：スキル・バフ・用語などを作り、承認して公開する場所。スキルの画面には、そのスキルの素の性能（威力の最小・平均・最大と、条件で変わる威力の一覧）までを出す（計画60 §5.18、PR60-21）。
- **戦闘マスター（この計画）**：スキル同士をかち合わせて勝率を見る、本物の処理で1回ぶつける、敵と行動パターンを扱う、その結果をルームのバトルでも使う。

マスターデータの画面がこれ以上膨らまないように、ここで分ける（2026-11-12 ユーザーの構想）。

## 2. 柱（たたき台）

### 2.1 スキルのかち合わせと勝率

2つのスキル（と、それぞれの使う人の値）を選び、マッチで勝つ・引き分け・負ける確率と、威力の出方を見せる。

- 威力は「固定値＋ダイス」なので、ダイスを何千回も振らなくても、両者の威力の分布を組み合わせれば勝つ確率がそのまま出る。使う人と相手の値（補正・状態）を入れれば、戦闘と同じ `calculate_skill_preview` が条件込みの式を出す（PR60-21 で作る見込みの API と同じ部品）。
- 分布で表せない処理（威力の後で決まる効果、乱数を使う特殊な処理など）がどこまであるかは、実装の前に洗い出す。

### 2.2 ルームのバトルでの有利・不利の表示

2.1 の計算を、実際のルームのバトルで使う。例：宣言パネルで、相手が宣言したスキルに対して、自分の候補のスキルごとに勝率か「有利・不利」を出す。

- 計算は軽い（分布の組み合わせ）ので、宣言のたびに出しても負荷は小さい見込み。

### 2.3 本物の処理で1回ぶつける（旧 計画60 Phase 4b）

下書きや公開中のスキル1つと、相手のキャラ・スキルを選び、本物の処理で1回の対決を解決した結果（ダイス・威力・勝敗・付いた状態・ログ）を見せる。計画60 §3.3 から移した。

- `manager/sim/`（計画30、F03）は動かす間アプリ全体の部品を差し替えるため、本番のプロセスの中では動かさない。**別のプロセス**で動かし、そのプロセスの辞書にだけ下書きを重ねる。Render のメモリが足りるかは、実装の前に測る。
- 短い戦闘を何回も回す集計は、今の CLI（F03）をローカルで使う（計画60 論点5の決定を引き継ぐ）。

### 2.4 敵と行動パターン（計画61との関係）

計画61（敵キャラと行動パターンの管理）の画面を、戦闘マスターの中に置くか、マスターデータ側に置くかを決める（§6 論点4）。敵を相手にした 2.1・2.3（「この敵のこのパターンに対して」）は、置き場にかかわらずここから使えるようにしたい。

## 3. 使える部品

- `calculate_skill_preview`（`manager/game_logic.py`）：使う人・相手の値から、条件込みのダイスの式と幅を出す。
- PR60-21 の威力の見込みの API（計画60 §5.18）：素の性能の計算。2.1 の土台になる。
- `manager/battle/duel_solver.py`・`resolve_match_runtime.py`：マッチの解決。勝敗の決まり（同値のとき・守備・回避・一方攻撃）はここに合わせる。
- `manager/sim/` と CLI（F03）：本物の処理を回す。
- 計画61 の敵・行動パターンのデータ（作れば）。

## 4. 画面の置き場

ロビーの前のメニュー（計画62の候補、メインメニュー構想）ができれば、そこに「マスターデータ」と並べる。それまではロビーのボタンから開く。マスターデータと同じく、渡された枠の中に描く作りにして、置き場を変えても作り直さずに済むようにする。

## 5. 段階（たたき台）

1. かち合わせと勝率（2.1）の画面。計算の正しさを、CLI（F03）で回した結果と比べて確かめる。
2. ルームでの有利・不利の表示（2.2）。
3. 1回ぶつける（2.3）。メモリを測ってから。
4. 敵と行動パターン（2.4、計画61と合わせて）。

## 6. 論点（未決定）

1. **画面の名前**：「戦闘マスター」でよいか。
2. **勝率の範囲**：攻撃同士のマッチだけか、守備・回避・一方攻撃も含めるか。引き分けの扱い。威力の後で決まる効果（与えるダメージ・状態）まで見るか。
3. **ルームでの見せ方**：数字（勝率%）か段階（有利・五分・不利）か。誰に見せるか（プレイヤーにも見せるか、GM だけか）。相手の値が分からない場面（敵の補正など）をどう扱うか。遊びの緊張感を削らないか。
4. **計画61との関係**：敵・行動パターンの画面を戦闘マスターに置くか、マスターデータ側に置くか。計画61を戦闘マスターの段階に組み込むか、別の計画のままつなぐか。
5. **使える人**：誰でも使えるか、制作者・GM だけか。
6. **計算の置き場**：サーバーか、端末（ブラウザー）か。2.2 は宣言のたびに出すので、軽さと戦闘とのずれのなさの両方を見て決める。
