## 1. 目的

セッションや戦闘で何度も目にする場面（ダイスの結果、マッチの決着、ダメージ、ラウンド開始など）に、0.2〜0.8秒程度の小さなアニメーションを入れる。動画を貼らずに、遊んでいて楽しい手触りを足す。

## 4. 作り方（案）

### 4.1 演出は1か所から呼ぶ

`window.Fx` を1つ作り、ゲーム側からは `Fx.play('clash-win', {anchor, ...})` のように演出の名前と表示位置だけを渡す。どの演出で何を描くかは、`Fx` の中の対応表で決める。素材の作り方を後から変えても、ゲーム側のコードは直さない。

### 4.2 演出は「始まってからの秒数」から描く

Egatariの部品の決まりに倣い、各演出を次の形にする。

```js
Fx.define('clash-win', {
  duration: 0.6,                 // 秒
  mount(root, params) { /* 自分の要素を root の中に作る。大きさを測るならここだけ */ },
  render(t) { /* 開始 t 秒後の見た目を描く。t = 0 は始まる前、t = Infinity は最後の見た目 */ },
});
```

- `Fx.play` は再生のたびに定義から1つ分の実体（`Object.create(定義)`）を作り、`mount` で作った要素は `this` に持たせる。同じ演出を同時にいくつ出しても互いに干渉しない。
- `mount` が受け取る `params` には、呼ぶ側の値に演出の段階 `level`（§7）を足したものが入る。

- 同じ t なら必ず同じ見た目にする。t は戻ったり飛んだりして、どの順番で来てもよい。`render` の中に「もう終わった」のような状態を持たず、前回の描画結果に頼らない。
- `render(0)` は始まる前の見た目、`render(Infinity)` は最後の見た目として、どちらも必ず描けるようにする。
- 進み具合は `Fx.prog(t, 開始, 長さ)`、補間は `Fx.lerp(a, b, e)` で求める。式はEgatariの `DECK.prog`・`DECK.lerp`・`DECK.ease` と同じにする（ゆっくり始まりゆっくり止まる2次の曲線。t = Infinity なら1）。演出のコードを動画へそのまま持ち込め、動きの曲線も一致する。
- 動きはすべて `render` の中でインラインのスタイルとして計算する。CSSの `@keyframes`・`transition`・Web Animations API、独自の `setTimeout`、`Math.random` は演出の定義の中で使わない。ブラウザが自分の時計で動かす動きは、動画の側で時刻を指定して描けないため。揺れの向きやダイスの面の変化も、t と受け取った値から決める。
- 演出の段階（§7）は `params.level` として受け取る。演出の定義の中で `localStorage` や設定を読まない。
- 時計は `Fx` の中の `requestAnimationFrame` 1本だけにする。タブを裏に回して戻ったときは、経過秒数から描くので見た目がずれない。
- 飛ばすときや演出を切ったときは `render(Infinity)` を描いてすぐ片付ける。
- t を指定して描けるので、テストはタイマーを待たずに書ける（§8）。

### 4.3 素材の種類は段階的に増やす

1. DOMとインラインのスタイル（第1段）。揺れ、光、数字の切替など。CSSは色や形など止まった見た目だけに使う（§4.2）。既存の立ち絵・状態アイコン以外の外部画像は使わない。
2. 手描きの連番画像（スプライトシート、第2段）。決め所だけに使う。画像はCloudinaryに置き、`render(t)` でコマを選ぶ。
3. Rive（任意の第3段）。キャラの立ち絵を状態ごとに反応させたくなったときだけ検討する。

外部ライブラリは第3段まで入れない。

### 4.4 説明動画の部品と共有できる形にする

- 演出を足すときは計画56の `scripts/fx_gallery/samples.mjs` にも見本を足す（定義との一致をテストで確かめる）。

説明動画（計画54）は作らないが、そこで同じ演出を使えるように、各演出の定義を次の形で書く。動画の部品も同じく時刻から描くため（`typst_manual/動画/common/components/`）、`render(t)` をそのまま包めば動画に載せられる。

- `Fx.define` の `mount` と `render` は、受け取った値と描く場所（`root`）だけで完結させる。`EventBus`・`window` 上のアプリの状態・ほかのモジュールに頼らない。呼ぶ場所との接続は `Fx.play` の側に置く。
- 表示する要素は、演出が `mount` で `root` の中に自分で作る。駒など演出の外にあるものは参照しない。どこに出すかは、アプリ側が `root` の置き場所で決める。動画で包むときは、空の要素とJSONの値を渡すだけで済む。
- 色は `--fx-damage`・`--fx-heal`・`--fx-win`・`--fx-gem` などFx専用のCSS変数で決め、既定値はアプリのCSSに置く。動画の側では、これを自分のテーマ変数（`--emph` など）に割り当てる。Egatariの変数名はアプリへ持ち込まない。
- 大きさは `--fx-scale` とem単位など、外から変えられる値で決める。動画は文字の下限のため全体を約1.7倍に拡大する。位置や大きさを測るのは `mount` だけにし、`render` の中では測らない（アプリで毎フレーム測ると描画が重くなるため）。
- 読ませる数字や文字には `data-readable` を付ける。アプリでは何も起きないが、動画の品質検査（文字の大きさの下限）の対象にできる。
- 長さはアプリに合わせて決める（§5）。動画では、包む側が `render(t / 倍率)` として時間を引き伸ばす。Fx側には動画用の値を足さない。
- ファイルは次の3つに分ける。動画は上の2つを写して使う。どれも `scripts/build_frontend.mjs` の `CLASSIC_SCRIPTS` に依存順で追加する。

| ファイル | 中身 | アプリへの依存 |
|---|---|---|
| `static/js/fx/fx_core.js` | `Fx.define`、`Fx.prog`・`Fx.lerp`・`Fx.ease`、定義の対応表 | なし |
| `static/js/fx/fx_effects.js` | 各演出の定義 | なし |
| `static/js/fx/fx_player.js` | `Fx.play`、時計、同時に出す数の上限、3段階の設定と `localStorage`、切り替えメニュー | あり（アプリ専用） |

- 画像の素材（ダイスの絵、第2段の連番画像など）は、Cloudinary の URL のほかに手元のファイルからも読めるようにする。動画は作業フォルダの外やネットの素材を埋め込めない。
- 動画へ持ち込む作業（部品として包む、写しを置く）は計画54の側で行う。この計画では、上の形を守るところまでを扱う。動画の今の部品（`m-impact-hp` など）をFx版へ置き換えるかも、計画54の再開後に決める。

## 5. 守る決まり（案）

- **ゲームの進行を止めない。** 演出は今の表示の上に重ねて流すだけにする。ラウンドバナーの1.8秒や解決パネルの段階の長さなど、進行の時間は延ばさない。演出の終わりを待って次へ進む作りにしない。ただしラウンドバナーだけは、今と同じく終わったときに `battle:round:banner:finished` を出し、盤面の更新の保留（`BoardPresentationCoordinator`）を解く。
- **終わりは描画の時計で決めない。** 演出の終わり（片付けと完了の知らせ）は `setTimeout` で長さどおりに決める。`requestAnimationFrame` はタブが裏にある間止まるため、描画にだけ使う。裏にある間に終わった演出は、描かずに片付ける。
- **再接続や状態の同期では再生しない。** その場で起きたことにだけ出す（終結の結果表示と同じ扱い。E02 Part 13）。
- **短くする。** 単発の光などは0.2〜0.8秒。PR4.5aの威力確定は1.4秒、数字・効果・KOは勝敗2.6秒＋待ち2秒に収める。PR3の属性別攻撃は1.4秒で、攻撃段階内で終わる。通常は宝石の加護・戦闘の終結以外で、演出のために進行の時間を追加しない。PR4.5aでは、PR4.5cの記録による延長と、最小拍でも入らない行を省かず続ける場合には、自動進行待ちを帯の終了まで延ばす（§6.5）。
- **同時に出す数を絞る。** 範囲攻撃などで一斉に出るときは上限（12個）を設け、超えた分は「軽め」（§7）の出し方にする。情報は欠かさない。
- **効果音と同じ瞬間に出す。** 効果音（`SoundFx`）を鳴らしている箇所には、演出も同じ箇所から出す。演出に合わせた新しい効果音は計画55で扱う（2026-10-29）。

### 6.1 解決パネルの背景の立ち絵

- カードの中の左右半分に、攻撃側・防御側の立ち絵を大きく薄く敷く。中央へ向かって薄く消し、中央の威力や勝敗の文字を読みやすく保つ。
- PR2の確認値は不透明度15%。勝敗の段階で、勝った側に光を、負けた側に暗い影を約10%重ねる。光と影は Fx の演出で、背景そのものは動かさない（§4.4の「自分の要素だけを動かす」決まりのため）。
- 今の小さな顔の絵（左右の情報枠の68〜92px）は消す。左右のキャラ名ははっきり残す。広域合算で防御側の参加者を並べる小さな丸アイコンは、参加者一覧として残す。
- 防御側を複数人まとめて表示する場面（広域合算）では、右側に背景を出さず、左（攻撃側）だけにする。対象を1人ずつ表示する場面では、広域攻撃でも左右両方に出す。
- 画像のないキャラは、その側だけ背景を出さない。
- 画像は今の顔の絵と同じ取得の仕組み（駒の画像）を使う。

### 6.2 解決パネルに演出を置くときの注意

PR2の実装仕様（2026-10-28）：

- 段階は `names`（名前・スキル同時、600ms）→ `power`（1400ms）→ `attack`（1400ms）→ `outcome`（2600ms）。配分は `RESOLVE_STAGE_TIMING` に集約する。各段階への移行は1回だけ通知し、同じ段階の再描画では通知しない。同期で途中から表示した場合は過ぎた段階の演出を再生しない。
- PR2時点ではマッチだけに `power-roll`、`clash-flash`、`clash-shade`、`attack-flash`、`resolve-damage` を追加した。PR3で以下の種類にも拡張した。演出の終了を待たずに進行し、切替・終了・破棄で `Fx.finishAll(host)` を呼ぶ。完了通知は1回だけ。
- ダメージの記録を確認したところ、`applied.damage` はHP差分（`source: ダメージ` 等）で、マッチの主対象は現行どおり勝者の威力を上限に本体と効果へ配分する。種類が残る行では `rupture` / `fissure` / `bleed` / `bleed_flood` / `thorns` および日本語の破裂・亀裂・出血・荊棘をアイコンに対応させる。`on_hit` / `on_damage` / `custom_damage` / `timing_effect` 等はアイコンを推測しない。主対象の効果の内訳は効果合計の範囲内で配分し、残りはアイコンなしとする。サーバーが種類を記録していない行をログ文から推測しない。
- 数字は本体を対象ごとに1つ、追加は記録の行ごとに別々に表示する（未知のsourceもアイコンなしで行ごとに表示）。汎用HP差分より種類の残っている行を先に効果合計へ配分する。本体は即時、合算防御側は対象ごとに0.15秒ずらし、追加は対応する効果名の拍＋0.1秒に出す。拍と標準枠4.6秒の扱いは§6.5に従う。色は対象の敵・味方に従って金・赤、追加は緑。マイナスはフォント依存を避けた太い横線とする。
- チャットは `new_log` の入口で生きたログだけを記録し、描画直後に消費する。過去ログ・再描画・シークレットの非公開部分には再生しない。ダイス判定は `SoundFx.isDiceLog` を共有する。合計はHTMLを除いた表示文の最後の `=` / `->` / `→` に続く数値から取得し、取得できない行は演出しない。

- 解決パネルは、マッチが変わるたびにカードの中身（`panelContent.innerHTML`）を作り直す。演出はカードの中身ではなく、パネルの外枠の側に置き、名前や「VS」などの位置はそのつど測って置く（`Fx.play` の `left` / `top`）。
- 段階の切り替えを知らせるイベント `battle:resolve:flow:stage`（`{ stepKey, stage, kind, outcome }`）を EventBus へ通知し、演出はこれを受けて出す。パネルのクラス `reveal-<段階>` も切り替える。
- 「次のマッチへ」や自動で早く次へ進んだときに前のマッチの演出が残らないよう、`Fx.finishAll(host)` で置き場所ごとにまとめて終わらせる。

PR3の実装仕様（2026-10-28）：

- `attack-slash` / `attack-strike` / `attack-pierce` は1.4秒。攻撃開始から0.8秒で着弾し、攻撃段階内で終わる（形と着弾時刻はPR4.5bまで維持）。paramsは `level`、`tier`（small / medium / large）、`direction`（1 / -1）、`tone`（enemy / ally / neutral）、`width` / `height`、`mode`（hit / draw / wide）。属性対応と `ATTACK_TIERS`（8 / 15）は接続モジュールの各1か所に置く。

- PR4で `hp_after` と `self_destructed` の記録を追加した。ダメージ行の `hp_after` でKOと判定した対象への攻撃だけをlargeにする。自滅だけではtierを補正しない。現在のstateのHPからは推測しない。ダメージ0はsmallで、数字なし。
- チャットのダイス完了時は `fx-chat-dice-slot` を除き、合計値を子要素なしの数字のテキストへ戻す。履歴と同じDOM・CSSにする。

### 6.3 攻撃の動きの段階（PR3）

- ダメージ量そのもので3段階に分ける。8未満は小、8〜14は中、15以上は大。PR4では適用後HPの記録でダメージによるKO対象を特定し、その対象への攻撃を必ず大にする。自滅は大への補正に使わない。しきい値は1か所にまとめ、実際の戦闘を見て直す。
- 段階の判断は味方・敵で同じにし、色だけ変える（味方が受けた一撃は赤系の警告色、敵に入った一撃は金色の光）。
- 段階で変えるのは、線の太さ・光・揺れの強さ。長さは変えない（§7の段階の設定と同じ考え方）。
- マッチでは、勝った側のスキルの属性で動きを決め、攻撃の段階（0.8秒）で勝った側から負けた側へ届かせる。引き分けでは、両者の動きを中央で小さく出して打ち消し合わせる（両側の光・影は付けない、という引き分けの決定は変えない）。
- 属性ごとの動き（攻撃の段階 → 勝敗の段階の始めの着弾）。描く場所は受けた側の背景の上、向きは攻撃した側から受けた側へ。画像は使わずSVGと要素で描く。

| 属性 | 攻撃の段階 | 着弾 |
|---|---|---|
| 斬撃 | 斜めの弧を描く光の筋が横切る | 筋の通った跡が一瞬光って消える |
| 打撃 | 縦長の光の塊が上から落ちる（はじめゆっくり、地面に近いほど速い。攻撃した側から10°ほど斜め、短い光の尾）。「地面」は背景の下から4分の1あたりの見えない横線 | 白い閃光、地面を這って左右へ走る横向きの光の筋2本（先ほど細く薄い）、上下につぶした楕円の輪、跳ねて落ちる破片（位置は番号から決める） |
| 貫通 | 細い光線が攻撃した側からまっすぐ伸びる | 刺さった点で十字の閃光 |
| 属性なし | PR2の `attack-flash` のまま | なし |

- 打撃の3段階：小は衝撃波が背景の半分まで・破片なし・筋は細い。中は端まで・破片4個・筋が太く光が広がる。大は端まで届き、0.1秒遅れて2つ目の波・破片8個・着弾の閃光が大きい。斬撃・貫通も、線の太さ・光の広がり・閃光の大きさで同じ考え方で段階を付ける。
- 着弾の揺れは、その一撃の光・衝撃波・ダメージの数字をまとめたFxの層だけを数ピクセル揺らす。解決パネルのカードや画面は揺らさない。軽めは揺れなし、通常は大の一撃だけ小さく、派手は中・大で強めに揺らし、大ではカード全体を覆う薄い白の閃光（Fxの要素）を一瞬重ねる。
- 一方攻撃と、回避で止められなかった強硬攻撃（`_isOneSidedPresentation`）：威力のダイスは攻撃した側だけ。攻撃した側の属性で受けた側へ動きを届け、受けた側に着弾・影・ダメージの数字を出す。中央のぶつかり合う光と、攻撃した側の光は出さない。回避で止められた強硬攻撃はマッチと同じに扱う。不発には新しい演出を付けず、今の「不発」の文字表示のままにする。
- 広域-個別は、1件ずつマッチまたは一方攻撃の決まりのまま出す。
- 広域-合算（攻撃側の威力と防御側の威力の合計を比べ、差の分が、攻撃側の勝ちなら防御側の全員に同じだけ、防御側の勝ちなら攻撃側に入る）：
  - 攻撃側の勝ち：攻撃側の属性の動きを、右側の参加者一覧の全体へ向けて1回、横長に大きく出す。右側に影、被弾した相手ごとのアイコンに数字を0.15秒ずつずらして出す。
  - 防御側の勝ち：右から左へ、属性を持たない「返しの一撃」の光を出す。左側に影とダメージの数字。代表の参加者のスキルの属性は使わない。
  - 引き分け：中央で小さく向かい合わせに出す。攻撃側はスキルの属性、防御側は属性なしの `attack-flash` とし、代表の参加者のスキル属性は使わない。
  - 動きの段階は、1人あたりの差の分のダメージで決める。
- ダメージが0の一撃（勝ったが0だった、一方攻撃が0だった）は、動きを「小」で出し、数字は出さない。0になった理由はPR4の「発動した効果」の名前で示す。
- 軽めでは動かさず、着弾の後の見た目（打撃なら地面の光の筋）をフェードで出して消す。引き分けは中央で小さく出す（打撃なら中央に叩きつけ、短い衝撃波を左右へ）。

### 6.4 発動した効果の記録（PR4）

PR4の実装仕様（2026-10-29）：

- 同時数の上限12個には、`start <= performance.now()` の演出だけを数える。遅延中の予約は含めず、`Fx.play` で決めた段階は途中で変更しない。
- 合算の守る側の数字とKOは、その対象のキャラID付き丸アイコンへ配置する。見つからないときだけ参加者一覧全体へ出す。効果名は対象名付きで守る側の下の帯へまとめる（PR4.5a）。本体数字はdamageEventsの各被弾者に記録された量を使い、全員のアイコンへ0.15秒ずつずらす。
- `collectDamageKnockouts` は `hp_after` によるKOだけを取り出し、攻撃tierのlarge補正に使う。`collectKnockouts` はこれに自滅を加え、`ko-shatter` の表示に使う。サーバーの記録と判定は変更しない。

- `process_skill_effects` は戻り値を変えず、contextに明示された `fired_effects` リストだけへ追記する。CUSTOM_EFFECT・型別ハンドラ・蓄力-誘爆の直接呼び出しで、その効果の変更前の値と返された変更列から `{name, delta}` を作る。HPは除外し、名前のない用語・未登録効果・不発の効果は記録しない。
- 解決段のローカルなリストを単体・強硬・マッチの委任先 `duel_solver`・広域個別・広域合算のタイミング処理へ渡し、`applied.fired_effects` へ入れる。広域合算は既存の `statuses` / `damage_events` と同じ階層にも効果一覧を載せ、表示側で正規化する。威力ロールの既存APIは保ち、合算の `BEFORE_POWER_ROLL` の記録先だけをネスト可能なContextVarのスコープで渡す。判定・変更の適用順は変えない。
- `statuses` はMP差分、ダメージ行はその行の生成時点の `hp_after` を持つ。自滅の条件を共通化し、処理前に `self_destructed` を確定して送信する。自滅処理の実行位置は保つ。
- 勝敗2.6秒＋待ち2秒を標準枠4.6秒として、0秒の本体数字→0.1秒から側ごと1つのeffect-band（効果名・結果をまとまり単位の連続した流れ（§6.6項目5））→対象の山場・最終行の拍に合わせたKOへ進める。過密でも0秒へ圧縮せず全行を続ける。詳細は§6.5。早送りは遅延中もhost単位で片付ける。
- `effect-band` は効果名と結果行を時刻から順に表示する。HPを除外し、自分への効果は `--fx-self` の紫。新規の混乱はW-07の結果末尾へまとめ、W-07がなければ単独表示する。`ko-shatter` は結晶・ひび・破片・影・文字、合算防御側はキャラID付き参加者アイコン上のchip表示。軽めは位置・形を動かさずフェードだけ。
- 広域合算は威力合計に参加していない敵にもダメージを適用する。KOの置き場所を欠かさないよう、記録にある被弾対象で威力参加者以外のキャラも一覧へ加え、「対象」と表示する（防御威力を加えたとは表示しない）。
- 記録の対象外：`RESOLVE_STEP_END` はtrace送信後に実行されるため、その段の表示用一覧へは収録しない。`RESOLVE_START` と宣言中の即時効果は解決段の外。旧広域モーダルの `wide_solver.execute_wide_match` は任意の `fired_effects` リストへ記録できるが、解決traceを作らない経路なので解決パネルへは送らない。これらの処理順や進行を変えて記録をさかのぼらせることはしない。

解決の記録（trace）の各段に、次の3つを足す。記録を増やすだけで、判定は変えない。

- **「発動した効果」の一覧**：1件ごとに `term_id`（用語図鑑のID）、`name`（画面に出す効果名）、`actor_id`（発動したキャラ）、`target_id`（受けたキャラ）、`results`（その効果で起きた変化。`{種類, 量}` の並び。例：戦慄 −5、MP −5）。並びは発動した順。記録する場所は、効果の処理が集まる `manager/game_logic.py` の `process_skill_effects` の1か所にする。
- **効果と用語図鑑のIDの対応**：新しいファイル `manager/battle/effect_glossary_map.py` に、内部のキーとIDの対応を置く（下の表）。`name` は用語図鑑のそのIDの名称から引く。対応表にない効果は記録しない。

| ID | 効果 | 戦闘の処理での呼ばれ方 |
|---|---|---|
| W-01 | 出血氾濫 | CUSTOM_EFFECT `出血氾濫` |
| W-03 | 破裂爆発 | CUSTOM_EFFECT `破裂爆発`。蓄力-誘爆から続けて起きる破裂爆発（`game_logic.py` の直接呼び出し）も含む |
| W-05 | 亀裂崩壊 | CUSTOM_EFFECT `亀裂崩壊_DAMAGE`・`FISSURE_COLLAPSE` |
| W-07 | 戦慄殺到 | CUSTOM_EFFECT `戦慄殺到` |
| W-09 | 荊棘飛散 | CUSTOM_EFFECT `荊棘飛散` |
| W-79 | 血漿転化 | `CONVERT_STACK_RESOURCE_VARIANT` で凝魔を変換したとき |
| W-81 | 爆破誘導 | `CONVERT_STACK_RESOURCE_VARIANT` で蓄力を変換したとき |
| W-58 | 再使用 | スキルの再使用が決まったとき（`action_effects.py`） |

- 載せないもの：自滅（W-59。戦闘不能の演出で見せる）、召喚（W-61。盤面に出たことで分かる）、伝授（W-60）・震盪（W-64。発動の瞬間がない）。用語図鑑に用語のない効果（追加攻撃 `APPLY_SKILL_DAMAGE_AGAIN`、最大HPの割合ダメージ、ラウンドの即時終了）は、用語図鑑に足すまで出さない。
- **混乱の付与だけは状態の変化でも出す**：混乱（W-10）が新しく付いたとき（`applied.statuses` で混乱が0から1以上になったとき）、受けた側に「混乱」の一言を出す。戦慄殺到のMP切れで付いたときは、戦慄殺到の結果の後に続ける。
- **ポップアップにするもの**：対応表に載せた名前の付いた効果と、§6.6項目5に定めた状態の付与。FPやMPの差分は付与のまとまりに含めない。効果名（Zen Antique）を出してから、結果（戦慄 −5、MP −5 など）を同じ下の帯に1行ずつ出し、前の行を上へ送る。出すのは効果を受けた側で、自分にかかる効果は自分の側に紫で出す。HPの減りはPR2のダメージの数字（アイコン付き）を効果名の後に続けて出し、結果の文字には重ねて出さない。
- **状態の変化の記録にMPを足す**：`applied.statuses` を作る差分（`resolve_effect_runtime.py` の `_diff_snapshot`）の比べる対象にMPを入れる。処理の前後のMPはすでに取ってある。
- **ダメージの記録に一撃の後のHPを足す**：`applied.damage` の各行に `hp_after`。戦闘不能（前が1以上、後が0）の判定と、§6.3の「HPが0になる一撃は必ず大」に使う。

- **戦闘不能**：
  - 判定：ダメージの記録で、前のHPが1以上、`hp_after` が0になった行（ダイスでも効果でも同じ）。自滅は解決の記録の後でHPを0にしているため、記録に自滅したキャラの一覧 `self_destructed` を足す（処理の順番と判定は変えず、記録の中身に追記する）。
  - 出す時：対象の山場以後・最後の帯行や追加数字の拍＋0.4秒。自滅は相手の山場以後、枠末尾で制限する（§6.5）。
  - 見た目：ガラス・宝石のような結晶質のものが砕ける。受けた側の背景の上に、透きとおった結晶の面が現れ、ひびが走り、破片が光りながら飛び散って落ちる。その後に暗い影が重なり、「戦闘不能」の文字（Zen Antique）を出す。破片の形と飛ぶ向きは番号から決める。背景そのものは動かさず、Fxの層だけで描く。
  - 攻撃の動き：HPが0になる一撃は必ず大にする（§6.3でPR3から保留していた分）。
  - 広域-合算：防御側の参加者が戦闘不能になったら、その人の小さな丸アイコンの上で、小さな結晶が砕けて×印を出す。
  - 軽め：ひびと破片の動きをなくし、ひびの入った結晶・影・文字をフェードで出して消す。

**調べたこと（2026-10-29）**

- タメとツメ（[Shade3D「攻撃の動きとタメとツメ」](https://shade3d.jp/store/marketplace/articles/startanimation/vol7.html)）：振りかぶりで止めて見せる「タメ」と、振り下ろしで一気に加速する「ツメ」で、動きにメリハリを出す。記事の例は30fpsで、溜め7コマ（約0.23秒）、振り出し11コマ（約0.37秒）、斬り抜け5コマ（約0.17秒）。日本のアニメはこれを強く誇張する。
- ヒット演出（[トイロジック「ヒット演出」代表10選](https://blog.toylogic.co.jp/planner/4111.html)、ニーア・FF16の実例）：
  - ヒットエフェクトで、斬撃・刺突・殴打の違いと強弱を表す。斬撃の向きは、力の加わる向きに合わせる。
  - ヒットストップ：命中の瞬間に止めるかスローにする。全体を止め、ヒットエフェクトだけ等倍で流すと際立つ。「何が起きたか」を目に残す役にも立つ。
  - 揺れや画面効果は、頻繁に使うと画面がガチャつくので、要所に絞る。
- アニメ調のゲームの斬撃（[原神のVFXの解説](https://www.vfxapprentice.com/blog/genshin-impact-stylized-vfx-breakdown)）：
  - 斬撃は、前の縁が鋭く、後ろへ尾が伸びる三日月形。尾を後ろへ引き伸ばして、残像（モーションブラー）の代わりにする。均一に広がる円や線では速さが出ない。
  - 命中の瞬間に1〜2コマだけ白（または反転）の閃光を入れる「インパクトフレーム」。
  - 縁のはっきりした形と、はっきりした色で、乱戦でも読める。
- 止めと揺れ（[桜井政博さんのヒットストップの動画の紹介記事](https://www.gamesradar.com/smash-bros-masahiro-sakurai-has-started-a-fascinating-youtube-game-design-series)、「Juice it or lose it」「The Art of Screenshake」の紹介記事）：止めの長さで重さが変わる。目安は重い一撃で0.05〜0.1秒程度（出どころにより幅がある）。揺れは短く小さく、すぐ収める。
- ダメージの数字（[Siv3D「ダメージ演出」](https://siv3d.github.io/ja-jp/course/damage-number/)、ゲーム開発者の記事）：対象の上に置き、体の中に重ねない。同時に出るものは少しずらす。縁取りで背景から浮かせる。同じ情報はいつも同じ場所に出す。
- ダイスの出し方（スロットやメーターの部品の解説）：結果は先に決まっていて、動きはそれを見せるだけ。速く切り替えてから終わりにかけて遅くし、最後の数字で止める。最低限の長さを取らないと「一瞬光っただけ」に見える。
- 戦闘の速さ（RPGの戦闘速度の設定の例）：ふつうの行動は短く、決め技にだけ長い演出を使う。速さの切り替え（1倍・1.5倍・2倍など）を持つゲームが多い。

**論点（一問一答で決める）**

1. ~~1回の解決の長さ~~ → **決定済み**：6秒（名前0.6・威力1.4・攻撃1.4・勝敗2.6）。威力は数字の切り替え1.0秒＋決まった数字を見せる0.4秒。攻撃は溜め約0.3・振り約0.2・止め約0.08・余韻約0.8秒。勝敗の段階は、次へ進むまでの待ち2秒と合わせて4.6秒使える。速さの切り替えは後回し。
2. ~~文字の置き場所~~ → **決定済み**：置き場所を分ける。数字は受けた側の立ち絵の上の方に、いつも同じ位置（土台）で出す。同じ対象に続けて出る数字は、新しい数字が土台に出るたびに、前の数字をその行の高さ（本体52px・追加36px）だけ押し上げて縦に積む（2026-10-29 改め。当初の「少しずつ上と外側へずらす」は、先の数字が浮いて後の数字に追いつき重なったため）。土台は上から40%（当初25%。3つ積んでも上の端で切れないように下げた）。新しい数字は土台から10pxだけ浮き上がって落ち着き、押し上げは0.2秒。押し上げが3回を超えた数字は消える。効果名と結果は、その側の下の帯に、外側の端から1行ずつ横に滑り込ませ、新しい行が来たら古い行を上へ送って薄くする。帯は本体数字から0.7秒後に始め、各行を共通の拍で出す。戦闘不能は対象の山場以後・最後の行や追加数字の拍＋0.4秒、枠末尾で制限し、立ち絵の真ん中に出す（2026-10-29レビュー修正）。帯がその側の下の情報と重ならないかは一覧（計画56）で確かめる。
3. ~~攻撃の動きの作り直し方~~ → **決定済み**：

### 6.6 戦闘不能と重要な場面の延長（PR4.5c。2026-10-29 論点決定済み）

#### PR4.5c 実装契約（帯とKO時刻は項目5・6の追加2で更新）

- 入力は正規化済みstepのダメージ行のhp_afterとselfDestructed（元のself_destructed）。OUTCOME_EXTENSIONSのknockoutは1500ms。複数KOでも1回だけで、該当する重要度の最大値を採る。resolveStageTiming(step)が配分の単一の正となり、標準600 / 1400 / 1400 / 2600ms、KO時600 / 1400 / 1400 / 4100ms。待ち2000msは維持する。結果枠はそれぞれ4.6 / 6.1秒。途中参加の段階・段の長さ・接続・一覧も同じ関数を使い、共有開始時刻は変えない。
- KOは対象の本体数字の山場＋0.1秒、最後の帯行や追加数字の開始＋0.4秒以後。自滅は相手の山場＋0.1秒以後。通常は全KOの最遅の必要時刻から0.3秒ずつずらす。枠末尾−2.6秒の期限を超える場合は最後を期限に合わせて前を0.3秒ずつ早め、数字の山場の下限を守れない場合だけ間隔を縮める。過密で先行行が期限を超える場合は期限を優先し、行とKOのどちらも省かない。
- ko-shatterは受けた側の背景の矩形全体（合算は対象アイコン）へ出す。起点は横50%・縦38%。番号で決まる曲がった放射10本と、通常2重・派手3重の輪で、通常30・派手40多角形として板全体を埋める。共有する多角形辺をひびにも使い、形を一致させる。外側の線を細くする。
- ひび0〜0.4秒、白い光0.4〜0.44秒、破片の回転・落下0.4〜1.0秒。回転に応じた白い縁のきらめきは番号と時刻から決定する。灰色・減光の膜は0.5〜0.9秒、文字は0.8秒から短くフェードして出す。立ち絵要素への書込みは行わない。SVGの描画範囲内で割り、外へ飛ばす表現は加えない。
- 灰色の膜・影・Zen Antiqueの文字（chipは×）は枠末尾まで残す。params.durationはKO開始から枠末尾まで。終わりの0.15秒だけ各部品を同じ率でフェードし、Fx.finishAllで片付く。軽めは最初から静止したひび・膜・影・文字のフェードだけで、閃光・落下・きらめきは出さない。同じ時刻の表示は呼出し順や早送りに依存しない。
- 一覧は場面ごとの枠4.6 / 6.1秒、全演出の実体durationと開始時刻を使う。背景全体とchipの単体見本、合算の2人KOを追加する。サーバーの判定・記録、攻撃の形・反応、ダイス、効果名別の色は変更しない。

8. ひびを本物のガラスの割れ方に寄せ、不規則にする（2026-10-29 ユーザーの確認）。
   - 参考：鑑識での割れ方の説明（[Forensic glass analysis](https://en.wikipedia.org/wiki/Forensic_glass_analysis)）と、Houdini のガラスの割れ方の作り方（[Working with glass](https://www.sidefx.com/docs/houdini/destruction/glass.html)）。
     - 放射状のひびは衝撃点から外へ走る。輪のひびは、隣り合う放射状のひびの間を結ぶ、ほぼまっすぐな区間の集まりで、放射状のひびに当たって止まる（後からできたひびは、先にあるひびで止まる）。
     - 輪のひびは、外へ行くほど間隔が広がる。輪はつながった円ではなく、ところどころ途切れる（Houdini の Discontinuity）。
     - 放射状のひびの本数にもばらつきがあり、ひびの線そのものにも細かい揺らぎ（Edge Noise）がある。
   - 大事なのは不規則さで、描き込みを細かくすることではない（ユーザーの確認）。
   - 実装（2026-10-29、Claude）：
     - 疑似乱数は mulberry32。種は戦闘不能になったキャラのID。形はすべて `mount` で決め、`render(t)` では乱数を引かない。
     - 放射は通常・軽め8〜10本、派手9〜11本（chip 4〜6本）。隣との角度の間隔は平均の0.5〜1.6倍。放射ごとに伸びる速さも変える。
     - 輪は3重（基準20% / 45% / 78%）で、ひびごとに半径を±18%揺らす。内側の輪は必ず残し、外側は間ごとに通常45%・派手35%の割合で途切れさせる。途切れた間の破片はつなげて1枚にし、破片の辺とひびの線の一致は保つ。
     - 破片は通常20〜30枚・派手27〜39枚。枝は区間ごとに0〜3本（起点から出る区間は1本多い）、角度20〜60°、長さ3〜14px。SVG の要素は最大230（派手のきらめきの粒を24個から20個に減らして収めた）。
     - 途中で止まる放射状のひびは入れていない。破片の分け方（共有する辺）と両立させると作りが大きく変わり、不規則さはほかの点で十分出るため。要素の数は今（最大230）から増やさない。割れた角の欠け（Chipping）や、衝撃点の砕けた跡を細かく描くことはしない。
   - 不規則さは、番号から決まる疑似乱数（対象のIDなどを種にする）で作る。`Math.random` は使わない。同じ場面なら毎回同じ割れ方になる。
9. 付与と効果の表示順を、スキルに書かれた処理の順にする（2026-10-29 起票。**後のタスク**。PR4.5c では行わない）。
   - 今は付与のまとまりを、段の前後の状態の差分（`applied.statuses`）から作り、効果のまとまりより先に並べている。差分には処理の順がなく、「付与してから同じ状態を消費する」と差分が0になって付与が表示されない。相手の行動による増減も混ざる。
   - 案：状態を付与した処理も、発動した効果を記録している一覧（`fired_effects`）に、サーバーが処理した順に1件ずつ積む（例：`{kind: 'grant', target_id, name, delta}`）。画面は差分から付与を作るのをやめ、この一覧の順に付与と効果のまとまりを並べる。続けて付与したものは1つのまとまりにまとめる。
3. レビューで見つかった直し。
   - 灰色の膜（`backdrop-filter`）は、親の要素の不透明度が1未満だと効かない。戦闘不能の演出を包む要素にはフェードをかけず、中の部品それぞれに同じフェードをかける。
   - 戦闘不能が複数いるとき、期限（枠の終わり − 2.6秒）から逆算して、最後の人が期限に入るように前の人を0.3秒ずつ早める。早める分は、その人の「表示が引いてから」の時刻より優先する。

## 7. 入り切りの設定（案）

演出の段階は次の3つ（2026-10-23 決定）。どの段階でも演出の長さは同じにし、強さだけを変える（§5の「進行を止めない」を守るため）。

| 段階 | 中身 |
|---|---|
| 軽め | 動かさない。位置・大きさを変えず、揺れ・光・粒子なし。出すときと消すときは不透明度の短いフェード（0.15秒程度）だけにする。結果として残る表示（マッチの決着など）は最後の見た目をそのまま出し、時間がたつと消える表示（ダメージ数値・ラウンドバナー）は、通常と同じ時間その場に出してから消す。別の「切」は設けず、これを実質の切とする |
| 通常 | §6の演出（0.2〜0.8秒）。揺れは小さく、粒子は少なめ。初期値 |
| 派手 | 通常と同じ長さで、揺れ・光・粒子を強める。着弾の揺れは中・大の一撃で強めに出し、大の一撃ではカード全体を覆う薄い白の閃光を一瞬重ねる（揺らすのはFxが作った層だけ。§6.3） |

- アクションドックの♪ボタンの隣にボタンを1つ置き、押すと3択の小さなメニューが開く。今の段階に印を付ける。
- 保存先は効果音と同じく `localStorage`（キーは `motion_fx_level`、値は `light` / `normal` / `rich`）。
- OSでアニメーションを減らす設定（Windowsの「アニメーション効果」を切る、など。`prefers-reduced-motion`）が有効で、まだ選んでいなければ、初期値を「軽め」にする。
- 各演出は `render(t)` の中で段階を見て強さを変える。段階ごとに別の演出を作らない。

## 8. テスト

- `Fx` の時計と対応表：Node の `vm` で読み込み、`render` を決まった t で呼んで見た目（クラスやスタイル）を確かめる。今の `tests/test_*_frontend.py` と同じ書き方にする。
- 時刻から描く決まり（§4.2）：各演出で、t を進めた後に戻しても、飛ばして戻っても同じ見た目になること。`render(0)` と `render(Infinity)` が描けること。`Fx.prog` が `DECK.prog` と同じ値を返すこと（数点の t で比べる）。
- 共有できる形（§4.4）：`fx_core.js` と `fx_effects.js` を、アプリの `window` の状態なしで読み込めること。この2つの中に `@keyframes`・`transition`・`animate(`・`setTimeout`・`setInterval`・`Math.random`・`localStorage` が出てこないこと（文字列の検査）。
- 決まりの確認：3段階の設定（段階で強さが変わり、長さは変わらないこと）、`prefers-reduced-motion` での初期値、同時に出す数の上限、再接続では出さないこと。
- 呼ぶ場所：解決パネルが段階の切り替えでイベントを出すこと。ダイスのログで `Fx.play` が呼ばれること。
