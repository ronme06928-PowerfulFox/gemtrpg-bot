# 計画52：戦闘とセッションの小さなアニメーション演出

作成日: 2026-10-23
状態: 計画（未着手）。範囲・作り方の土台（§4）・第1段の対象（§6）・段階の設定（§7）はユーザー決定済み。PR1から着手できる。手描きの素材（PR4）だけ保留（§10）。

## 1. 目的

セッションや戦闘で何度も目にする場面（ダイスの結果、マッチの決着、ダメージ、ラウンド開始など）に、0.2〜0.8秒程度の小さなアニメーションを入れる。動画を貼らずに、遊んでいて楽しい手触りを足す。

## 2. 対象範囲

対象：

- PC Web版の戦闘画面と、セッション中のログ表示（`static/js/`、`static/css/`）。
- 新しく作る演出の部品（§4）と、その呼び出し口。
- 演出の入り切りの設定（§7）。

対象外：

- 説明動画・ルール解説の教材。Egatari（https://github.com/egatari ）で別のセッションが進めるため、この計画では扱わない（2026-10-23 ユーザー決定）。
- モバイル版（`static/mobile/`。開発停止中）。
- サーバー側の判定ロジック。演出のために判定結果を変えたり、新しい項目を足したりはしない。ジェムリアには現在クリティカル・ファンブルの決まりがないため、それを判定する処理も作らない（2026-10-23 ユーザー確認）。

## 4. 作り方（案）

### 4.1 演出は1か所から呼ぶ

`window.Fx` を1つ作り、ゲーム側からは `Fx.play('clash-win', {anchor, ...})` のように演出の名前と表示位置だけを渡す。どの演出で何を描くかは、`Fx` の中の対応表で決める。素材の作り方を後から変えても、ゲーム側のコードは直さない。

### 4.2 演出は「始まってからの秒数」から描く

Egatariの部品の決まりに倣い、各演出を次の形にする。

```js
Fx.define('clash-win', {
  duration: 0.6,                 // 秒
  mount(root, params) { /* 自分の要素を root の中に作る。大きさを測るならここだけ */ },
  render(t) { /* 開始 t 秒後の見た目を描く。t = 0 は始まる前、t = Infinity は最後の見た目 */ },
});
```

- 同じ t なら必ず同じ見た目にする。t は戻ったり飛んだりして、どの順番で来てもよい。`render` の中に「もう終わった」のような状態を持たず、前回の描画結果に頼らない。
- `render(0)` は始まる前の見た目、`render(Infinity)` は最後の見た目として、どちらも必ず描けるようにする。
- 進み具合は `Fx.prog(t, 開始, 長さ)`、補間は `Fx.lerp(a, b, e)` で求める。式はEgatariの `DECK.prog`・`DECK.lerp`・`DECK.ease` と同じにする（ゆっくり始まりゆっくり止まる2次の曲線。t = Infinity なら1）。演出のコードを動画へそのまま持ち込め、動きの曲線も一致する。
- 動きはすべて `render` の中でインラインのスタイルとして計算する。CSSの `@keyframes`・`transition`・Web Animations API、独自の `setTimeout`、`Math.random` は演出の定義の中で使わない。ブラウザが自分の時計で動かす動きは、動画の側で時刻を指定して描けないため。揺れの向きやダイスの面の変化も、t と受け取った値から決める。
- 演出の段階（§7）は `params.level` として受け取る。演出の定義の中で `localStorage` や設定を読まない。
- 時計は `Fx` の中の `requestAnimationFrame` 1本だけにする。タブを裏に回して戻ったときは、経過秒数から描くので見た目がずれない。
- 飛ばすときや演出を切ったときは `render(Infinity)` を描いてすぐ片付ける。
- t を指定して描けるので、テストはタイマーを待たずに書ける（§8）。

### 4.3 素材の種類は段階的に増やす

1. DOMとインラインのスタイル（第1段）。揺れ、光、数字の回転など。CSSは色や形など止まった見た目だけに使う（§4.2）。ダイスの絵（§6）のほかに画像は使わない。
2. 手描きの連番画像（スプライトシート、第2段）。決め所だけに使う。画像はCloudinaryに置き、`render(t)` でコマを選ぶ。
3. Rive（任意の第3段）。キャラの立ち絵を状態ごとに反応させたくなったときだけ検討する。

外部ライブラリは第3段まで入れない。

### 4.4 説明動画の部品と共有できる形にする

説明動画（計画54）は作らないが、そこで同じ演出を使えるように、各演出の定義を次の形で書く。動画の部品も同じく時刻から描くため（`typst_manual/動画/common/components/`）、`render(t)` をそのまま包めば動画に載せられる。

- `Fx.define` の `mount` と `render` は、受け取った値と描く場所（`root`）だけで完結させる。`EventBus`・`window` 上のアプリの状態・ほかのモジュールに頼らない。呼ぶ場所との接続は `Fx.play` の側に置く。
- 表示する要素は、演出が `mount` で `root` の中に自分で作る。駒など演出の外にあるものは参照しない。どこに出すかは、アプリ側が `root` の置き場所で決める。動画で包むときは、空の要素とJSONの値を渡すだけで済む。
- 色は `--fx-damage`・`--fx-heal`・`--fx-win`・`--fx-gem` などFx専用のCSS変数で決め、既定値はアプリのCSSに置く。動画の側では、これを自分のテーマ変数（`--emph` など）に割り当てる。Egatariの変数名はアプリへ持ち込まない。
- 大きさは `--fx-scale` とem単位など、外から変えられる値で決める。動画は文字の下限のため全体を約1.7倍に拡大する。位置や大きさを測るのは `mount` だけにし、`render` の中では測らない（アプリで毎フレーム測ると描画が重くなるため）。
- 読ませる数字や文字には `data-readable` を付ける。アプリでは何も起きないが、動画の品質検査（文字の大きさの下限）の対象にできる。
- 長さはアプリに合わせて決める（§5）。動画では、包む側が `render(t / 倍率)` として時間を引き伸ばす。Fx側には動画用の値を足さない。
- ファイルは次の3つに分ける。動画は上の2つを写して使う。どれも `scripts/build_frontend.mjs` の `CLASSIC_SCRIPTS` に依存順で追加する。

| ファイル | 中身 | アプリへの依存 |
|---|---|---|
| `static/js/fx/fx_core.js` | `Fx.define`、`Fx.prog`・`Fx.lerp`・`Fx.ease`、定義の対応表 | なし |
| `static/js/fx/fx_effects.js` | 各演出の定義 | なし |
| `static/js/fx/fx_player.js` | `Fx.play`、時計、同時に出す数の上限、3段階の設定と `localStorage`、切り替えメニュー | あり（アプリ専用） |

- 画像の素材（ダイスの絵、第2段の連番画像など）は、Cloudinary の URL のほかに手元のファイルからも読めるようにする。動画は作業フォルダの外やネットの素材を埋め込めない。
- 動画へ持ち込む作業（部品として包む、写しを置く）は計画54の側で行う。この計画では、上の形を守るところまでを扱う。動画の今の部品（`m-impact-hp` など）をFx版へ置き換えるかも、計画54の再開後に決める。

## 5. 守る決まり（案）

- **ゲームの進行を止めない。** 演出は今の表示の上に重ねて流すだけにする。`ROUND_BANNER_DURATION_MS` や解決パネルの段階の長さなど、進行の時間は延ばさない。演出の終わりを待って次へ進む作りにしない。
- **再接続や状態の同期では再生しない。** その場で起きたことにだけ出す（終結の結果表示と同じ扱い。E02 Part 13）。
- **短くする。** 何度も見る演出は0.2〜0.8秒。1秒を超えるのは宝石の加護と戦闘の終結だけにする。
- **同時に出す数を絞る。** 範囲攻撃などで一斉に出るときは上限を設け、超えた分は最後の見た目だけ出す。
- **効果音と同じ瞬間に出す。** 効果音（`SoundFx`）を鳴らしている箇所には、演出も同じ箇所から出す。

## 7. 入り切りの設定（案）

演出の段階は次の3つ（2026-10-23 決定）。どの段階でも演出の長さは同じにし、強さだけを変える（§5の「進行を止めない」を守るため）。

| 段階 | 中身 |
|---|---|
| 軽め | 動かさない。最後の見た目（`render(Infinity)`）だけを短いフェード（0.15秒程度）で出す。揺れ・光・粒子なし。別の「切」は設けず、これを実質の切とする |
| 通常 | §6の演出（0.2〜0.8秒）。揺れは小さく、粒子は少なめ。初期値 |
| 派手 | 通常と同じ長さで、揺れ・光・粒子を強める。マッチの決着で画面全体が少し揺れる |

- アクションドックの♪ボタンの隣にボタンを1つ置き、押すと3択の小さなメニューが開く。今の段階に印を付ける。
- 保存先は効果音と同じく `localStorage`（キーは `motion_fx_level`、値は `light` / `normal` / `rich`）。
- OSでアニメーションを減らす設定（Windowsの「アニメーション効果」を切る、など。`prefers-reduced-motion`）が有効で、まだ選んでいなければ、初期値を「軽め」にする。
- 各演出は `render(t)` の中で段階を見て強さを変える。段階ごとに別の演出を作らない。

## 8. テスト

- `Fx` の時計と対応表：Node の `vm` で読み込み、`render` を決まった t で呼んで見た目（クラスやスタイル）を確かめる。今の `tests/test_*_frontend.py` と同じ書き方にする。
- 時刻から描く決まり（§4.2）：各演出で、t を進めた後に戻しても、飛ばして戻っても同じ見た目になること。`render(0)` と `render(Infinity)` が描けること。`Fx.prog` が `DECK.prog` と同じ値を返すこと（数点の t で比べる）。
- 共有できる形（§4.4）：`fx_core.js` と `fx_effects.js` を、アプリの `window` の状態なしで読み込めること。この2つの中に `@keyframes`・`transition`・`animate(`・`setTimeout`・`setInterval`・`Math.random`・`localStorage` が出てこないこと（文字列の検査）。
- 決まりの確認：3段階の設定（段階で強さが変わり、長さは変わらないこと）、`prefers-reduced-motion` での初期値、同時に出す数の上限、再接続では出さないこと。
- 呼ぶ場所：解決パネルが段階の切り替えでイベントを出すこと。ダイスのログで `Fx.play` が呼ばれること。
