# アプリ全体のUI計画（見た目と操作の共通の決まり）

作成日: 2026-11-15
状態: たたき台（レビュー前）。これまでの計画書・仕様・会話で決めてきた見た目と操作の決まりを1か所に集め、まだ決めていない点を §6 に挙げた。Codex のレビューのあと、§6 を一問一答で決めてから段階に分ける。

## 1. 目的と位置づけ

管理画面（マスターデータ・ユニット管理）、ロビー、ルームの画面で、文言・大きさ・操作の置き場・色・飾りがばらばらにならないよう、アプリ全体の共通の決まりを持つ。新しい画面を作るときは、この決まりを先に当て、画面ごとの計画では差分だけを決める。

文書の役割：

| 文書 | 役割 |
|---|---|
| この計画 | アプリ全体の共通の決まり（案と決定）。画面をまたぐ判断の正本 |
| `manuals/ui_design_decision_log.md` | 画面ごとに、実装した見た目と理由の記録 |
| `manuals/implemented/E01`・`E02` | 実装済みの UI の仕様 |
| `static/css/modules/common_ui.css` | 共通の色・角丸などのトークンの実装 |
| 各機能の計画（計画57・60・61 など） | その画面だけの見た目（戦闘の演出の秒数・SE などは機能の計画が正） |

対象としないもの：モバイル版（開発停止中）、戦闘の演出の秒数・SE（計画52・55・57）、本（PDF）の組版（計画46、`typst_manual/`）。本の色は、色の元として参照する。

## 2. 今ある決まりと出典

### 2.1 文言

- 和語の言い回しを減らし、熟語・カタカナ語で短く書く（例：「使っている編成」→「使用中の編成」、「保存の前の検査」→「保存前チェック」、「JSON から取り込む」→「JSONインポート」）。出典：計画61 §3.7（2026-11-14 ユーザーの指摘）。
- 注意書きを増やさず、構造（並べ方・見出し・札）で意味を伝える。補足は短い ⓘ の説明にする。出典：計画60 §6-3（洗い出し1）、§5.14。
- 内部のキー（`state_name`・`type` 名など）を画面にそのまま出さない。出典：計画60 §5.15。
- 言葉の使い分け：一覧から取り除くのは「外す」、データそのものを消すのは「削除」、選んでいる物を空にするのは「解除」。出典：計画61 §3.10。

### 2.2 大きさと空白（管理画面）

- 文字は13px ほど。見出しだけ少し大きく、強弱で区切る。
- 余白は小さく。すき間は4〜8px、枠の内側は8〜10px。
- 入力欄は中身に合った幅（数値は数文字分、名前は1行分）。画面いっぱいに伸ばさない。
- 1件を1〜2行の行で見せ、長い文は1行で切って、開いたときだけ全文を出す。
- 出典：計画61 §3.9（論点25）。マスターデータの画面（`master_data.css`）は、これより大きいままで、まだ揃えていない。

### 2.3 読み物のページ（使い方ページなど）

- 本文は16px・行間1.85・1行約38字（DADS の「本文の行の高さは文字の150%以上」と WCAG 1.4.12 の1.5倍を満たす）。目次は左に固定、図は手順の下、写真は要る所を切り出す。出典：計画60 §5.20（`static/help/master_data.html`）。

### 2.4 操作の置き場と大事さ

- 置き場の段（計画61 §3.10、論点27）：
  1. 画面全体の操作：見出しの右（書き出し・取り込み、再読み込み、閉じる）。
  2. 一覧の操作：一覧の見出しの右に「＋ 新規」。検索と絞り込みはその下。
  3. 開いている1件の操作：下の帯。右に「保存」と「変更を破棄」、左に「その他 ▾」（廃止・削除などをしまう）。戻るは左上。
  4. 節の操作：節の見出しの右に、対象名の付いた「＋ 〇〇を追加」。見出しごと上に留める。
  5. 1行の操作：行の右端に文字で。外す・削除は一番右に離す。
  6. 窓：見出しの右に「閉じる」、主の操作は窓の下の右に1つ。
- 大事さの3段：主（塗りつぶし）は1つの面に1つまで、ふつうは枠だけ、危険は赤い文字。出典：計画60 §5.14（決まり4・5）、計画61 §3.10。
- 候補から選ぶ：プルダウンの候補が左上から開く件があるので、候補はページの中の一覧で選ぶ。複数を選ぶ物は、追加しても窓を閉じず「追加済み」と示す。出典：計画61 §3.7・§3.10。

### 2.5 確認・未保存・知らせ

- 下書き・保存は、保存したときに作る。保存していない変更があるまま離れようとしたら確かめる。「未保存」を出し、「変更を破棄」は未保存のときだけ押せる。出典：計画60 §5.14（決まり8）、計画61 §3.10。
- 共通の確認窓：Enter は印の付いたボタンだけを動かす。最初の印は呼び出しごとに選び、削除・破棄・取り下げなど危険な確認は「キャンセル側」。出典：E02 Part 16（計画61 PR61-2c）。
- 知らせ：成功は右下に浮かべて数秒で消し、画面をずらさない。誤りは消えず、閉じるボタンを付ける。出典：計画60 §5.14（決まり9）。
- 浮かぶ枠（候補など）は、枠とその開くボタン以外のどこを押しても閉じる。出典：計画60 §5.14（決まり9）。

### 2.6 色と札

- コントラスト：文字は背景に対して4.5:1以上、操作の枠（入力欄・ボタンなど）は3:1以上。飾りの線（カード・区切り）は薄い色でよい（`--cat-edge` と `--cat-control` を分けた）。出典：計画60 §5.14（決まり3）・§5.15。
- 色だけに頼らない：状態・陣営・公開範囲・警告は、文字・枠・形も併用する（廃止と編集中は破線の枠など）。出典：計画60 §5.14（決まり2）、`ui_design_decision_log.md` §4、計画61 §3.9。
- 危険は赤、注意は黄土。出典：`ui_design_decision_log.md` §4。

### 2.7 狭い幅

- 1280px と 680px で確かめる。680px では列を縦に積み、下の帯は画面の下に留める。出典：計画60 §5.14（決まり5）、計画61。
- 管理画面とルームは PC の Web が中心（モバイル版は開発停止）。

### 2.8 進め方

- 見た目は、依頼の前に試作で見比べて決める（`/_local/` に出す。本番のバンドルには入らない）。
- 別の DB で本物の画面を確かめるときは、起動するときのカレントのフォルダを別にし、手元の DB が変わっていないことを確かめる。

## 4. 共通の決まり（案）

§2 の決まりは、このまま全体の決まりにする。そのうえで、色と飾りを次のようにそろえる案。

1. **色のトークンを1つの系統にまとめる**：`common_ui.css` に、意味の名前（文字・補助の文字・飾りの線・操作の枠・面・主・危険・注意・追加・味方・敵）でトークンを置き、`--cat-*`・`--bo-*` はそれを使う。値は、文字と線は本の濃紺・灰青に寄せ、コントラストの決まり（§2.6）を満たす値にする。
2. **分類の色に宝石の色を使う**：種類のタブ（ユニット・編成・ステージ）や、スキルの10分類（Ps・Pb・Pp・Ms・Mb・Mp・B・C・D・E）、マスターデータの7種類に、宝石の色を割り当てる。タブ・行の左端の印・札にその色を使い、本とも見た目をつなぐ。
3. **スキルの札は戦闘と同じ色**：属性・分類・距離の札は、宣言パネルと同じ色の組を共通のクラスにして、管理画面でも使う。
4. **陣営は赤と青**：「敵」「味方」の札、敵編成・味方編成は、配置のときのキャラの色と同じ系統にする。
5. **飾りは「宝石の印」と「淡い面」に絞る**：見出しの横の小さな宝石の印、選んでいる行・見出し・確認欄を分ける淡い面と罫線まで。影・グラデーション・大きな絵は管理画面には使わない。
6. **大事さの3段に色を合わせる**：主は主の色の塗りつぶし、ふつうは操作の枠の色の枠だけ、危険は赤い文字（§2.4）。

## 5. 当てる画面と順番（案）

1. ユニット管理（計画61。今いちばん手が入っている）
2. マスターデータ（計画60。大きさと空白も §2.2 にそろえる）
3. ロビーと、ルームの中の管理系の窓（配置の画面、プリセット配置など）
4. 戦闘の画面は、計画57 など戦闘の計画を正とし、ここでは色のトークンを使うかどうかだけを決める

## 6. 未決定事項

1. **トークンの置き場と名前**：`common_ui.css` に寄せるか、新しいファイルにするか。意味の名前の付け方。
2. **宝石の色の割り当て**：どの分類にどの宝石を当てるか（本の章の割り当てと揃えるか、別に決めるか）。暗い背景の画面（戦闘）でも読める値にするか。
3. **管理画面の大きさ**：§2.2（13px・詰める）をマスターデータにも当てるか。使い方ページ（16px）とどう分けるか。
4. **飾りの範囲**：宝石の印をどこまで使うか（見出し・タブ・空の状態の表示など）。
5. **戦闘の画面への適用**：トークンを戦闘の画面にも使うか、戦闘は別の色の系統のままにするか。
6. **記録の置き場**：画面ごとの記録は `ui_design_decision_log.md` に続けて書くか（今は 2026-08 の2件で止まっている）。
7. **進め方**：色の試作（ユニット管理で、案を2つほど見比べる）を先に作るか、トークンの整理（見た目を変えない置き換え）を先にするか。

## 7. 段階（案）

1. この計画をレビューし、§6 を決める。
2. 色と飾りの試作を作り、ユニット管理で見比べる。
3. トークンを1つの系統にまとめる（見た目を変えない置き換え）。
4. 決めた色と飾りをユニット管理に当て、次にマスターデータ、ロビーと管理系の窓へ広げる。
5. 決まりを E02 と `ui_design_decision_log.md` に移す。
