# バックアップ自動化の比較

確認日: 2026-11-01。手元バックアップの初回取得・読込再検査は11/1に成功した。次に自動化する方法を選ぶ場合は以下を比較する。今回の比較では定期ジョブ・新しい契約・接続情報の外部登録は行わない。

## 比較

| 方法 | 追加契約・費用の考え方 | 実行と保管 | 採用前に必要な判断 |
|---|---|---|---|
| 手動でPCへ保存 | 新しい有料契約を使わない。既存DBの利用枠・PCの空き容量を使用 | セッション後・更新前に `scripts/backup_postgres.cmd` を実行し、PCのGit除外フォルダへ保存 | 手動実行の習慣と、何世代・どこへ保管するか |
| 同じPCのWindowsタスク | サービスの追加契約は不要。DBの利用枠とPCの実行環境を使用 | 決めた日時にPCで同じ処理を実行。PCの電源・スリープ・ネットワーク等の条件を考慮 | 日時、実行アカウント、接続情報の安全な保管方法、失敗の通知先 |
| GitHub Actions等の外部実行 | 無料枠があっても実行時間・artifact保管等に上限があり、枠を超えれば費用が発生しうる | PCがオフでも外部ランナーが実行。保管先と保存期間を別途選ぶ | DB接続情報とバックアップを外部へ預ける許容、保管先・権限・保持期間・費用上限 |
| Neonの定期スナップショット | 現在のFreeアカウント画面では `Upgrade for schedules` と表示。実際に選べるプラン・料金は未確認 | Neon内でスケジュール作成。PCの電源に依存しないが、Neonとは別の保管先にはならない | 有料化の必要性、保持期間、取得実績と復元検証 |

Windowsタスクの仕組みは[Microsoft公式](https://learn.microsoft.com/en-us/windows/win32/TaskSchd/using-the-task-scheduler)、GitHubの無料枠・storage課金は[GitHub公式](https://docs.github.com/en/billing/concepts/product-billing/github-actions)、NeonのスケジュールAPIは[Neon公式](https://api-docs.neon.tech/reference/setsnapshotschedule)を参照。比較の数値を一般化せず、実際のアカウントの表示と利用量を照合してから採用する。

## 推奨する進め方

1. まず手動で1回保管し、アーカイブ読込検査が成功することを確認する。手順は[PostgreSQL手元バックアップ](../../operations/postgres_backup_runbook.md)。
2. 手間が問題になる場合、同じPCのWindowsタスクを最初の自動化候補にする。PCが止まっている時間も取得したいなら外部実行・Neonの定期機能を比較する。
3. 接続URLをタスクの引数や平文のバッチへ書かない。無人実行にする前に資格情報の保管方法を決める。
4. 保存世代・容量・失敗通知・定期的な復元検証を決める。既存バックアップの自動削除は、その方針が承認されるまで実装しない。

バックアップ取得はDBの処理・転送量を使用するため、ゲーム中の高頻度実行は先に負荷を測る。バックアップ自動化をアプリの描画・通信の高速化そのものとは扱わず、初回保管を確認した後に `PERF-BASELINE` の計測へ進む。
