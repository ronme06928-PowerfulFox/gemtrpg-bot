# Part 1: キャラクター詳細モーダル仕様

本ドキュメントは、繰り返し発生したレイアウト崩れや仕様の混同を防ぐために定義された、「キャラクター詳細モーダル」の確定仕様である。
今後の改修において、本仕様を逸脱する変更（特に横幅の可変可や、バフ表示の簡略化など）を行う際は慎重に検討すること。

## 1. 基本レイアウト (Layout & Dimensions)

* **コンテナ幅**: **固定 `650px`**
  * **理由**: スキル名の視認性確保（以前の500pxでは見切れたため）およびバフ展開時のレイアウト安定化のため。
  * **モバイル対応**: `max-width: 90vw` を併用。
* **スクロール制御**:
  * `overflow-x: hidden`: コンテンツが幅を超えてもモーダル自体が広がらないように強制。
  * `box-sizing: border-box`: パディングを含めた幅計算。
* **テキスト処理**:
  * すべての説明文・パラメータに対し `overflow-wrap: break-word` (または `anywhere`) を適用し、長い英単語等によるレイアウト破壊を防ぐ。

## 2. ヘッダー領域

* **キャラクター名**: 左側にカラーバーを表示。
* **操作ボタン**:
  * **設定（歯車）**: クリック時、**ポップアップ（コンテキストメニュー）**を表示する。
    * *※インラインで設定項目を展開してはならない（過去の不具合原因）。*
  * **閉じる（×）**: モーダルを閉じる。

## 3. パラメータ表示 (Parameters)

* **形式**: **3列 × 3行 のCSS Grid** (`.char-params-grid`)
* **対象項目**: `['筋力', '生命力', '体格', '精神力', '敏捷', '直感', '経験', '物理補正', '魔法補正']`
* **デザイン**:
  * 個別のボックス（背景 `#f9f9f9`, ボーダーあり）に格納。
  * **Label** (グレー/太字) : **Value** (黒/太字) の形式で表示。
  * 単なるテキストの羅列（スラッシュ区切りなど）には戻さないこと。

## 4. 特殊効果 / バフ (Buffs)

* **UI構造**: **折りたたみ式 (`<details>`)**
* **デフォルト状態**: 原則として折りたたみ (Closed)。
* **各要素のデザイン**:
  * **ヘッダー (`<summary>`)**:
    * 背景色: 灰色 (`#e9ecef`)
    * 表示内容: **バフ名** + **残りターンバッジ** + **Delayバッジ**
    * **動的バフ名処理**: `_` (アンダーバー) 以降の文字列は内部IDとみなし、表示から除外する。（例: `Bleed_React` → `Bleed`）
  * **詳細ボディ**:
    * 背景色: 白 (`#fff`)
    * **説明文**: 太字の黒文字。
    * **フレーバー**: 斜体のグレー文字。
    * 両者が存在する場合、両方とも表示する。

## 5. スキル (Skills)

* **セクション全体**: **折りたたみ式 (`<details>`)**
* **ヘッダー**:
  * **帯デザイン**: 背景灰色 (`#f8f9fa`)、パディングを広めに確保してクリックしやすくする。
  * **インジケーター**: 右端に「▼」を表示し、開閉可能であることを明示する。
* **リスト表示**: 2列のグリッド表示。
* **GM機能**: ユーザー属性がGMの場合のみ、各スキルに「公開設定」チェックボックスを表示。

## 6. 設定メニュー (Settings Context Menu)

* **表示形式**: `position: absolute` によるポップアップメニュー（ボタン直下に表示）。
* **実装機能**:
    1. **所有権の譲渡**: プルダウン + 実行ボタン。
    2. **駒サイズ**: スライダー (0.5倍 ～ 2.0倍)。
    3. **立ち絵変更**: 青色ボタン（画像ピッカー起動）。
    4. **未配置に戻す**: グレーボタン（確認ダイアログあり）。
    5. **削除**: 赤色ボタン（最下部に配置）。
    6. **GMトグル**: 「GMのみ操作可能」の設定。

## 7. その他 重要コーディング規約

* **イベントリスナー**:
  * モーダル生成時 (`renderCharacterCard`) にHTML文字列として生成し、`openCharacterModal` 内でDOM要素化してからイベントを付与する。
  * 設定メニュー等のイベントは、メニュー生成時に動的に付与し、メモリリークや多重登録（ゾンビイベント）に注意する。

# Part 2: プリセット・ステージUI操作仕様

最終更新: 2026-05-07

## 対象
今回の対象は、通常ルーム用プリセット適用、戦闘専用ステージ選択、戦闘突入、ステージ効果詳細表示の操作変更です。
文字化けしている既存マニュアル本文の修正は別作業とします。

## 通常ルーム用プリセット適用
通常ルームでは `通常プリセット` ボタンから、以下を通常ルームへ反映できます。

- 敵キャラ
- 敵編成
- ステージ

ステージ適用では、以下の項目をチェックボックスで選択します。

- 敵編成
- 背景
- フィールド効果
- ステージアバター

敵編成を適用する場合、既存の敵キャラクターは全置換されます。味方キャラクターは残ります。

## 戦闘専用ステージ選択
戦闘専用ルームでは `戦闘専用編成` からステージプリセットを選択できます。
ステージ選択時には、以下が編成へ反映されます。

- 敵編成
- 味方編成
- 必要味方人数
- ステージ効果設定
- ステージアバター設定

ステージカードと選択サマリーには、敵編成、必要味方人数、背景、効果ルール数、アバター状態を表示します。

## 戦闘突入
ステージ選択後、編成条件が満たされると `戦闘突入` が押せるようになります。
戦闘突入後は、戦闘状態へステージ効果がランタイム反映されます。

## ステージ効果詳細表示
戦闘中は右上付近のステージ効果カードから `詳細` を開けます。
詳細では以下を確認できます。

- ステージ効果 ON/OFF
- ステージアバター ON/OFF
- 効果ルール数
- 効果ルール名
- 効果説明
- フレーバーテキスト

ステージアバターが OFF の場合、表示用ステージアバター欄は表示しません。

## リセット/再読込時の状態
戦闘リセット、再入室、再読込時は、トップレベルのランタイム用ステージ効果を消去します。
一方で、次回戦闘準備のための `battle_only` 内ステージ選択情報は保持します。

# Part 4: スキルピッカーUI 仕様

**実装完了日**: 2026-06-28
**対象**: 宣言パネル（`DeclarePanel.js`）のスキル選択UI
**採用方針**: 案B（縦・インライン切替）

## 1. 概要

宣言パネル下半分（`.declare-panel-scroll` 領域）を、スキルの選択状態に応じて
**スキルピッカーグリッド ↔ スキル詳細** にインライン切替する方式。

### 変更前後

| 変更前 | 変更後 |
|---|---|
| `<select>` による縦一列プルダウン | 2カラムのカードグリッド |
| スキル名・コストのみ表示 | ID・名前・属性バッジ・コストをカードで表示 |
| 属性情報なし | 属性（斬撃/打撃 等）・分類・距離をバッジ表示 |

## 2. UI状態遷移

```
パネル起動（スキル未選択）
    ↓
[下半分 = スキルピッカーグリッド]  ← _skillPickerOpen === true
    ↓ カードをクリック
[下半分 = スキル詳細]             ← _skillPickerOpen === false
    - スキル行に「↩ 再選択」ボタン表示
    ↓ ↩ ボタンをクリック
[スキルピッカーグリッドに戻る]
```

### 表示ルール

| 条件 | 下半分の表示 |
|---|---|
| `skillId` が空 かつ `!isUiReadOnly` | スキルピッカーグリッド（自動展開） |
| `skillId` あり かつ `_skillPickerOpen === false` | スキル詳細（`.declare-skill-meta`） |
| `isUiReadOnly === true` | スキル詳細（固定） |

## 3. スキルカード仕様

```
┌──────────────────────────┐
│ Pb-01                    │  ← スキルID（小・薄色・monospace）
│ 叩き打ち                 │  ← スキル名（太字）
│ [打撃] [物理] [近接]     │  ← 属性バッジ
│                   FP:1   │  ← コスト（右寄せ）
└──────────────────────────┘
```

### カード状態

| 状態 | クラス | 見た目 |
|---|---|---|
| 通常 | — | ベージュ系背景 |
| ホバー | `:hover` | 少し明るく + shadow |
| 選択中 | `.is-selected` | 濃紺ハイライト・白文字 |
| コスト不足 | `.is-disabled` | 半透明（opacity:0.45）・クリック不可 |
| クリック瞬間 | `:active` | scale(0.97) |

# Part 5: キャラクターJSON追加導線仕様（Plan 28 P1-4）

**最終更新日**: 2026-07-10
**対象**: `static/js/modals.js::openCharLoadModal`、`static/js/common/char_json.js`、`events/socket_char.py::handle_add_debug_character`

## 1. 基本方針

キャラクター追加は、追加先選択とJSON入力を分けた2段階モーダルで行う。

1. 最初の画面で「味方を追加」「敵を追加」を選ぶ。
2. 次の画面でJSONを貼り付ける、またはローカルJSONファイルを読み込む。
3. 「追加」ボタンで既存の `loadCharacterFromJSON(type, jsonText, resultMsg)` を呼び、従来と同じ `request_add_character` 経路で追加する。

通常の敵JSON追加は、現時点では非GMにも開放する。

モーダルはビューポート内に収め、内容が長い場合はモーダル内部をスクロールさせる。閉じるボタンは右上に固定表示し、素の小ボタンではなく視認しやすい丸形ボタンとして扱う。

## 2. ローカルJSONファイル読込

- JSON入力画面に「ファイルから読み込み」ボタンを表示する。
- 実体は非表示の `<input type="file" accept=".json,application/json">`。
- 選択されたファイルはブラウザの `FileReader` で読み、テキストエリアへ反映する。
- ファイルパスやファイル本体を直接サーバーへアップロードしない。
- 追加時にサーバーへ送るのは、既存どおりJSON文字列から生成されたキャラクターデータのみ。

## 3. GM専用デバッグキャラ生成

- GMの場合のみ、各追加画面の下部にデバッグ生成パネルを表示する。
- 味方追加画面ではデバッグ味方、敵追加画面ではデバッグ敵だけを生成する。
- 追加人数はプルダウンで1〜5体から選ぶ。
- サーバー側でもGM権限、整数、上限5体を検証する。
- 非GMが `request_add_debug_character` を直接送っても拒否する。

## 4. 検証観点

- JSON貼り付けで味方/敵を追加できる。
- ローカルJSONファイル読込後、同じ追加ボタンで味方/敵を追加できる。
- 非GMでも通常の敵JSON追加はできる。
- 非GMにはデバッグ生成UIが表示されない。
- GMのデバッグ生成は選択した陣営と人数だけ生成する。

## 2. 軽量成長パネル（インライン展開・スキル選択UI）

各キャラ行の「成長」ボタンで、行の下に成長パネルをトグル表示する。成長とは「通過点・シナリオ経験を通して輝化スキルや新たな戦闘スキルを得ること」であり（パラメータの直接上昇はこの画面のUIからは提供しない）、CharaCreatorのスキル選択体験（カテゴリ絞り込み＋プルダウン＋効果プレビュー）を踏襲した軽量版を提供する。

- **種別セレクト**（`.owned-chars-growth-type`）: 「⚔️ 戦闘スキル」/「✨ 輝化スキル」を切り替える。
- **カテゴリセレクト**（`.owned-chars-growth-category`）: 戦闘スキル選択時のみ表示。スキルIDの先頭プレフィックス（`B/C/D/E/Ps/Pb/Pp/Ms/Mb/Mp`、CharaCreatorのシートタブ区分と同じ並び）から動的に選択肢を構築する（`skillCategoryOf()`が`/^([A-Za-z]+)-/`で判定）。実データに存在するプレフィックスのみを表示し、想定外のプレフィックスは末尾にアルファベット順で追加する。輝化スキル選択時は非表示（輝化は1リストのみ）。
- **スキルセレクト**（`.owned-chars-growth-skill-select`）: 選択中の種別・カテゴリで絞り込んだ一覧を`[ID] 名称（コスト:X）`形式で列挙する。データは`window.allSkillData`/`window.radianceSkillData`（ロビー読み込み時に`main.js`がグローバルへ格納済み）を利用し、未取得時はモーダル側で`ensureSkillData()`/`ensureRadianceData()`が`GET /api/get_skill_data`・`GET /api/get_radiance_data`を直接叩いて補う。
- **効果プレビュー**（`.owned-chars-growth-preview`）: スキル選択時に、戦闘スキルなら分類/距離/属性/コスト/使用時効果/特記/発動時効果を、輝化スキルならコスト（通過点）/効果/フレーバーテキストを表示する。
- **「＋ 予定に追加」ボタン**: 選択中のスキルを「習得予定」チップ一覧（`.owned-chars-growth-pending`）へ追加する（この時点ではAPIを呼ばない）。チップは種別ごとに色分け（戦闘スキル=青、輝化スキル=紫）し、`×`ボタンで予定から削除できる。同じスキルは選択肢からも消えるため二重追加はできない。
- **消費予定表示**（`.owned-chars-growth-budget`）: 「消費予定 経験値: X / 残り Y ・ 消費予定 通過点: X / 残り Y」。経験値と通過点は完全に独立した予算であり、どちらかが残り予算を超えると赤字で警告表示する（送信前のクライアント側チェックであり、実際の許可判定はサーバー側で行う）。
- **「成長を適用」ボタン**: 予定チップの`add_skill_ids`（戦闘スキル）・`add_radiance_ids`(輝化スキル)をまとめて`POST /api/owned_characters/<id>/growth`へ送信する（F01 Part 9-5参照）。成功後は一覧を再取得し、パネルは閉じた状態にリセットされる（再度開くとまっさらな状態から選び直す）。

## 3. キャラ追加ウィザードの「持ちキャラから選ぶ」タブ

E02 Part 5の2段階ウィザード（味方/敵選択→JSON入力画面）に、既存のJSON貼り付け欄とは`.char-load-divider`（「または」の区切り線）で明確に区切った「📋 保存済みの持ちキャラから選ぶ」セクションを追加する（2026-07-13改修: 当初はJSON貼り付け欄の直前に区切りなく配置していたため、①どちらのボタンがどちらの入力に対応するか分かりにくい、②`<select>`が横並びレイアウトの中で潰れて見えなくなる、という2つのUI不具合があった。後述の回帰防止のため経緯を残す）。

## 4. キャラ詳細モーダルの「成果を反映」パネル

`createSettingsContextMenu`（キャラ詳細モーダルの⚙️設定メニュー）に、`char.owned_character_id`が存在する場合のみ表示するセクションを追加する。

- 「獲得経験値」数値入力、「獲得アイテム（`item_id:個数`形式、カンマ区切り）」テキスト入力、「成果を反映」ボタン。通常ルームでは「獲得通過点」（0以上の整数）も表示し、`radiance_gain`として送信する。負値・不正値は送信前に案内し、サーバー拒否`invalid_radiance_gain`も同じ案内で通知する。

# Part 9: PvEチャート駆動スロット生成UI（Plan 39・2026-07-31）

## 1. Profile全体設定

- 共通行動チャートエディター上部に「スロット生成方式」を説明付きラジオボタンで表示する。
- `step_actions`は「チャートのスキル数から生成」、`character_action_count`は「キャラクターの行動回数から生成」と表示する。

- 対象不在・使用不能でキャンセルされたスロットは、タイムラインに「キャンセル」と理由を表示する。

## 3. ビルドと確認

変更後は`npm run build`を実行し、デスクトップ幅と狭幅でラジオボタン、step件数、0件注意、対象不在表示を確認する。保存・再読込後も選択方式と`on_no_target`が維持されることを確認する。

- 管理画面、配置画面、既存編集フォームは可視状態で重ねない。配置画面を手動で閉じた場合は呼び出し元の管理画面または詳細調整画面へ戻る。

## 2. 共通プリセット配置ブラウザー

- 通常ルームと戦闘専用は`PresetDeploymentBrowser`を共有し、呼び出し側は`targetMode`だけを指定する。
- デスクトップは、分類280px、候補一覧最低520px、配置トレイ360〜420pxの3領域で構成する。
- 左領域は「このルームのブックマーク」「すべて」「未分類」と、検索可能なコレクション・区分ツリー・件数を表示する。「最近使った」と複合準備リストは設けない。
- 中央領域はステージ、編成、キャラクターのタブと横断検索を持つ。カードには種別、分類、人数またはステージ構成を表示し、星でルームブックマークを即時切替する。
- 右領域はステージ最大1件、味方編成最大1件、敵編成最大1件、単体キャラクター複数件を保持する一時トレイである。画面を閉じると保存せず、項目があれば破棄確認を出す。
- ステージ追加時は参照編成をトレイの初期値にする。後から手動選択した同陣営編成で上書きでき、ステージの背景・効果・アバターは維持する。
- 味方・敵編成は追加または置換を選択できる。単体キャラクターは数量、陣営、味方の場合だけ担当ユーザーを選択する。
- サーバープレビューが最新選択に対して`ready: true`を返すまで確定ボタンを有効にしない。新規生成数、置換で外れる人数、ステージ変更、警告、阻害事項を適用前に表示する。

## 3. 戦闘専用への接続

- 詳細調整画面の上部に「プリセット配置」を置き、共通ブラウザーへ遷移する。従来の詳細編成フォームは削除せず、反映後の調整先として維持する。
- 反映後に阻害事項がなければ「戦闘突入を確認」を主操作として有効にし、「詳細調整」を副操作にする。
- 阻害事項がある場合は内容を一覧表示し、「戦闘突入を確認」を無効化して「詳細調整」を主操作にする。反映済み下書きは保持する。
- 通常ルームでは適用成功後に配置画面を閉じ、既存フィールドへ戻る。

## 4. 管理ワークスペースの大量件数対策

- コレクション欄に専用検索、全レコード件数、コレクション件数、選択中コレクションの区分ツリーと区分件数を表示する。
- コレクションのブックマークと編集は各行の星・省略操作へ集約し、「選択中を編集」「コレクションを登録」の長い常設ボタンを廃止する。
- デスクトップの3ペインは分類240〜280px、一覧400px以上、詳細360〜480pxとし、一覧を主領域にする。980px以下は詳細を下段、680px以下は縦積みにする。
- 一覧カードは登録件数が少なくてもペインの余白へ引き伸ばさず、内容に必要な高さで上詰めにする。
- サイドバーで省略表示されたコレクション名・区分名は、カーソルを重ねた際のツールチップで全文を確認できる。
- アーカイブは通常のチェックボックス寸法を維持し、「削除せず普段の一覧から隠す」ことを一覧と詳細の説明で示す。

## 5. レスポンシブ・状態表現

- 1180px以下では配置トレイを右側インスペクターとして開閉し、ヘッダーの「今回の配置 (N)」で操作する。
- 760px以下では分類を左側ドロワーにし、候補一覧を主領域として横スクロールを発生させない。
- 種別、選択、成功、警告、阻害、削除、無効は色だけでなくラベル、文言、枠、アイコンを併用する。
- `aria-label`、`aria-expanded`、ステータス用`role="status"`を設定し、`prefers-reduced-motion`ではドロワー遷移時間を最小化する。

# Part 12: プリセット移送UI（2026-08-15）

- 管理ワークスペースのヘッダーに「移送JSON取込」を置き、ファイル選択、dry-run相当の内容確認、衝突処理選択、DB登録を同じ詳細ペイン内で進める。子モーダルは重ねない。

# Part 13: 通常ルーム戦闘セッションUI（計画49・2026-09-08）

## 1. 表示と権限

- 通常ルームの戦闘画面だけに、全参加者へ同期される「戦闘準備中」または「戦闘中」の状態表示を出す。戦闘専用モードには表示しない。
- GMには準備中の「戦闘突入」、戦闘中の「戦闘終結」を表示する。プレイヤーは状態表示だけを確認できる。
- 準備中は、通常ルームのラウンド開始・終了操作を表示しない。状態同期によるアクションドックの再描画など、どの描画経路でも同じ判定を用いる。サーバー側の進行ガードが正本であり、古い画面や直接Socket送信も拒否する。

## 2. 終結ダイアログと結果演出

- 「戦闘終結」は結果選択を必須とし、`VICTORY` / `DEFEAT` / `RETREAT` / `INTERRUPTED`を送信する。未解決のマッチ・宣言・解決キューがある場合は、破棄され復元できないことを示す。
- 終結の同期を受けた画面は、前の戦闘のタイムラインと行動枠を即時に消去する。再読み込みを必要としない。
- 終結後の次の戦闘は同じ画面でRound 1から始まる。前の戦闘と同じラウンド番号でも、解決演出は通常どおり表示する。
- 成功時は全参加者へ一度だけ結果演出を表示する。英語見出しの日本語副題は順に「戦闘勝利」「戦闘敗北」「戦闘撤退」「戦闘中断」とする。再接続や通常の状態同期では再表示しない。

## 3. 戦闘記録モーダル

- 「戦闘記録」は全参加者が開ける。左側に新しい順の記録一覧、右側に結果、開始・終了時刻、完了ラウンド、参加者別の与ダメージ・被ダメージを表示する。
- 参加者名と結果は記録時点のスナップショットであり、後からキャラクターを削除または改名しても過去記録の表示は変えない。
- 所有者が分かる召喚体のダメージは所有者の補助集計へ加え、所有者不明分のみ「その他の召喚体」1行へ集約する。
- GMだけに1件削除と全件削除を表示する。確認UIは戦闘記録モーダルより前面に表示し、対象と復元不可であることを確認した場合だけ要求を送る。
- 戦闘記録モーダルのヘッダーは濃色背景に明色の見出しと閉じる操作を用い、背景色と区別できるコントラストを保つ。
