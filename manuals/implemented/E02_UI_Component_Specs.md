# Part 1: キャラクター詳細モーダル仕様

本ドキュメントは、繰り返し発生したレイアウト崩れや仕様の混同を防ぐために定義された、「キャラクター詳細モーダル」の確定仕様である。
今後の改修において、本仕様を逸脱する変更（特に横幅の可変可や、バフ表示の簡略化など）を行う際は慎重に検討すること。

## 1. 基本レイアウト (Layout & Dimensions)

* **コンテナ幅**: **固定 `650px`**
  * **理由**: スキル名の視認性確保（以前の500pxでは見切れたため）およびバフ展開時のレイアウト安定化のため。
  * **モバイル対応**: `max-width: 90vw` を併用。
* **スクロール制御**:
  * `overflow-x: hidden`: コンテンツが幅を超えてもモーダル自体が広がらないように強制。
  * `box-sizing: border-box`: パディングを含めた幅計算。
* **テキスト処理**:
  * すべての説明文・パラメータに対し `overflow-wrap: break-word` (または `anywhere`) を適用し、長い英単語等によるレイアウト破壊を防ぐ。

## 2. ヘッダー領域

* **キャラクター名**: 左側にカラーバーを表示。
* **操作ボタン**:
  * **設定（歯車）**: クリック時、**ポップアップ（コンテキストメニュー）**を表示する。
    * *※インラインで設定項目を展開してはならない（過去の不具合原因）。*
  * **閉じる（×）**: モーダルを閉じる。

## 3. パラメータ表示 (Parameters)

* **形式**: **3列 × 3行 のCSS Grid** (`.char-params-grid`)
* **対象項目**: `['筋力', '生命力', '体格', '精神力', '敏捷', '直感', '経験', '物理補正', '魔法補正']`
* **デザイン**:
  * 個別のボックス（背景 `#f9f9f9`, ボーダーあり）に格納。
  * **Label** (グレー/太字) : **Value** (黒/太字) の形式で表示。
  * 単なるテキストの羅列（スラッシュ区切りなど）には戻さないこと。

## 4. 特殊効果 / バフ (Buffs)

* **UI構造**: **折りたたみ式 (`<details>`)**
* **デフォルト状態**: 原則として折りたたみ (Closed)。
* **各要素のデザイン**:
  * **ヘッダー (`<summary>`)**:
    * 背景色: 灰色 (`#e9ecef`)
    * 表示内容: **バフ名** + **残りターンバッジ** + **Delayバッジ**
    * **動的バフ名処理**: `_` (アンダーバー) 以降の文字列は内部IDとみなし、表示から除外する。（例: `Bleed_React` → `Bleed`）
  * **詳細ボディ**:
    * 背景色: 白 (`#fff`)
    * **説明文**: 太字の黒文字。
    * **フレーバー**: 斜体のグレー文字。
    * 両者が存在する場合、両方とも表示する。

### 4.1 亀裂の集約表示（2026-10-24）

- 対象はキャラクター詳細の「特殊効果 / バフ」欄のみ。`Bu-Fissure` を1つの折りたたみ行へ集約し、見出しを「亀裂　6重」の形式にする。既存の期限・回数・出典バッジはこの行には表示しない。
- 合計は `states` の「亀裂」の値を正とする。状態異常欄の表示は残す。合計が正なら、期限付きバケットがなくても集約行を表示する。合計0でもバケットが残る場合は、不整合を確認できるよう行を表示する。
- 説明は「スキルで受けるダメージに、亀裂の重数を加算する。各重は、それぞれの残りラウンドが尽きると消失する。期限なしの分は、ラウンド経過では消失しない。」とする。
- 説明の下に「残りラウンド / 重数」の表を置く。内訳1種類でも同じ形式とし、`lasting` と `delay` が同じバケットの `count` を合算する。通常分は残りラウンド昇順、遅延付きはその後に `delay`、`lasting` の昇順で並べる。
- 遅延付きの行は「発動まで1ラウンド / 持続2ラウンド」の形式で区別する。現行の付与処理では遅延付きも即座に状態値へ加算されるため、合計とバケット合計には含める。
- 「期限なし」の重数は `状態値 − 全Bu-Fissureのcount合計` とする。正の場合のみ表の最後に表示する。
- バケット合計が状態値を超える場合、期限別の配分を推測せず、表の代わりに「残りラウンドの内訳を確認できません」と表示する。合計は状態値のままとし、保存データは補正しない。バケットの重数・期限・遅延が不正な場合も同じ表示にする。
- 集計は状態を変更しない純粋関数として切り出し、通常・同期限合算・期限なし・0・不整合・遅延をテストする。詳細カード描画でも集約行が1つになり、他のバフの表示が維持されることを検証する。
- 戦闘計算、期限切れ、消費、保存形式、マップ等の他画面は変更しない。

## 5. スキル (Skills)

* **セクション全体**: **折りたたみ式 (`<details>`)**
* **ヘッダー**:
  * **帯デザイン**: 背景灰色 (`#f8f9fa`)、パディングを広めに確保してクリックしやすくする。
  * **インジケーター**: 右端に「▼」を表示し、開閉可能であることを明示する。
* **リスト表示**: 2列のグリッド表示。
* **GM機能**: ユーザー属性がGMの場合のみ、各スキルに「公開設定」チェックボックスを表示。

## 6. 設定メニュー (Settings Context Menu)

* **表示形式**: `position: absolute` によるポップアップメニュー（ボタン直下に表示）。
* **実装機能**:
    1. **所有権の譲渡**: プルダウン + 実行ボタン。
    2. **駒サイズ**: スライダー (0.5倍 ～ 2.0倍)。
    3. **立ち絵変更**: 青色ボタン（画像ピッカー起動）。
    4. **未配置に戻す**: グレーボタン（確認ダイアログあり）。
    5. **削除**: 赤色ボタン（最下部に配置）。
    6. **GMトグル**: 「GMのみ操作可能」の設定。

## 7. その他 重要コーディング規約

* **イベントリスナー**:
  * モーダル生成時 (`renderCharacterCard`) にHTML文字列として生成し、`openCharacterModal` 内でDOM要素化してからイベントを付与する。
  * 設定メニュー等のイベントは、メニュー生成時に動的に付与し、メモリリークや多重登録（ゾンビイベント）に注意する。

# Part 2: プリセット・ステージUI操作仕様

最終更新: 2026-05-07

## 対象
今回の対象は、通常ルーム用プリセット適用、戦闘専用ステージ選択、戦闘突入、ステージ効果詳細表示の操作変更です。
文字化けしている既存マニュアル本文の修正は別作業とします。

## 通常ルーム用プリセット適用
通常ルームでは `通常プリセット` ボタンから、以下を通常ルームへ反映できます。

- 敵キャラ
- 敵編成
- ステージ

ステージ適用では、以下の項目をチェックボックスで選択します。

- 敵編成
- 背景
- フィールド効果
- ステージアバター

敵編成を適用する場合、既存の敵キャラクターは全置換されます。味方キャラクターは残ります。

## 戦闘専用ステージ選択
戦闘専用ルームでは `戦闘専用編成` からステージプリセットを選択できます。
ステージ選択時には、以下が編成へ反映されます。

- 敵編成
- 味方編成
- 必要味方人数
- ステージ効果設定
- ステージアバター設定

ステージカードと選択サマリーには、敵編成、必要味方人数、背景、効果ルール数、アバター状態を表示します。

## 戦闘突入
ステージ選択後、編成条件が満たされると `戦闘突入` が押せるようになります。
戦闘突入後は、戦闘状態へステージ効果がランタイム反映されます。

## ステージ効果詳細表示
戦闘中は右上付近のステージ効果カードから `詳細` を開けます。
詳細では以下を確認できます。

- ステージ効果 ON/OFF
- ステージアバター ON/OFF
- 効果ルール数
- 効果ルール名
- 効果説明
- フレーバーテキスト

ステージアバターが OFF の場合、表示用ステージアバター欄は表示しません。

## リセット/再読込時の状態
戦闘リセット、再入室、再読込時は、トップレベルのランタイム用ステージ効果を消去します。
一方で、次回戦闘準備のための `battle_only` 内ステージ選択情報は保持します。

# Part 4: スキルピッカーUI 仕様

**実装完了日**: 2026-06-28
**対象**: 宣言パネル（`DeclarePanel.js`）のスキル選択UI
**採用方針**: 案B（縦・インライン切替）

## 1. 概要

宣言パネル下半分（`.declare-panel-scroll` 領域）を、スキルの選択状態に応じて
**スキルピッカーグリッド ↔ スキル詳細** にインライン切替する方式。

### 変更前後

| 変更前 | 変更後 |
|---|---|
| `<select>` による縦一列プルダウン | 2カラムのカードグリッド |
| スキル名・コストのみ表示 | ID・名前・属性バッジ・コストをカードで表示 |
| 属性情報なし | 属性（斬撃/打撃 等）・分類・距離をバッジ表示 |

## 2. UI状態遷移

```
パネル起動（スキル未選択）
    ↓
[下半分 = スキルピッカーグリッド]  ← _skillPickerOpen === true
    ↓ カードをクリック
[下半分 = スキル詳細]             ← _skillPickerOpen === false
    - スキル行に「↩ 再選択」ボタン表示
    ↓ ↩ ボタンをクリック
[スキルピッカーグリッドに戻る]
```

### 表示ルール

| 条件 | 下半分の表示 |
|---|---|
| `skillId` が空 かつ `!isUiReadOnly` | スキルピッカーグリッド（自動展開） |
| `skillId` あり かつ `_skillPickerOpen === false` | スキル詳細（`.declare-skill-meta`） |
| `isUiReadOnly === true` | スキル詳細（固定） |

## 3. スキルカード仕様

```
┌──────────────────────────┐
│ Pb-01                    │  ← スキルID（小・薄色・monospace）
│ 叩き打ち                 │  ← スキル名（太字）

│                   FP:1   │  ← コスト（右寄せ）
```

# Part 5: キャラクターJSON追加導線仕様（Plan 28 P1-4）

**最終更新日**: 2026-07-10
**対象**: `static/js/modals.js::openCharLoadModal`、`static/js/common/char_json.js`、`events/socket_char.py::handle_add_debug_character`

## 1. 基本方針

キャラクター追加は、追加先選択とJSON入力を分けた2段階モーダルで行う。

1. 最初の画面で「味方を追加」「敵を追加」を選ぶ。
2. 次の画面でJSONを貼り付ける、またはローカルJSONファイルを読み込む。
3. 「追加」ボタンで既存の `loadCharacterFromJSON(type, jsonText, resultMsg)` を呼び、従来と同じ `request_add_character` 経路で追加する。

通常の敵JSON追加は、現時点では非GMにも開放する。

モーダルはビューポート内に収め、内容が長い場合はモーダル内部をスクロールさせる。閉じるボタンは右上に固定表示し、素の小ボタンではなく視認しやすい丸形ボタンとして扱う。

## 2. ローカルJSONファイル読込

- JSON入力画面に「ファイルから読み込み」ボタンを表示する。
- 実体は非表示の `<input type="file" accept=".json,application/json">`。
- 選択されたファイルはブラウザの `FileReader` で読み、テキストエリアへ反映する。
- ファイルパスやファイル本体を直接サーバーへアップロードしない。
- 追加時にサーバーへ送るのは、既存どおりJSON文字列から生成されたキャラクターデータのみ。

## 3. GM専用デバッグキャラ生成

- GMの場合のみ、各追加画面の下部にデバッグ生成パネルを表示する。
- 味方追加画面ではデバッグ味方、敵追加画面ではデバッグ敵だけを生成する。
- 追加人数はプルダウンで1〜5体から選ぶ。
- サーバー側でもGM権限、整数、上限5体を検証する。
- 非GMが `request_add_debug_character` を直接送っても拒否する。

## 4. 検証観点

- **種別セレクト**（`.owned-chars-growth-type`）: 「⚔️ 戦闘スキル」/「✨ 輝化スキル」を切り替える。
- **カテゴリセレクト**（`.owned-chars-growth-category`）: 戦闘スキル選択時のみ表示。スキルIDの先頭プレフィックス（`B/C/D/E/Ps/Pb/Pp/Ms/Mb/Mp`、CharaCreatorのシートタブ区分と同じ並び）から動的に選択肢を構築する（`skillCategoryOf()`が`/^([A-Za-z]+)-/`で判定）。実データに存在するプレフィックスのみを表示し、想定外のプレフィックスは末尾にアルファベット順で追加する。輝化スキル選択時は非表示（輝化は1リストのみ）。
- **スキルセレクト**（`.owned-chars-growth-skill-select`）: 選択中の種別・カテゴリで絞り込んだ一覧を`[ID] 名称（コスト:X）`形式で列挙する。データは`window.allSkillData`/`window.radianceSkillData`（ロビー読み込み時に`main.js`がグローバルへ格納済み）を利用し、未取得時はモーダル側で`ensureSkillData()`/`ensureRadianceData()`が`GET /api/get_skill_data`・`GET /api/get_radiance_data`を直接叩いて補う。
- **効果プレビュー**（`.owned-chars-growth-preview`）: スキル選択時に、戦闘スキルなら分類/距離/属性/コスト/使用時効果/特記/発動時効果を、輝化スキルならコスト（通過点）/効果/フレーバーテキストを表示する。

# Part 9: PvEチャート駆動スロット生成UI（Plan 39・2026-07-31）

# Part 14: 解決パネル・チャットの演出（計画52・計画57 PR57-1・PR57-2、2026-10-31）

## 演出の段階の設定

- 段階は軽め・通常（初期値）・派手の3つ。どの段階でも演出の長さは同じにし、強さだけを変える。段階ごとに別の演出を作らず、各演出が `render(t)` の中で `params.level` を見て強さを変える。
- 軽め：位置・大きさを変えず、揺れ・光・粒子なし。出すときと消すときは不透明度の約0.15秒のフェード（`Fx.stillOpacity`）だけ。結果として残る表示は最後の見た目をそのまま出し、時間がたつと消える表示（ダメージの数字・ラウンドバナー）は通常と同じ時間その場に出してから消す。別の「切」は設けず、軽めを実質の切とする。
- 派手：通常と同じ長さで、揺れ・光・粒子を強める（揺れの値は下のPR4.5b）。
- アクションドックの♪ボタンの隣の✨（`#dock-motion-fx-icon`）で3択のメニューを開き、今の段階に印を付ける。保存先は `localStorage` のキー `motion_fx_level`（`light` / `normal` / `rich`）。まだ選んでいなくて、OSの `prefers-reduced-motion` が有効なら、初期値を軽めにする。
- 同時に出す数の上限12個を超えた分は、軽めの出し方で出す。情報は欠かさない。

## 戦闘の外の演出

- 駒の上のダメージの数字（`float-text`）は、戦闘の外でHPが変わったとき用に残す。解決中は盤面の駒に目印も数字も出さない（盤面は解決パネルに覆われ、更新も解決が終わるまで止まっている）。手番の明滅（`pulse-turn`）は演出の対象外。
- ラウンドバナー（`round-banner`、1.8秒）は演出が自分で要素を作る。終わったときに `battle:round:banner:finished` を出し、盤面の更新の保留（`BoardPresentationCoordinator`）を解く。

## 舞台型の解決パネル

- `ResolveFlowPanel._renderStep` の通常の手順は舞台型。戦闘開始introは従来どおり。上の帯に種類・#番号・現在の段階、左右の大きな立ち絵・名前、その上の斜めの札（属性アイコン・スキル名・ID）、札の内側の端の宝石（最終威力・幅）、中央にVSを出す。立ち絵は反転せず、中央側の縁だけ溶かす。画像がなければシルエットと頭文字を出す。
- 下の帯は「◯◯ 勝利 ・ 総ダメージ N（ダイス a ／ 効果 b）」の1行。威力の補正と細かいダメージ種別は出さず、チャットのログに任せる。tiebreakとnotesはカード下部の注記欄へ残す（長文は欄内を送る）。注記の高さも画面への収まりに含める。
- 進行の操作は結果帯の下。次のマッチへ・進行役の引継ぎ・自動進行・待ちの表示・進行の帯を保つ。権限、送信、待ち、共有カーソル、遅延中の演出を読み終えるまで待つ処理は変更しない。
- スキルの文章はカード外の下。`_skillById` の「使用時効果」「発動時効果」「特記」の空でない値だけを出し、`[[ID|表示名]]` は表示名にする。長い札の名前は元の8割まで縮め、その後はellipsisとtitleで扱う。
- 寸法の正は `static/js/battle/components/resolve_stage_layout.js`。1180px・660pxの2つの設計寸法を持ち、`pickStageLayout` が地図の欄の幅×0.92と「画面高さ−108px」で両方を当てはめ、実際に出る札の文字（`plaqueFont`×縮小率）が大きい方の組を選ぶ（同じなら1180px）。縮小率だけで比べると、少し縮む1180pxより縮まない660pxが選ばれ、幅に余裕があるのにパネルが小さくなるため。全体は一度だけ縮小する。プレビューの `scripts/resolve_preview/layout.mjs` も同じモジュールを再エクスポートする。演出は縮小する舞台の中に置き、画面上の矩形から座標を逆算しない。
- 文章欄はカードと14pxの間隔の下に残る高さを割り当て、設計上の上限は広い組160px・狭い組145px。高さが足りなくても本文2行が見える最低の高さ（`minCopyHeight`：広い組100px・狭い組128px）は残し、その分だけ舞台を縮める。文章は欄の中で縦に送る。660pxは攻撃側・防御側のタブで1段にし、再描画のたびに選択を戻さない。

## 演出の接続と片付け

- 威力ロール（`power-roll`、1.4秒の定義）は、はじめ0.03秒ごとの数字の切り替えを終わりにかけて0.1秒ごとまで遅くし、1.0秒で決まった数字に止め、1.15倍から戻して短く光らせて0.4秒見せる。数字は回転させない。大小の紋章の数字に重ね、元の数字を演出中だけ隠す。攻撃と打ち合いの光は舞台中央、clash-shadeはその側の半分。命中の反応と揺れに限り、立ち絵・側・数字欄・攻撃の絵を動かす。派手・largeの正の被弾だけカードの揺れとimpact-flashを重ねる（末尾PR4.5b）。
- 斬撃・打撃・貫通は `attack-slash` / `attack-strike` / `attack-pierce`（1.4秒、0.7秒で着弾）。属性なしはattack-flash。引き分けは両者を中央へ向け、small・draw・neutralで描く。一方攻撃と止められなかった強硬攻撃は攻撃側だけロール。不発には攻撃・決着の演出を付けない（実消費した加護があれば名前段階には出す）。広域個別はresolutionKindに従う。
- 引き分けは中央のぶつかり合う光だけを出し、両側に光も影も付けない。ダメージの数字は記録上ダメージを受けた側にだけ出す。ダメージ0の一撃（勝ったが0、一方攻撃が0）は動きを小で出し、数字・「無効」・「0」の文字は出さない（0の理由は発動した効果の名前で示す）。
- small / medium / largeは被弾側の合計ダメージで8未満 / 8〜14 / 15以上。判断は味方・敵で同じにして色だけ変え、しきい値は接続側の1か所に置く。ダメージ記録によるKOだけlargeへ補正する。合算のtierは人数を足さずrolls.deltaを使い、防御側勝利は属性なし、攻撃側勝利はwide。合算の各対象の本体数字は0.15秒ずつずらす。
- 数字は各側のdamage箱の土台（下端−42px）。参加者は各自の立ち絵の上。ceilingは通常が数字箱の上端、参加者が小さい紋章の下端＋4pxから、字の半分の高さを引いた位置。効果は各側のband箱の外端・下端へ置く（合算の守備側は非表示）。箱と土台とceilingは共有レイアウト関数で決める。
- KOはその側の半分いっぱいのガラス。合算参加者はその人の列いっぱいの縦長のガラスにし、通常側は内側と上下、参加者は四方の縁をmaskで溶かす。数字・帯より背面、立ち絵より前面で描く。
- 演出の定義・時刻・軽め/通常/派手は `fx_core.js` / `fx_effects.js` / `resolve_flow_result_fx.js` のまま。再生した各hostを追跡し、切替・早送り・終了・破棄時に遅延予約も含めてfinishAllで片付ける。画面幅の組が変わったときも旧hostを片付け、現在段階の経過時刻で再接続する。

## 結果演出の計画

- `planResolveOutcome` は記録だけから順序を決める。現在HPやログの文から推測しない。本体数字、0.1秒から側ごと1つのeffect-band、効果と対応する追加数字、対象のKOを計画する。合算の守備側は帯だけ描かず、ほかの演出と計画の時刻は保つ。過密でも省略せず表示が終わるまで待ちを延長する。

- 付与・効果・混乱は `fired_effects` だけを処理順に表示する（計画52 PR7）。同じ対象・同じ自分への付与の区分で、帯の中で続く付与行だけを見出しなしのまとまりにし、効果が挟まれば分ける。付与行は `status` のアイコン・記録された `name`・正の `delta`。自分への付与も紫。消費した元の状態の負の行とHP行は省く。W-07のresults内の混乱は末尾に数字なし、W-10は見出しだけ。変換後の凝魔・蓄力の名前はサーバー記録を使う。状態差分・図鑑・接頭辞による付与の推測や差引きは行わない。
- 数字は後続が前の数字の高さと余白の分だけ昇るのを待って出し、押し上げない。帯は行ごとに外端から横へ入り、独立して昇って消える。速さ・行高・減速・消え方は次のFxの共有定数に従う。
  - 昇り方は `Fx.floatDistance(t, until, speed)` の一本の曲線。`until` 秒までは一定の速さで昇り、その後は時定数0.5秒でなめらかに減速して毎秒12pxへ近づき、消えるまで昇り続ける。速さを段で切り替えない。
  - 数字：同じ対象の数字は出た瞬間から自分で昇り、後の数字は前の数字が「2つの行の高さの平均＋8px」昇ってから土台に出す。出続ける間は列の速さ（間を空けるのに要る分だけ、上限毎秒60px）で一緒に昇り、最後の数字が出た時刻からそろって減速する。4つ目が出たら一番古い数字を0.15秒で消す。上の端（`ceiling`）の36px手前から薄れて消える。大きさは0.6倍から0.3秒で膨らみ（列の最初1.3倍・派手1.6倍・2つ目以降1.12倍）、0.5秒で1倍に落ち着き、薄れと同じ進みで0.82倍へ縮む。
  - 帯：効果名の行と結果の行を1行ずつ別に出す。行は帯の下端に出て横から0.3秒で滑り込み、後の行は前の行が「後の行の高さ＋8px」昇ってから出す。出続ける間は毎秒80pxで一緒に昇り、最後の行が出た時刻からそろって減速する。上端（見える高さ180px）の36px手前から薄れ、薄れと同じ進みで外側の下の角を軸に0.9倍まで縮む。帯は最後の行が滑り込み終える時刻（`stopAt`）から読取りの0.8秒だけ残して終える。文字は見出し28px・行40px、結果22px・行32px・太さ700、状態のアイコン24px。行の高さは `Fx.EFFECT_BAND_ROW_HEIGHTS` とCSSで一致させる。
  - 薄れ方：出てから0.8秒は濃いまま残し、その後は表示の終わりまで `(1 - x)²` で薄れる（`Fx.lingerProgress` / `Fx.lingerOpacity`）。1.1秒より短い表示は終わりの0.3秒で薄れる。
  - 数値は `Fx.FLOAT`・`Fx.EFFECT_BAND_LAYOUT` に集め、数字の行の間のゆとり8pxは `resolve_flow_result_fx.js` に置く。軽めは滑らかに動かさず大きさも変えず、数字は最後の位置に置き、帯の行は新しい行が出たときだけ1行分上へ置き直して、不透明度だけで薄れる。
- KOは数字の山場以後、最後の対象行・追加数字＋0.4秒以後、自滅は相手の山場以後。全体の期限は枠末尾−3.1秒。複数は通常0.3秒ずつずらし、期限を超える場合は後ろから詰める。ひび0〜0.4秒、止め0.4〜0.9秒、破砕0.9秒、膜1.0〜1.4秒、文字1.3秒から。KO対象の数字と帯は破砕時刻から0.3秒で引く。混在する他対象は残す。
- ガラスは設計上のwidth / heightをそのままviewBoxへ使い、対象IDを種にした疑似乱数で形を固定する。共有辺がひびと破片を兼ね、細枝はpathへまとめる。軽めは完成形と膜・文字のフェードのみ、SVGは400要素以内。単体のchip見本は一覧だけに残す。

- 重さの目安は、勝敗段階の攻撃・数字・帯・反応・揺れを同時に描いてrAF間隔の中央値16.7ms以内（2026-11-03、Chrome・DPR 2・舞台1180 /660×3属性×通常・派手で全て満たした）。初回の斬撃で最大約190msの長いフレームが出たが原因は特定できず、約50万画素へ下げても改善しなかったので100万画素を採る。CPU描画のCanvasは遅くなるので使わない。再計測は `scripts/check_motion_fx_browser.py --canvas`（比較は `--pixel-scale` / `--software-canvas`）で行う。

置き場所は本番・プレビューで `stageFxPlacement` を共有し、`left` / `top` は命中の点を表す。命中は受けた側の立ち絵の横中央・上から45%（打撃は70%）、広域合算の攻撃側勝ちは受けた側の参加者の並びの中央・参加者の立ち絵の上から45%（打撃は70%）、引き分けは舞台の中央。攻撃3属性は設計の箱（320×240、wideは横1.35倍）を渡された箱に収まる倍率で全体ごと拡大縮小し、引き分けは倍率1。立ち絵の下端の余白は舞台の寸法 `portraitBottom` / `participants.portraitBottom` からCSSへ渡す。プレビューの「攻撃の属性」で、どの見本でも攻撃の絵だけを3属性に差し替えて見比べられる。
